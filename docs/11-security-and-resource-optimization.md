# 11 · 安全与资源优化专项

> 一个工具最容易被记住的时刻，是卸载它的那一刻：是干净得让你意外，还是脏得让你恼火。

---

## 一、零污染承诺

### 1.1 承诺内容

| 形态 | 承诺 |
|------|------|
| **便携版（绿色版）** | 解压即用。不写注册表、不写系统目录、不装服务、不建计划任务、不改文件关联、不装驱动、不开机自启 |
| **安装版** | 只写入卸载所必需的最小信息，卸载时 100% 删除 |
| **两者共同** | 不捆绑、不静默安装第三方组件、不强制重启、不强制登录、不强制联网 |

### 1.2 卸载后必须为 0 的项目

| 类别 | 具体项 |
|------|-------|
| 目录 | 程序目录、数据目录（用户选择清除时）、缓存、日志、临时文件 |
| 注册表 | 软件项、文件关联项、右键菜单项、启动项、卸载信息项 |
| 服务 | 无（我们不安装任何服务） |
| 驱动 | 无（我们不安装任何驱动） |
| 计划任务 | 无（我们不创建计划任务） |
| 启动项 | 无（不自启） |
| 防火墙规则 | 卸载时删除自动添加的规则 |
| 快捷方式 | 桌面、开始菜单、快速启动栏 |
| 系统钩子 | 全局快捷键钩子、剪贴板监听钩子 |
| 后台进程 | 全部进程退出，无残留 |

## 二、各平台落点清单

### 2.1 Windows

| 位置 | 便携版 | 安装版（默认） | 卸载时 |
|------|:------:|:-------------:|-------|
| 程序目录 | 解压位置 | `%LocalAppData%\Programs\DeskBase`（**非管理员安装**）或用户指定 | 删除 |
| 数据目录 | 程序目录 `data\` 或用户指定 | `%UserProfile%\DeskBaseData` 或用户指定 | 用户选择 |
| 缓存 | 程序目录 `cache\` 或数据目录 | `%LocalAppData%\DeskBase\cache` | 删除 |
| 日志 | 数据目录 `logs\` | 数据目录 `logs\` | 删除 |
| 临时文件 | 系统 TEMP（以固定命名） | 同左 | 启动与退出时清理，卸载时清理残留 |
| 注册表 `HKCU\Software\DeskBase` | **不写** | 写：安装路径、版本、数据目录、安装选项（**仅卸载所需**） | 删除整个项 |
| 注册表 `HKLM` | **不写** | **不写**（使用非管理员安装） | — |
| 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\DeskBase` | **不写** | 写：显示名、卸载命令、图标、版本、发布者（**系统要求，不可省**） | 删除 |
| 注册表 `HKCU\...\Run`（自启） | **不写** | **不写**（自启默认关闭；若用户开启，卸载时删除） | 删除 |
| 文件关联 `HKCU\Software\Classes` | **不写** | **默认不写**；若用户勾选关联，卸载时删除 | 删除 |
| 右键菜单 | **不写** | **默认不写**；若用户勾选，卸载时删除 | 删除 |
| 服务 | **不装** | **不装** | — |
| 计划任务 | **不建** | **不建** | — |
| 防火墙规则 | **不加** | 仅在用户开启远程访问且系统提示时添加，并记录以便卸载时删除 | 删除 |
| 系统托盘图标 | 运行时存在 | 运行时存在 | 退出时消失 |
| 全局快捷键钩子 | 运行时注册 | 运行时注册 | 退出时注销 |
| 剪贴板监听 | 运行时注册 | 运行时注册 | 退出时注销 |

> **关键决策：使用 `HKCU` + 非管理员安装**。这样不需要管理员权限，不会污染 `HKLM`，卸载时能完整清理。这也符合"默认最小权限"原则。

**注册表项的最小化清单（安装版）**

```
HKCU\Software\DeskBase
  ├── InstallPath      REG_SZ    <安装路径>
  ├── DataPath         REG_SZ    <数据目录>
  ├── Version          REG_SZ    <版本号>
  ├── InstallOptions   REG_SZ    <安装选项摘要，用于卸载时判断需要清理什么>
  └── InstallDate      REG_SZ    <安装日期>

HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\DeskBase
  ├── DisplayName      REG_SZ    DeskBase 桌库
  ├── DisplayVersion   REG_SZ    <版本>
  ├── Publisher        REG_SZ    <发布者>
  ├── InstallLocation  REG_SZ    <安装路径>
  ├── UninstallString  REG_SZ    <卸载程序路径>
  ├── DisplayIcon      REG_SZ    <图标路径>
  └── NoModify/NoRepair REG_DWORD 1
```

**共约 12 个值，全部为卸载所需。没有任何一个是"为了统计"或"为了推广"。**

### 2.2 Linux

| 位置 | 便携版 | 安装版 | 卸载时 |
|------|:------:|:------:|-------|
| 程序 | 解压位置 | `/opt/DeskBase` 或 `~/.local/opt/DeskBase`（用户级） | 删除 |
| 数据 | 程序目录或 `~/.local/share/DeskBase` | 同左（用户可指定） | 用户选择 |
| 配置 | 程序目录 | `~/.config/DeskBase` | 删除 |
| 缓存 | 程序目录 | `~/.cache/DeskBase` | 删除 |
| 日志 | 数据目录 | `~/.local/state/DeskBase/logs` | 删除 |
| 桌面项 | **不写** | `~/.local/share/applications/deskbase.desktop`（用户级） | 删除 |
| 图标 | **不写** | `~/.local/share/icons/hicolor/*/apps/deskbase.png` | 删除 |
| MIME 关联 | **不写** | 默认不写；勾选时写用户级 MIME 配置 | 删除 |
| systemd 服务 | **不装** | **不装**（用户级 unit 都不建） | — |
| 自启 `~/.config/autostart` | **不写** | 默认不写；勾选时写 | 删除 |
| 防火墙规则 | **不加** | 不主动加；若需放行由用户自行配置并告知 | — |
| AppImage | 自包含，无副作用 | — | 删除文件即可 |

> **优先提供 AppImage**，因为它是零安装、零残留的最干净形式。

### 2.3 macOS

| 位置 | 便携版 | 安装版 | 卸载时 |
|------|:------:|:------:|-------|
| 程序 | `.app` 所在位置 | `/Applications/DeskBase.app` | 拖入废纸篓 |
| 数据 | `.app` 同级或用户指定 | `~/Library/Application Support/DeskBase` | 用户选择 |
| 配置 | 同数据 | `~/Library/Preferences/com.deskbase.app.plist` | 删除 |
| 缓存 | 同数据 | `~/Library/Caches/com.deskbase.app` | 删除 |
| 日志 | 数据目录 | `~/Library/Logs/DeskBase` | 删除 |
| 启动代理 LaunchAgent | **不装** | 默认不装；勾选时写 `~/Library/LaunchAgents/` | 删除 |
| LaunchDaemon | **不装** | **不装**（需 root） | — |
| 登录项 | **不加** | 默认不加；勾选时加 | 删除 |
| 键盘监听权限 | 截图/全局快捷键需要 | 在系统设置中由用户授权 | 卸载时提示用户手动撤销 |

> **提供 `.dmg` 中的"卸载脚本"**，因为 macOS 惯例是拖入废纸篓，但那样会留下 `~/Library` 下的数据。卸载脚本可帮助用户彻底清理。

## 三、安装模式对比

| 维度 | 便携版 | 安装版 |
|------|-------|-------|
| 是否需要管理员权限 | 否 | **否**（用户级安装） |
| 写入注册表 | 不写 | 最小写入（HKCU，仅卸载所需） |
| 数据默认位置 | 程序目录 | 用户目录 |
| 随 U 盘移动 | ✅ | ❌ |
| 开机自启 | ❌ | 可选（默认关） |
| 文件关联 | ❌ | 可选（默认关） |
| 开始菜单 | ❌ | ✅（可选） |
| 自动更新 | ❌（手动下载新版本覆盖） | ✅（默认关闭，用户可开） |
| 卸载 | 删除目录 | 卸载程序 |
| 多人共用电脑 | ⚠️ 数据在程序目录，可能被他人访问 | ✅ 数据在用户目录，隔离更好 |
| 推荐场景 | 试用、U 盘携带、临时机器、网吧 | 长期使用、多人电脑、需要开始菜单 |

**默认推荐便携版**。安装向导的第一步就说明这个区别，让用户自己选。

## 四、安装时的写入行为

### 4.1 写入时序

```
用户点击安装
    ↓
① 检查磁盘空间（不足则明确说明需要多少）
    ↓
② 解压程序文件到目标目录（写临时名 → 原子重命名）
    ↓
③ 创建数据目录（若用户指定了非默认位置）
    ↓
④ 写入最小注册表项（仅安装版，仅 HKCU）
    ↓
⑤ 创建快捷方式（仅用户勾选的）
    ↓
⑥ 写文件关联（仅用户勾选的）
    ↓
⑦ 写自启项（仅用户勾选的）
    ↓
⑧ 生成卸载器（写入卸载程序与 UninstallString）
    ↓
⑨ 记录安装清单（install-manifest.json，用于卸载时精确清理）
    ↓
⑩ 完成
```

**关键设计：`install-manifest.json`**

安装时把"我创建了什么"完整记录在安装目录内：

```json
{
  "version": "1.0.0",
  "installedAt": "2026-09-17T14:30:00+08:00",
  "installPath": "C:\\Users\\chj\\AppData\\Local\\Programs\\DeskBase",
  "dataPath": "D:\\DeskBaseData",
  "created": {
    "registry": [
      "HKCU\\Software\\DeskBase",
      "HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\DeskBase"
    ],
    "shortcuts": [
      "Desktop\\DeskBase.lnk",
      "StartMenu\\DeskBase.lnk"
    ],
    "fileAssociations": [],
    "firewallRules": [],
    "startupEntries": []
    },
  "options": {
    "createDesktopShortcut": false,
    "createStartMenuShortcut": true,
    "associateFiles": false,
    "autoStart": false,
    "remoteAccess": false
  }
}
```

这个文件是**卸载器精确清理的依据**。它保证"只删我们建的，不删别人的"。

### 4.2 幂等与失败回滚

| 情形 | 行为 |
|------|------|
| 安装目录已存在旧版本 | 提示升级，保留数据目录，替换程序文件 |
| 安装中途失败 | 回滚已创建的项（注册表、快捷方式、文件），恢复到安装前状态 |
| 磁盘空间不足 | 安装前预检，不足则拒绝并说明 |
| 权限不足 | 明确说明哪个操作需要什么权限，并说明"可以改用便携版" |
| 已有另一份安装在运行 | 检测并提示先关闭 |

### 5.3 卸载器的技术要点

| 要点 | 说明 |
|------|------|
| **自删除** | 卸载器不能删除自己正在运行的文件。方案：把卸载器复制到临时目录运行，或使用系统提供的"重启后删除"机制 |
| **精确清单** | 依据 `install-manifest.json` 清理，不盲目删除目录 |
| **不删别人的东西** | 若检测到安装目录内有用户放入的额外文件，明确询问是否一起删除 |
| **数据目录在程序目录内时** | 特殊处理：先提示"数据在程序目录内"，让用户选择移出或一并删除 |
| **权限不足** | 若某项无法删除（如被占用），列出并说明原因与手动处理方法 |
| **失败不中断** | 单项失败记录并继续，最后汇总报告 |
| **环境变量** | 若安装时添加了 PATH（默认不加），卸载时移除 |
| **文件占用** | 检测占用进程，提示用户关闭后重试，或提供"重启后删除" |

### 5.4 卸载界面要求

- **自有品牌界面**，不是系统默认的灰色小框。
- 支持亮/暗主题、高 DPI、多语言。
- 键盘可达，屏幕阅读器可读。
- 进度真实，错误友好。
- 完成后给出**明确的残留检查报告**——这是给用户的最后一份信任凭证。

## 六、后台行为与资源优化

### 6.1 后台进程原则

| 原则 | 说明 |
|------|------|
| **不需要就不启动** | 未开启远程 → 不启动远程进程；未使用 AI → 不加载模型 |
| **用完即退出** | 备份完成 → 备份进程退出；AI 空闲 5 分钟 → 释放模型 |
| **退出主程序即全退** | 用户选择"退出"时，全部进程结束，无残留 |
| **不做后台常驻服务** | 不安装服务，不创建计划任务，不注册开机自启（默认） |

### 6.2 禁止的后台行为

| ❌ 禁止 | 原因 |
|--------|------|
| 秒级轮询 | 浪费 CPU 与电量 |
| 隐藏的定时网络请求 | 违反网络默认关闭 |
| 后台预加载全部数据 | 浪费内存 |
| 常驻多个无用进程 | 资源浪费、卸载残留风险 |
| 后台持续读写磁盘 | 影响用户其他工作、损耗 SSD |
| 后台监听麦克风/摄像头/位置 | 隐私侵犯 |
| 后台持续监听剪贴板（未开启剪贴板历史时） | 隐私侵犯 |

### 6.3 允许的周期性任务（及约束）

| 任务 | 间隔 | 约束 |
|------|------|------|
| 自动备份检查 | 每天一次 | 在用户配置的时间窗口内；系统空闲时才执行；可跳过 |
| WAL checkpoint | 按写入量 | 被动触发；空闲时执行 |
| 自动保存 | 按用户活动 | 由用户操作触发，非定时 |
| 日志轮转 | 按大小/天 | 低优先级 |
| 缓存清理 | 每天一次 | 低优先级；仅在空闲时 |
| 更新检查 | **默认关闭** | 用户开启后也仅在启动时检查一次 |
| 备份健康检查 | 每周 | 用户可关 |

**约束**：所有周期性任务必须

1. 有明确且合理的间隔（不低于 1 分钟）。
2. 可被用户关闭。
3. 在系统休眠/睡眠时不执行，恢复后延后而不是补跑。
4. 在系统负载高时自动延后。
5. 合并执行（多个任务同时到期时合并为一次）。

### 6.4 资源目标

| 资源 | 空闲 | 典型使用 | 峰值 |
|------|------|---------|------|
| CPU | ≤ 0.3% | ≤ 8% | ≤ 60%（仅导入/查询时，可中断） |
| 内存（主窗口） | ≤ 180 MB | ≤ 400 MB | ≤ 800 MB |
| 内存（最小化到托盘） | ≤ 60 MB | — | — |
| 内存（完全退出） | **0** | — | — |
| 磁盘 IO | 0（无操作时） | 按需 | 导入时高（可限速） |
| 网络 IO | **0**（未开启网络功能时） | 0 | 按需 |
| 句柄数 | ≤ 500 | ≤ 2000 | — |
| 电池影响 | 无感知 | 低 | — |

### 6.5 空闲时的行为验证

**测试方法**：安装后启动，不做任何操作，静置 30 分钟，用系统监视器记录：

| 观测项 | 期望 |
|-------|------|
| CPU 曲线 | 平稳，接近 0，无周期性尖峰 |
| 内存曲线 | 平稳，无持续增长（无内存泄漏） |
| 磁盘 IO | 接近 0（除日志写入） |
| 网络 IO | **0**（网络功能未开启时） |
| 句柄数 | 平稳 |
| 线程数 | 平稳 |

> **内存泄漏检测**：长时间运行（≥ 8 小时）后，内存增长应 ≤ 10 MB。若持续增长，视为 P0 缺陷。

## 七、缓存策略

### 7.1 缓存分类

| 缓存 | 位置 | 上限 | 清理策略 | 可安全删除 |
|------|------|------|---------|-----------|
| 缩略图 | 缓存目录 | 200 MB | LRU | ✅ |
| 查询缓存 | 内存 | 64 MB | LRU + 库关闭时清 | ✅ |
| 元数据缓存 | 内存 | 32 MB | 库关闭时清 | ✅ |
| 附件预览缓存 | 缓存目录 | 500 MB | LRU | ✅ |
| 字体/图标缓存 | 缓存目录 | 20 MB | 版本升级时清 | ✅ |
| SQL 执行计划缓存 | 内存 | 16 MB | 库关闭时清 | ✅ |
| 向量索引 | 数据目录 | 无硬上限（可配） | 手动/可重建 | ⚠️ 可重建但耗时 |
| 搜索结果缓存 | 内存 | 8 MB | LRU | ✅ |

### 7.2 缓存原则

| 原则 | 说明 |
|------|------|
| **有硬上限** | 每个缓存都必须有明确的容量上限，不允许无限增长 |
| **LRU 淘汰** | 统一使用最近最少使用策略 |
| **可一键清除** | 设置中提供「清除全部缓存」 |
| **删了不影响正确性** | 任何缓存被删除后，程序应正常工作（只是变慢） |
| **不缓存敏感明文** | S2 数据的缓存必须加密或使用后立即清除 |
| **退出时释放** | 内存缓存随进程退出释放；磁盘缓存在退出时可选择清理（默认保留，因为它能加速下次启动） |

## 八、日志策略

### 8.1 日志分类

| 类型 | 内容 | 默认级别 | 保留 |
|------|------|---------|------|
| 运行日志 | 启动、模块加载、非致命错误 | 信息 | 7 天 |
| 错误日志 | 异常、崩溃堆栈 | 错误 | 30 天 |
| 审计日志 | 见 [08](08-privacy-security.md#六审计日志) | — | 90 天或按容量 |
| 性能日志 | 慢操作、慢查询 | 关闭 | — |
| 调试日志 | 详细过程（仅排查时开启） | 关闭 | 3 天 |

### 8.2 日志规则

| 规则 | 要求 |
|------|------|
| **不记录敏感数据** | 不记录笔记内容、字段值、SQL 语句中的字面量、口令、密钥、令牌 |
| **脱敏** | 记录路径时，用户主目录部分可用 `~` 代替 |
| **轮转** | 按大小（默认单文件 ≤ 10 MB）与时间（按天）轮转 |
| **上限** | 保留最近 N 个文件，总量有上限 |
| **本地** | 日志仅本地，不上报 |
| **可导出** | 用户可导出日志用于报告问题（导出时提示检查隐私内容） |
| **可关闭** | 运行日志可降低到"仅错误" |
| **级别可调** | 设置 → 高级 → 日志级别 |
| **注入防护** | 日志中的换行符与控制字符必须转义 |

### 8.3 日志文件命名与结构

```
logs/
├── app-2026-09-17.log           运行日志（按天）
├── app-2026-09-16.log
├── error-2026-09-17.log         错误日志
├── audit/                       审计日志（结构化，独立目录）
│   ├── audit-2026-09-17.jsonl
│   └── audit-2026-09-16.jsonl
└── perf/                        性能日志（仅开启时）
    └── perf-2026-09-17.jsonl
```

## 九、临时文件策略

| 来源 | 位置 | 清理时机 |
|------|------|---------|
| 导入暂存 | 系统临时目录（固定子目录） | 导入完成后立即 |
| 备份暂存 | 备份目标目录 | 备份完成后原子重命名或删除 |
| 导出暂存 | 导出目标目录 | 完成后 |
| 长截图拼接缓冲 | 系统临时目录 | 保存后立即 |
| 解压中间文件 | 系统临时目录 | 完成后 |
| 崩溃转储 | 数据目录 `crashes/` | 保留最近 5 份，超期自动删 |
| 更新下载包 | 缓存目录 | 安装后立即删 |

**要求**

- 全部临时文件使用固定前缀（如 `deskbase-tmp-`），便于识别与清理。
- 启动时扫描并清理超过 24 小时的自家临时文件（不碰别人的）。
- 退出时清理本次产生的全部临时文件。
- 不允许把临时文件写到用户桌面、文档等"显眼"位置。

## 十、启动与退出优化

### 10.1 启动流程优化

```
冷启动目标：≤ 1.2 秒到可交互

阶段分解：
  0.0 – 0.2s   进程创建、运行时初始化
  0.2 – 0.5s   加载核心资源、创建主窗口（立即显示骨架屏）
  0.5 – 0.9s   加载用户偏好、最近项目、渲染首屏
  0.9 – 1.2s   后台加载其他模块（不阻塞交互）
```

| 优化手段 | 说明 |
|---------|------|
| 骨架屏 | 窗口立即显示，不用等数据加载完 |
| 延迟加载 | 非首屏模块懒加载 |
| 并行初始化 | 独立模块并行初始化 |
| 缓存热路径 | 上次的界面状态缓存，直接恢复 |
| 不在启动时做重活 | 备份检查、完整性检查、更新检查都延后或按需 |
| 资源预编译 | 静态资源预编译、压缩 |
| 减少同步 IO | 启动路径上避免同步磁盘操作 |

### 10.2 退出流程

```
用户触发退出
    ↓
① 保存未提交内容（强制）
    ↓
② 执行 checkpoint
    ↓
③ fsync 关键文件
    ↓
④ 清除"脏标志"（标记正常退出）
    ↓
⑤ 关闭数据库连接、释放句柄
    ↓
⑥ 注销全局快捷键与钩子
    ↓
⑦ 清理本次临时文件
    ↓
⑧ 释放内存缓存
    ↓
⑨ 退出全部子进程
    ↓
⑩ 主进程退出
```

**退出超时保护**：若某项超过 5 秒未完成，弹出提示"正在保存，请稍候"，提供"继续等待"与"强制退出（可能丢失未保存内容）"选项。

**退出后自检**（开发与测试阶段）：验证进程表、句柄、钩子均已释放。

## 十一、构建与发布安全

### 11.1 依赖管理

| 要求 | 说明 |
|------|------|
| 版本锁定 | 全部依赖写入锁文件，锁文件入库 |
| 不引入不必要依赖 | 引入前评估：体积、维护活跃度、安全性、许可证 |
| 依赖审计 | CI 中执行漏洞扫描（SCA）与许可证合规检查 |
| 及时升级 | 高危漏洞 30 天内修复 |
| 禁止 | 分析 SDK、广告 SDK、社交 SDK、任何"可能上报"的库 |

### 11.2 构建

| 要求 | 说明 |
|------|------|
| 无网络构建 | 依赖预先缓存，构建过程不联网 |
| 可复现构建 | 相同源码 + 相同工具链 → 相同产物哈希 |
| 隔离环境 | 构建在隔离环境执行，不接触签名密钥 |
| 产物校验 | 构建产物哈希记录，发布时比对 |

### 11.3 发布产物

每个发布版本必须附带：

| 产物 | 说明 |
|------|------|
| 安装包 / 便携包 | 各平台 |
| 数字签名 | 平台签名（Windows Authenticode / macOS 公证 / Linux GPG） |
| SHA-256 校验和 | 单独文件 + Release Notes 中列出 |
| SBOM | SPDX 或 CycloneDX 格式 |
| 第三方许可证清单 | 全部依赖的许可证文本 |
| 可复现构建说明 | 如何自行构建出相同产物 |
| CHANGELOG | 变更说明 |

### 11.4 签名密钥管理

| 要求 | 说明 |
|------|------|
| 离线保管 | 密钥存于离线硬件令牌 |
| 多人持有 | 至少 2 人，避免单点失效 |
| 最小使用 | 仅在发布时使用 |
| 轮换公告 | 轮换时在 Release Notes 公告新旧指纹 |
| 泄露响应 | 立即吊销并发布安全公告 |

| # | 红线 |
|---|------|
| 1 | 空闲 CPU 平均 ≤ 0.3%，无周期性尖峰 |
