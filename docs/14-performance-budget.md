# 14 · 性能优化清单与可量化指标

> 性能不是"感觉挺快"，而是**一串可以被测量、被复现、被回归检测的数字**。

---

## 一、基准测试环境定义

所有指标必须在此环境下测量，跨环境比较无意义。

### 1.1 参照配置

| 档位 | 用途 | 配置 |
|------|------|------|
| **低配（Baseline-Low）** | 下限保证 | 4 核 CPU / 8 GB 内存 / SATA SSD / 集显 / Windows 11 |
| **中配（Baseline-Mid）★ 主基准** | 主要验收 | 8 核 CPU / 16 GB 内存 / NVMe SSD / 独显（入门级）/ Windows 11 |
| **高配（Baseline-High）** | 上限观察 | 16 核 CPU / 32 GB 内存 / NVMe SSD / 独显（中高端） |

**主基准为中配**。低配用于验证"下限可用"，高配用于观察扩展性。

### 1.2 测试数据规模标准集

| 数据集 | 内容 | 用途 |
|--------|------|------|
| **DS-S** | 5 个库、每库 10 表 × 1 000 行、100 篇笔记、200 张截图 | 日常场景 |
| **DS-M** | 5 个库、每库 20 表 × 50 000 行、1 000 篇笔记、2 000 张截图 | 中等负载 |
| **DS-L** | 2 个库、每库 10 表 × 1 000 000 行、5 000 篇笔记、10 000 张截图 | 压力场景 |
| **DS-XL** | 1 个库、1 表 × 10 000 000 行 | 极限场景 |

数据集生成脚本随仓库提供（不入库大文件，只入库生成脚本）。

### 1.3 测量工具

| 项目 | 工具 |
|------|------|
| 启动时间 | 程序内埋点（从进程创建到首屏可交互）+ 外部计时器交叉验证 |
| 内存 | 操作系统任务管理器 / 性能计数器，取稳定后 60 秒平均值 |
| CPU | 同上，采样间隔 ≤ 1 秒 |
| 帧率 | 程序内性能覆盖层（开发模式）+ 系统级帧率捕获 |
| 磁盘 IO | 系统性能计数器 |
| 网络 IO | 系统性能计数器 + 抓包 |
| 体积 | 安装包大小 / 解压后 du 统计 |
| 卸载残留 | 安装前快照 → 安装 → 卸载 → 快照对比（文件 + 注册表） |

### 1.4 测量规程

| 规则 | 说明 |
|------|------|
| **冷启动定义** | 重启系统后首次启动；或使用工具清空文件系统缓存 |
| **热启动定义** | 完全退出后 10 秒内再次启动 |
| **测量次数** | 每项指标至少 5 次，取中位数（不用平均值，避免离群值干扰） |
| **环境稳定性** | 关闭其他应用；禁用杀毒软件实时扫描；电源模式设为"高性能" |
| **数据一致性** | 使用同一份数据集生成脚本、同一版本程序 |
| **记录完整** | 每次测量必须记录：日期、版本、机器配置、数据集、原始数据 |
| **可复现** | 任何人按本文档操作应得到 ±10% 以内的结果 |

### 优化手段

| 手段 | 说明 |
|------|------|
| 骨架屏 | 窗口立即显示，内容异步填充 |
| 惰性加载 | 非首屏模块首次访问时加载 |
| 并行初始化 | 独立模块并行启动 |
| 界面状态恢复 | 缓存上次的布局与滚动位置 |
| 启动路径无同步 IO | 全部磁盘操作异步化 |
| 延迟非关键任务 | 备份检查、完整性检查、更新检查延后 30 秒或按需触发 |
| 预编译资源 | 模板、样式、图标预编译 |
| 二进制优化 | 移除调试符号、开启链接时优化 |

### 反模式（禁止）

- ❌ 启动时扫描全盘
- ❌ 启动时联网检查更新（默认关闭）
- ❌ 启动时加载全部数据到内存
- ❌ 启动时执行数据库完整性检查（应改为定期或按需）
- ❌ 启动时预加载 AI 模型

## 三、内存

> **⚠️ 目标已于 2026-09-17 修订。** 原目标「空闲 ≤ 180 MB」被 PoC 实测证明不可达，
> 原因是外壳选型（系统 WebView2，见 [ADR-0010](adr/0010-desktop-shell-selection.md)）
> 的**架构成本**：空页即 359.9 MB 起，无法通过业务优化消除。
>
> 修订依据与实测数据可由 `poc/` 下的基准脚本复现。
>
> **测量要求**：测内存必须做 **PID 差分**——先记基线 PID，只统计启动后新增的进程。
> WebView2 的 `msedgewebview2.exe` 被多个应用共享，按进程名统计会同时导致严重低估与严重高估。

| 场景 | 目标 | 上限 |
|------|------|------|
| **空闲（主窗口打开，无操作）** | **≤ 400 MB** | 500 MB |
| 空闲（最小化到托盘） | ≤ 120 MB | 200 MB |
| 完全退出后 | **0**（无残留进程） | 0 |
| 打开 DS-S 并使用 | ≤ 500 MB | 650 MB |
| 打开 DS-M 并使用 | ≤ 700 MB | 900 MB |
| 打开 DS-L | ≤ 1 400 MB | 2 000 MB |
| 浏览 100 万行表 | ≤ 400 MB（增量） | 600 MB |
| 截图标注器打开 | ≤ 250 MB（增量） | 400 MB |
| AI 模型加载（小模型） | ≤ 1 500 MB（增量） | 2 500 MB |
| AI 空闲 5 分钟后 | **回到基线**（模型完全释放） | 基线 + 50 MB |
| 长时间运行（8 小时）内存增长 | **≤ 10 MB** | 30 MB |
| 反复打开/关闭库 100 次后内存增长 | ≤ 20 MB | 50 MB |

**基线说明**：WebView2 外壳的空页基线实测为 **359.9 MB**（16 核 / 31.8 GB / Windows 11）。
因此「空闲 ≤ 400 MB」意味着**业务侧只能在上限内用约 40 MB**——这要求业务数据必须
严格按需加载（虚拟滚动、分页、惰性加载都是硬性要求，不是优化项）。

### 优化手段

| 手段 | 说明 |
|------|------|
| 虚拟滚动 | 只保留可见行的数据 |
| 分页/游标 | 大结果集分批，不一次性载入 |
| 弱引用缓存 | 缓存对象可被 GC 回收 |
| 硬上限缓存 | 所有缓存有容量上限与 LRU 淘汰 |
| 及时释放 | 关闭库时释放其全部资源 |
| 避免大对象复制 | 使用共享引用或内存映射 |
| 流式处理 | 导入/导出/备份流式处理，不整份载入 |
| 二进制数据外置 | 大 BLOB 存文件引用，不常驻内存 |

### 内存泄漏检测

| 方法 | 判据 |
|------|------|
| 长时间运行 | 8 小时后增长 ≤ 10 MB |
| 重复操作 | 打开/关闭库 100 次，增长 ≤ 20 MB |
| 界面切换 | 模块切换 500 次，增长 ≤ 20 MB |
| 截图循环 | 连续截图 200 次，增长 ≤ 50 MB |
| 查询循环 | 连续执行查询 1 000 次，增长 ≤ 30 MB |

> **P0 缺陷定义**：任何持续增长（线性上升无收敛）的内存曲线，视为 P0 缺陷，必须修复后才能发布。

## 四、CPU 与电量

| 场景 | 目标 | 上限 |
|------|------|------|
| **空闲（主窗口打开，无操作）** | **平均 ≤ 0.3%** | 1% |
| 空闲时的 CPU 峰值 | ≤ 3%（且不允许周期性出现） | 5% |
| 打字/编辑时 | ≤ 5% | 12% |
| 滚动万行表格 | ≤ 15% | 25% |
| 执行复杂查询 | ≤ 50%（单核） | 80% |
| 批量导入（10 万行） | 可用满多核，但可限速 | — |
| 备份进行中 | ≤ 30% | 50% |
| AI 推理（CPU 模式） | 可用满多核 | — |
| 后台空闲总 CPU（含子进程） | ≤ 0.5% | 1.5% |

### 电量消耗

| 场景 | 目标 |
|------|------|
| 空闲（笔记本，屏幕常亮） | 电池续航影响 ≤ 3% |
| 空闲（最小化到托盘） | 电池续航影响 ≤ 1% |
| 使用电池时的 AI 推理 | 默认降级到小模型，不使用 GPU |
| 使用电池时的备份 | 默认延后到接入电源后执行 |

### 优化手段

| 手段 | 说明 |
|------|------|
| 事件驱动 | 用事件代替轮询 |
| 任务合并 | 多个到期任务合并为一次执行 |
| 空闲检测 | 系统空闲时才执行后台任务 |
| 节流 | 滚动、resize、搜索输入等高频事件节流/防抖 |
| 增量渲染 | 只更新变化的部分 |
| 后台任务低优先级 | 后台任务使用低优先级线程 |
| 休眠感知 | 系统睡眠/休眠时暂停后台任务，恢复后延后而非补跑 |
| 电池感知 | 使用电池时降低后台活动频率 |

### 禁止的 CPU 行为

| ❌ | 原因 |
|---|---|
| 秒级或更高频轮询 | 电量与 CPU 浪费 |
| 空闲时持续的动画 | 无意义渲染 |
| 隐藏的定时器 | 用户无法感知的资源占用 |
| 使用 `sleep` 循环等待 | 应使用事件或条件变量 |
| 全表扫描作为常规操作 | 应走索引 |

## 六、界面渲染

| 场景 | 目标 | 上限 |
|------|------|------|
| **万行表格滚动（10 000 行）** | **≥ 55 FPS** | 45 FPS |
| 百万行表格滚动（虚拟滚动） | ≥ 50 FPS | 40 FPS |
| 卡片列表滚动 | ≥ 58 FPS | 50 FPS |
| 界面切换动画 | ≥ 55 FPS | 45 FPS |
| 窗口拖拽/缩放 | ≥ 55 FPS | 48 FPS |
| 输入延迟（击键到显示） | ≤ 50 ms | 80 ms |
| 点击响应（点击到视觉反馈） | ≤ 100 ms | 150 ms |
| 首屏内容呈现（TTC） | ≤ 1 000 ms | 1 500 ms |
| 布局偏移（CLS） | ≤ 0.05 | 0.1 |
| 长任务阻塞主线程 | ≤ 50 ms/次 | 100 ms/次 |

### 优化手段

| 手段 | 说明 |
|------|------|
| 虚拟滚动 | 只渲染视口内 + 少量缓冲行 |
| 行高固定 | 万行表格使用固定行高，避免动态测量 |
| 避免布局抖动 | 批量读写 DOM/布局属性 |
| 减少重绘区域 | 局部更新替代整体重绘 |
| 硬件加速 | 合理使用合成层（但避免层爆炸） |
| 图片懒加载 | 视口外图片不加载 |
| 长列表分页 | 超大数据集先分页 |
| 避免同步布局 | 不在循环中读取会引起重排的属性 |
| 骨架屏替代 spinner | 减少感知等待 |

### 界面性能反模式

| ❌ | 原因 |
|---|---|
| 一次性渲染上万 DOM 节点 | 卡死 |
| 在滚动事件中做重计算 | 掉帧 |
| 表格中每行都绑复杂组件 | 内存与渲染成本爆炸 |
| 使用 CSS 滤镜做大量元素 | GPU 压力 |
| 无节流的搜索输入 | 重复计算 |
| 同步读取大量数据后再渲染 | 主线程阻塞 |

### 优化手段

| 手段 | 说明 |
|------|------|
| 增量备份 | 只备份变化块 |
| 页级变更跟踪 | 记录修改过的页，避免全库扫描 |
| 压缩前优化 | 先压缩后加密（压缩率更高；但需注意加密前压缩会泄露压缩率信息，可配） |
| 流式处理 | 不整份载入内存 |
| 限速 | 限制备份的 CPU 与磁盘占用 |
| 空闲时执行 | 默认在系统空闲时才执行自动备份 |
| 可暂停 | 用户操作时可暂停备份 |

| 项 | 目标 |
|----|------|
| **彻底清除卸载后残留项** | **0** |

| 卸载后网络连接数 | 0 |
| 卸载后后台进程数 | 0 |
| 卸载后注册表残留项 | 0 |
| 卸载后计划任务残留 | 0 |
| 卸载后服务残留 | 0 |

**残留检测方法**

1. 安装前：对文件系统相关目录、注册表相关键、计划任务、服务、启动项做快照。
2. 安装 → 使用 → 卸载。
3. 再次快照，逐项对比。
4. 差异项必须全部为 0（允许的例外：系统自身的临时文件、用户主动放到数据目录的个人文件）。

| 依赖漏洞（高危） | ✅ |

| # | 项目 |
|---|------|

| 2 | 低配环境下"上限"列不超标 |
| 3 | 空闲 CPU ≤ 0.3% |
| 4 | 网络关闭时网络 IO = 0 |
| 5 | 8 小时内存增长 ≤ 10 MB |
