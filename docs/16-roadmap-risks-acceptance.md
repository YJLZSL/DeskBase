# 16 · 分阶段路线图、风险、取舍与验收标准

> 一份路线图的价值不在于它列出了多少功能，而在于它**明确说了先做什么、后做什么，以及为什么这样排**。

---

## 一、排序逻辑

### 1.1 排序依据

功能排序遵循四个梯次，**前一个梯次未达标不进入下一个**：

```
梯次 1 · 立住                      ← 没有它，产品不成立
  能用（可完成完整工作闭环）
  不丢（崩溃与断电不损数据）
  不泄露（默认本地、网络关闭、零污染）
  可卸干净（卸载残留为 0）

梯次 2 · 站高                      ← 决定产品上限
  数据能力（完整 SQL、关系、索引、视图）
  搜索与组织（全文检索、标签、模板）
  备份可信（健康检查、恢复演练、时间点恢复）

梯次 3 · 变强                      ← 决定差异化
  本地 AI（断网可用）
  远程访问（端到端加密、手机端）
  自动化（规则、任务、工作流）

梯次 4 · 长大                      ← 决定生命力
  插件生态
  第三方集成
  多语言与社区翻译
```

### 1.2 三条不可调换的顺序

| 顺序 | 理由 |
|------|------|
| **先"不丢"再"强大"** | 数据丢失不可逆，功能缺失可后补 |
| **先"不泄露"再"联网"** | 一旦放开网络再收紧，用户信任已受损 |
| **先"能卸干净"再"装得漂亮"** | 卸载残留是长期债务，越晚处理代价越高 |

## 二、阶段路线图

### M0 · 地基与骨架

**主题**：在写第一行业务代码前，把"不返工"的东西定下来。

| 范围 | 内容 |
|------|------|
| 治理 | 仓库初始化、README、LICENSE、CONTRIBUTING、CoC、SECURITY、ROADMAP、GOVERNANCE |
| 文档 | 完整产品与工程方案（`docs/00`–`docs/17`）、ADR 机制 |
| 架构 | 信息架构冻结、数据模型 v1、迁移框架设计 |
| 选型 | 技术选型决策并固化为 ADR |
| 工程 | CI 骨架（lint / typecheck / test / build）、依赖锁定、漏洞扫描接入 |
| 平台 | 三平台构建流水线原型 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | 从空仓库一键构建出可启动的空壳应用 |
| 2 | CI 全绿且耗时 ≤ 15 分钟 |
| 3 | 信息架构全量清单已冻结并通过评审 |
| 4 | 数据模型 v1 有对应 ADR |
| 5 | 依赖锁定且漏洞扫描无高危未处理项 |
| 6 | 三平台均可产出可执行产物 |

**主要风险**：选型反复导致返工。**缓解**：ADR 一旦接受，改动需走 RFC，避免边写边改。

### M1 · MVP：能用的办公台

**主题**：让用户第一天就能把自己的东西放进来，并且觉得比备忘录舒服。

| 范围 | 内容 |
|------|------|
| 工作台 | 首页、最近项目、待办聚合、日程、快捷操作、全局搜索、命令面板 |
| 笔记 | Markdown、双向链接、大纲、标签、模板、自动保存、版本历史 |
| 表格 | 单元格编辑、列类型、排序筛选、冻结、基础公式 |
| 看板 | 分列、拖拽、卡片 |
| 日历 | 月/周/日、多日历、重复事件、提醒 |
| 待办 | 清单、子任务、优先级、截止日、重复规则 |
| 文件 | 用户指定目录索引、预览、标签（**不扫描全盘**） |
| 剪贴板 | 文本与图片历史、搜索、置顶、敏感模糊、容量上限 |
| **截图** | 区域/窗口/全屏/延时、**滚动长截图**、**长图拼接**、全套标注、贴图、历史 |
| OCR | 截图 OCR、图片 OCR、结果编辑与存入 |
| 标签 / 模板 | 统一标签、内置模板库、自定义模板 |
| 导入导出 | CSV / JSON / Markdown |
| 可靠性 | 自动保存、草稿恢复、回收站、误删恢复 |
| 隐私 | 网络总开关（默认关）、剪贴板本地化、OCR 本地化 |
| 打包 | 便携版（**零注册表写入**） |
| 帮助 | 新手引导、示例数据、隐私说明、FAQ |

**验收标准**

| # | 判据 | 判据说明 |
|---|------|---------|
| 1 | 新人 10 分钟内完成"记笔记 + 建清单 + 截长图" | 5 人测试，≥ 4 人成功 |
| 2 | 万行表格滚动 ≥ 55 FPS | 中配，DS-M |
| 3 | 冷启动 ≤ 1.2 s、空闲内存 ≤ 180 MB | 中配 |
| 4 | **断网环境下全部 MVP 功能可用** | 拔网线走完完整闭环 |
| 5 | 便携版不写任何注册表项 | 注册表快照对比，差异 = 0 |
| 6 | 强杀进程 50 次后数据一致 | 损坏率 = 0 |
| 7 | 长截图在 10 屏页面上成功率 ≥ 90% | 覆盖浏览器/聊天/列表三类页面 |
| 8 | 截图 ≤ 400 ms、OCR（1080p）≤ 1.5 s | 中配 |

**退出条件**：以上 8 项全部达标。

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 长截图在不同应用上成功率不稳定 | 核心差异化能力受损 | 早期在 20+ 真实应用上测试；提供手动滚动模式兜底 |
| 剪贴板监听引发隐私质疑 | 信任受损 | 默认不记录来源应用；提供排除列表与退出清空；隐私说明明示 |
| 截图与 OCR 体积膨胀 | 超过体积目标 | 组件可选化 + 按需下载语言包 |
| 大表格性能不达标 | 核心体验受损 | 虚拟滚动从第一版就做，不做"先全量渲染以后优化" |

### M2 · 数据核心：SQL 可用

**主题**：从"能记"到"能查"。

| 范围 | 内容 |
|------|------|
| 库管理 | 新建/打开/多库、库属性、只读打开、完整性检查 |
| 表 | 建表向导、字段编辑、类型、约束、表/字段注释、安全改结构 |
| 关系 | 外键、一对多、多对多、级联规则、ER 图 |
| 查询 | SQL 编辑器（高亮/补全/格式化/多标签）、执行、结果表格、历史、收藏、参数化 |
| 查询向导 | 免 SQL 的图形化构建器（新手默认入口），可查看等价 SQL |
| 视图 | 视图设计器（可视化/DDL 双模式） |
| 数据编辑 | 网格编辑、批量编辑、粘贴多行、行内校验、撤销 |
| 导入 | CSV / TSV / JSON / Excel，含向导、类型推断、错误报告 |
| 导出 | CSV / TSV / JSON / Excel / SQL |
| 性能 | 结果集上限、分页、后台执行长查询、查询超时 |
| 安全 | 参数化查询、危险操作确认、改结构前自动快照 |
| 教程 | SQL 入门教程（6 课，可在示例库练习） |

**验收标准**

| # | 判据 |
|---|------|
| 1 | 导入 10 万行 CSV ≤ 15 s，且错误行有报告 |
| 2 | 索引命中查询（万行表）≤ 50 ms |
| 3 | 多表 JOIN（3 表，各 10 万行）≤ 800 ms |
| 4 | 从没写过 SQL 的用户能用查询向导完成三表关联查询 |
| 5 | 查询向导每步都能查看等价 SQL |
| 6 | 破坏性操作（DROP / 无 WHERE 的 DELETE）必须二次确认 |
| 7 | 改结构前自动创建快照，可一键回退 |
| 8 | 打开库（10 万行）≤ 800 ms |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 新手被表结构概念劝退 | 核心用户流失 | 查询向导作为默认入口；类型用中文语义名；"这是什么"随处可达 |
| 中文表名/字段名兼容问题 | 数据不可用 | 早期用中文标识符做全流程测试 |
| 大表改结构耗时过长 | 用户等待 | 预演耗时并提示；后台执行 + 进度 |
| Excel 导入格式千奇百怪 | 导入失败率高 | 建立"脏数据"测试集，覆盖合并单元格、多表头、混合类型 |

### M3 · 不丢数据：可靠性与容灾

**主题**：让用户敢把真实工作托付进来。

| 范围 | 内容 |
|------|------|
| 存储 | 事务、WAL、原子写入、`fsync`、定期 checkpoint、崩溃一致性检测 |
| 崩溃恢复 | 异常退出检测、恢复向导、恢复报告、事故快照 |
| 草稿 | 编辑草稿区、崩溃后草稿恢复 |
| 版本历史 | 文档版本、结构版本、diff、回滚、版本锁定 |
| 回收站 | 跨模块回收站、保留窗口、恢复、清空 |
| 备份 | 自动备份（默认开）、手动备份、快照、备份位置配置、保留策略 |
| 备份增强 | 全量/增量/差异、压缩、加密、校验和、完整性验证 |
| 恢复 | 恢复向导（含沙箱预览）、恢复到新位置/覆盖、时间点恢复 |
| 验证 | **备份健康检查**、**恢复演练** |
| 多目标 | 最多 3 个备份目标 |
| 迁移 | 一键全量导出（开放格式）、换机迁移流程 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | **写入过程中强杀进程 100 次，第 101 次启动后完整性检查全部通过** |
| 2 | 崩溃最多丢失最后一次未提交事务 |
| 3 | 异常退出后**必进**恢复向导，不静默忽略 |
| 4 | 恢复前自动创建事故快照 |
| 5 | 备份健康检查能发现"备份文件损坏"（人为损坏一份备份验证） |
| 6 | 恢复演练能在沙箱中真实恢复并输出报告 |
| 7 | 增量备份（1 GB 库，5% 变更）≤ 20 s |
| 8 | 恢复（1 GB 库）≤ 60 s |
| 9 | 卸载时可选择保留数据 / 导出后卸载 / 彻底清除 |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| WAL 实现有缺陷导致恢复失败 | 数据损坏，信任崩塌 | 在 M3 开始前先写崩溃一致性测试套件（先测后写） |
| 备份空间占用过大 | 用户禁用备份 | 默认增量 + 压缩 + 保留策略；显示占用并给建议 |
| 用户从不做恢复演练 | 出事时才发现备份不可用 | 每季度主动提醒；首次配置备份后引导做一次演练 |
| 跨版本迁移丢失数据 | 灾难性 | 迁移前强制备份 + 迁移失败回滚 + 前向兼容测试 |

### M4 · 安心：隐私与安全加固

**主题**：把"本地优先"从口号变成可验证的事实。

| 范围 | 内容 |
|------|------|
| 加密 | 库级加密、敏感字段级加密、附件加密、配置加密 |
| 密钥 | 口令派生（Argon2id 等）、系统密钥链、恢复码、改口令、密钥轮换 |
| 网络 | 网络总开关、分项开关、连接审计日志、网络自证界面 |
| 审计 | 审计日志（本地、可查、可导、可清空、有上限） |
| 透明 | 「我本机存了什么」视图 |
| 供应链 | SBOM 生成、依赖锁定入 CI、漏洞扫描门禁 |
| 构建 | 可复现构建流水线 |
| 发布 | 三平台代码签名、SHA-256 校验和、第三方许可证清单 |
| 安全测试 | SAST、模糊测试（解析器）、越权测试、注入测试 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | 用户能在界面上看到全部本地数据位置与占用 |
| 2 | **网络功能全部关闭时，网络 IO = 0 字节**（抓包 + 系统计数器双验证） |
| 3 | 开启加密后，用第三方工具打开数据库文件读不出明文 |
| 4 | 忘记口令可用恢复码重置；未保存恢复码时明确告知不可恢复 |
| 5 | 每次发布附带 SBOM 与校验和，签名可验证 |
| 6 | 可复现构建：同源码两次构建产物哈希一致 |
| 7 | 审计日志完整记录全部出站连接尝试 |
| 8 | 关闭全部网络功能后，程序可完整使用（含加密数据库） |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 加密导致性能明显下降 | 用户关闭加密 | 分块/页级加密；公布性能数据让用户知情取舍 |
| 用户忘记口令且未保存恢复码 | 数据永久丢失 | 开启时必须确认已保存恢复码；提供打印/导出恢复码 |
| 加密功能实现有缺陷（如密钥泄漏） | 灾难性 | 第三方安全审计；避免自研密码学 |
| 代码签名证书成本与流程复杂 | 发布阻塞 | 早期准备证书；建立签名流程文档 |

### M5 · 变聪明：本地 AI

**主题**：AI 有用，但不出网。

| 范围 | 内容 |
|------|------|
| 推理 | 可插拔本地推理后端、模型管理与校验、资源控制、空闲释放 |
| 能力 | 自然语言查询（NL2SQL）、摘要、分类、翻译、OCR 增强、语音转写、语义搜索、报表解读 |
| 隐私 | AI 隐私面板、一键完全关闭、数据分类过滤、S2/S3 拦截 |
| 外部服务 | 逐次授权、脱敏预览、调用审计（默认完全禁用） |
| 存储 | 向量索引本地化、对话记录本地存储与一键清除 |
| 安全 | AI 生成 SQL 必须人工确认；不允许自动执行 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | **完全断网时全部 AI 功能可用** |
| 2 | AI 调用期间网络 IO = 0（本地模型路径） |
| 3 | NL2SQL 生成的 SQL 必须展示并等待确认，绝不自动执行 |
| 4 | 若配置外部服务，发送前必须展示实际将发送的内容 |
| 5 | S2/S3 数据在外发请求中被拦截 |
| 6 | AI 空闲 5 分钟后模型完全释放，内存回到基线 |
| 7 | 不使用 AI 时，AI 相关后台进程数 = 0 |
| 8 | 一键完全关闭 AI 后，界面不再出现任何 AI 入口 |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 本地模型质量不足以支撑 NL2SQL | 功能鸡肋 | 提供"生成 → 展示 → 用户修正"闭环；不承诺一次生成正确 |
| 模型体积大、下载门槛高 | 采纳率低 | 小模型优先；模型按需下载；提供多档选择 |
| 模型加载导致内存暴涨 | 违反资源目标 | 空闲释放；内存上限；按任务选模型 |
| 用户误以为 AI 会修改数据 | 数据风险 | AI 输出永远只作建议；写操作必须人工确认 |
| 外部 AI 服务成为事实上的数据外泄通道 | 隐私崩塌 | 默认禁用 + 逐次确认 + 脱敏预览 + 审计 |

### M6 · 走出去：远程与移动

**主题**：手机能安全地看到桌面数据，中间没人能看。

| 范围 | 内容 |
|------|------|
| 服务 | 远程服务开关（默认关）、仅局域网 / 局域网 + 自托管中继 |
| 配对 | 二维码 + 一次性码 + **设备指纹确认**、已配对设备管理、吊销 |
| 通道 | 局域网自动发现与直连、自托管中继、端到端加密、前向保密、重放保护 |
| 权限 | 五维粒度（库/表/字段/操作/时段）、预设角色、以设备视角预览 |
| 审计 | 连接、操作、越权尝试、权限变更 |
| 手机端 | 查看、录入、审批、查询、通知、离线队列、冲突提示 |
| 省电 | 按需连接、不后台常驻、无轮询 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | **抓包无法读出明文内容** |
| 2 | 未开启远程时，不监听任何端口、不做任何局域网发现 |
| 3 | 配对必须经用户确认设备指纹，无"跳过"选项 |
| 4 | 越权请求被服务端（桌面端）拒绝并记入审计 |
| 5 | 手机端无后台常驻服务，空闲耗电为 0 |
| 6 | 同网段操作延迟 ≤ 800 ms |
| 7 | 桌面端可一键吊销设备，吊销后立即失效（不需对方配合） |
| 8 | 手机端不存储完整数据副本，可一键清除本地缓存 |
| 9 | 无网络/不可达时手机端明确提示，不静默失败 |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 端到端加密实现有缺陷 | 隐私崩塌 | 使用成熟密码学原语；第三方审计；不做自研协议 |
| 用户忘关远程访问 | 暴露面扩大 | 托盘状态提示；提供"N 小时后自动关闭"选项 |
| 局域网发现泄露设备信息 | 隐私顾虑 | 默认关闭；开启时说明；仅广播最少信息 |
| 移动端开发与维护成本高 | 拖慢主线 | 移动端保持极简（只做查看/录入/审批）；复用同一套加密与协议 |
| 自托管中继部署门槛高 | 采纳率低 | 提供容器镜像与一键部署说明；局域网直连优先 |

### M7 · 长出来：自动化与插件

**主题**：让软件替用户重复做事，让别人替我们扩展能力。

| 范围 | 内容 |
|------|------|
| 自动化 | 规则（IF-THEN）、触发器、定时任务、批量处理、工作流编排 |
| 任务管理 | 启用/暂停、执行历史、失败重试、执行窗口、并发限制 |
| 插件宿主 | 独立进程沙箱、权限清单、资源上限、崩溃隔离 |
| 插件 SDK | 类型定义、示例、模板、本地加载、调试工具 |
| 插件市场 | 官方源、自建镜像、本地安装、权限审计、上架审核、签名标注 |
| 插件管理 | 启用/禁用、权限查看与撤销、更新、彻底卸载 |
| 扩展点 | UI 面板、导入导出格式、动作提供者、集成适配、主题 |

**验收标准**

| # | 判据 |
|---|------|
| 1 | 社区能独立开发一个通过权限审计的插件并上架 |
| 2 | 插件不得在未授权时联网（验证：插件尝试联网被拒绝且记录） |
| 3 | 插件崩溃不影响主程序，且给出明确提示 |
| 4 | 插件卸载后无残留文件、配置、进程 |
| 5 | 定时任务不空转、可合并、可暂停、系统休眠时延后 |
| 6 | 自动化任务失败有重试与通知 |
| 7 | 市场不上报任何用户端行为数据 |

**主要风险**

| 风险 | 影响 | 缓解 |
|------|------|------|
| 插件沙箱被绕过 | 安全事件 | 权限在服务端校验，不信任插件；沙箱以进程隔离为底线 |
| 恶意插件破坏信任 | 声誉受损 | 上架审核 + 权限最小化 + 用户可撤销 + 下架机制 |
| 自动化误操作破坏数据 | 数据损失 | 自动化任务执行前快照；提供"演练模式"；可一键撤销 |
| 插件 API 频繁破坏性变更 | 生态流失 | 插件 API 语义化版本；破坏性变更提前一个次版本公告 |

## 四、关键取舍记录

| # | 取舍 | 选择 | 放弃的 | 理由 |
|---|------|------|-------|------|
| T1 | 性能 vs 持久性 | **持久性优先**（每次提交 `fsync`） | 写入吞吐 | 数据丢失不可逆；目标场景是人工录入而非高频写入 |
| T2 | 功能全 vs 上手快 | **上手快**（渐进式复杂度） | 新手直接看到全部功能 | 核心用户是普通办公用户 |
| T3 | 便利 vs 隐私 | **隐私优先**（网络默认关闭、无云同步） | 跨设备即时同步的便利 | 便利可靠可选功能补，隐私丢了补不回来 |
| T4 | 体积 vs 开箱完整 | **体积优先**（大组件可选化、模型按需下载） | 下载后即全部可用 | 首次下载体验影响采纳率 |
| T5 | 单文件库 vs 服务化 | **单文件嵌入式** | 多客户端并发、服务化部署 | 目标用户是个人；单文件才便于备份迁移 |
| T6 | 云同步 vs 自托管 | **自托管** | 开箱即用的同步 | 官方托管会让"数据不经过我们"的承诺失效 |
| T7 | AI 能力 vs 资源占用 | **资源优先**（空闲释放模型） | AI 常驻带来的响应速度 | 「安静」是明确原则 |
| T8 | 加密默认开 vs 用户选择 | **用户知情选择**（首启询问） | 默认最安全的假象 | 加密有口令丢失风险，必须用户知情 |
| T9 | 插件自由度 vs 安全 | **安全优先**（进程隔离 + 权限清单） | 插件可直接操作界面的自由度 | 生态信任是长期资产 |
| T10 | 快速发版 vs 发布门禁 | **门禁优先** | 更快的发版节奏 | 隐私与数据的承诺不能因赶版本而打折 |
| T11 | 全平台同体验 vs 平台惯用法 | **平台惯用法优先** | 完全一致的界面与快捷键 | 用户对本地平台有肌肉记忆 |
| T12 | 功能广度 vs 单点做透 | **单点做透**（先做好本地这一件事） | 通用数据库客户端 | 功能稀释是产品失败的主因之一 |
| T13 | 默认主题 | **宣纸** | 跟随系统 | 宣纸是产品识别度的一部分，应被每个用户看到一次 |
| T14 | 分发形态（v0.1.0） | **便携版 + Windows 安装版 exe 同时提供** | 只做便携版 | 两种形态服务不同场景：便携版适合试用与携带，安装版适合长期使用与多人电脑；只出其一都会挡住一部分用户。~~原决策为只做便携版，已作废~~ |
| T15 | 界面语言（v0.1.0） | **只做中文（zh-CN）** | 多语言同步做 | 中文用户是第一批目标，先把中文体验打磨到位 |
| T16 | 中文字库 | **不内嵌**（只用系统字体栈） | 内嵌中文字库 | 中文字库 10–20 MB，直接违反包体积目标（≤ 80 MB） |
| T17 | 安装包覆盖平台（v0.1.0） | **只做 Windows 安装包** | 三平台安装包一次做齐 | Windows 是主战场；Linux / macOS 先出便携包，安装包顺延 v0.2.0 |

## 六、里程碑依赖关系

```
M0 地基
  │
  ├──→ M1 MVP 办公台 ──┬──→ M2 数据核心 ──→ M3 可靠性 ──→ M4 隐私安全加固
  │                    │                                    │
  │                    └──→ （截图/OCR 独立演进）             │
  │                                                          │
  └──→ M8 安装卸载体验（可与 M1–M4 并行，但发布前必须完成）   │
                                                             │
M3 + M4 ──→ M5 本地 AI ──→ M6 远程与移动 ──→ M7 自动化与插件
                                                             │
M4 + M5 + M6 + M7 ──→ M8 打磨与性能达标 ←────────────────────┘
```

**依赖说明**

| 依赖 | 理由 |
|------|------|
| M2 依赖 M1 | 需要先有数据载体，再有查询能力 |
| M3 依赖 M2 | 可靠性必须覆盖数据库层 |
| M4 依赖 M3 | 加密要在数据层稳定后引入 |
| M5 依赖 M3 + M4 | AI 需要数据层的向量存储与安全层的隐私闸门 |
| M6 依赖 M4 | 远程访问的安全模型依赖加密与权限体系 |
| M7 依赖 M4 + M5 | 插件权限模型依赖权限体系；自动化可能触发 AI |
| M8 依赖全部 | 打磨阶段覆盖所有已实现功能 |

**关键路径**：M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8

**并行机会**：截图/OCR 能力、安装卸载界面、文档与教程、多语言可在主线推进时并行。
