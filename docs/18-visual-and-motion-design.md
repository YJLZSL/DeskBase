# 18 · 视觉、质感、字体与动效设计系统

> 这份文档定义 DeskBase「看起来是什么样、动起来是什么感觉」。
> 它和 [14 · 性能指标](14-performance-budget.md) 具有同等约束力：**好看不能以变慢为代价**。

---

## 一、设计立场

### 1.1 三条主张

| # | 主张 | 含义 |
|---|------|------|
| 1 | **阅读优先** | 视觉的第一职责是让用户长时间看屏幕不累。任何装饰若降低可读性，一律砍掉 |
| 2 | **质感靠材质，不靠图形** | 「中式」不是画水墨画、不是加云纹边框、不是贴印章图案。它体现在纸的底色、墨的字色、克制的留白与极轻的纹理上 |
| 3 | **动效服务于理解** | 动效的第一个作用是让状态变化可被理解（东西从哪来、到哪去），第二个作用才是让人愉悦。反过来做就是噪声 |

### 1.2 明确不做

| ❌ 不做 | 原因 |
|--------|------|
| 水墨笔触、云纹、回纹等装饰图形 | 装饰性元素会与内容争夺注意力 |
| 循环播放的动画（飘落的花瓣、流动的墨迹） | 违反「安静」原则；持续占用 GPU |
| 拟物化的纸张阴影、卷轴展开效果 | 视觉噪音大，缩放下表现差 |
| 全屏渐变背景、大色块 | 压低对比度，长时间看疲劳 |
| 鼠标跟随光效、粒子 | 无信息价值 |
| 完成操作时的全屏庆祝动画 | 打断节奏 |
| 超过 500ms 的界面过渡 | 让人感觉慢 |

### 1.3 愉悦感的真实来源

愉悦不来自"加了动画"，来自这五件事：

| 来源 | 具体做法 |
|------|---------|
| **跟手** | 拖拽元素 1:1 跟随指针，零延迟；不出现"追不上手"的情况 |
| **即时反馈** | 点击到视觉反馈 ≤ 100ms，绝不出现"点了没反应" |
| **物理直觉** | 缓动符合直觉：进入减速、退出加速、落位有极轻微回弹 |
| **有始有终** | 每个操作都有明确的结束信号（保存成功、截图完成、导入结束） |
| **克制的惊喜** | 在极少数地方给一点点超预期（如第一次完成长截图时的轻微舒展），但绝不过度，也绝不重复到让人烦 |

> 判断标准：**如果用户注意到动画本身，说明做多了。**

## 二、主题体系

### 2.1 主题的结构

一个主题不是一份配色表，而是**四件东西的组合**：

```
主题 = 色板 + 质感 + 字号/排版尺度 + 推荐的动效强度
```

| 组成 | 说明 |
|------|------|
| **色板** | 语义化颜色 token（见第四节），不含硬编码色值 |
| **质感** | 背景纹理及其强度（宣纸主题有纸纹，其他主题可能没有） |
| **排版尺度** | 主题可对字号、行高、字距给出微调（如宋体主题行高更大） |
| **动效强度** | 主题可建议一个动效档位（如「高对比」主题建议「精简」） |

用户改动主题中的任一项，即自动派生为「自定义主题」。

### 2.3 宣纸主题详解

**设计意图**：模拟一张摊开的宣纸——不是陈旧发黄的仿古纸，而是新的、干净的、微微偏暖的纸。

|-------|------|------|
| `--paper` | `#F6F2E9` | 主背景（纸底） |
| `--paper-2` | `#EFEADE` | 次级背景（侧栏、分组底） |
| `--card` | `#FCFAF5` | 卡片、弹层、输入框底 |
| `--ink` | `#2B2823` | 主文字（不用纯黑，避免刺眼） |
| `--ink-2` | `#5A554C` | 次级文字 |
| `--ink-3` | `#8B8578` | 辅助文字、占位符 |
| `--line` | `#DDD5C6` | 分隔线、边框 |
| `--line-strong` | `#C8BEA9` | 强调边框 |
| `--accent` | `#2E4A6B` | 主强调：焦点、主按钮、选中态（靛青） |
| `--accent-soft` | `#DDE5EE` | 强调的浅色底（选中行背景） |
| `--seal` | `#A63A2E` | 朱砂：仅用于印章式点缀与极少量重点标记 |
| `--success` | `#4A6B3E` | 竹绿 |
| `--warning` | `#8F6416` | 赭黄 |
| `--danger` | `#8C2B22` | 深朱 |
| `--shadow` | `rgba(60, 50, 35, 0.08)` | 阴影基色（暖调，不用纯黑阴影） |

**朱砂（`--seal`）的使用约束**：整个界面中同时出现的朱砂元素不超过 **2 处**。它的价值来自稀少。滥用即失效。

**纸纹的呈现**：
- 只在 `--paper` 与 `--paper-2` 层叠加
- **不叠加在文字、卡片、输入框内部**（保证阅读区是干净的纯色底）
- 强度默认「轻」（见 3.2）

### 2.5 主题切换

| 要求 | 规格 |
|------|------|
| 切换耗时 | ≤ **200 ms** 完成全界面刷新 |
| 切换方式 | 设置内选择；也支持命令面板「切换主题」 |
| 是否闪白 | **不允许**。切换过程不得出现白色闪屏 |
| 切换动画 | 颜色过渡 180ms（`transition: background-color, color, border-color`），不做遮罩式切换动画 |
| 跟随系统 | 系统主题变化时自动切换，且需监听系统事件而非轮询 |
| 记忆 | 每个主题记住自己的「质感强度」偏好 |
| 导入导出 | 自定义主题可导出为 JSON 分享；导入时**不覆盖**网络相关设置 |

**不做的切换效果**：渐变遮罩、径向展开、翻转。理由：这些效果需要全屏重绘，会掉帧并显得廉价。

### 2.6 自定义主题包格式

第三方或用户自制主题以目录形式提供：

```
themes/<theme-id>/
├── theme.json     # 元信息：id、名称、作者、版本、基准明暗
├── tokens.json    # 全部语义 token 的映射
├── texture.json   # 纹理参数（可选）
└── preview.png    # 预览图（1200×800）
```

**主题必须提供的 token 清单**（缺项则继承基准主题对应值，并给出警告）：

| 类别 | 必需 token |
|------|-----------|
| 背景（4 项） | `color-bg-base`、`color-bg-raised`、`color-bg-sunken`、`color-bg-overlay` |
| 文字（5 项） | `color-text-primary`、`color-text-secondary`、`color-text-muted`、`color-text-disabled`、`color-text-inverse` |
| 边框（3 项） | `color-border-subtle`、`color-border-default`、`color-border-strong` |
| 强调（4 项） | `color-accent`、`color-accent-hover`、`color-accent-active`、`color-accent-soft` |
| 语义（4 项 + soft 变体） | `color-success`、`color-warning`、`color-danger`、`color-info` 及各自 `soft` 变体 |
| 状态（3 项） | `color-focus-ring`、`color-selection-bg`、`color-hover-bg` |
| 阴影（4 级） | `shadow-1` … `shadow-4` |
| 圆角（4 档） | `radius-sm` / `radius-md` / `radius-lg` / `radius-full` |
| 间距（8 档） | `space-1` … `space-8` |
| 字体（3 项） | `font-family-ui`、`font-family-content`、`font-family-code` |
| 动效（4 + 4 项） | `duration-instant` / `duration-fast` / `duration-normal` / `duration-slow`；`easing-standard` / `easing-enter` / `easing-exit` / `easing-emphasized` |

### 2.7 主题校验规则

导入或启用自定义主题前自动检查：

- 必需 token 是否齐全；
- 文字与背景对比度 ≥ 4.5:1；
- 交互元素对比度 ≥ 3:1；
- **不通过则拒绝启用并指出具体项，不做"警告后放行"**。

## 三、材质与质感

### 3.1 技术方案

宣纸纹理的实现，两种方案并存，按下述优先级选择：

| 方案 | 说明 | 采用 |
|------|------|:----:|
| **① 程序化生成** | 启动时用噪声函数生成一次，零资源体积、分辨率无关、参数可调 | ✅ 首选 |
| ② 小尺寸可平铺位图 | 打包进程序的 ≤256×256 灰度噪声图，单张 ≤ 32 KB | ✅ 备选 |
| ③ CSS 多层渐变叠加 | 用多个 `radial-gradient` 模拟，无需位图 | ✅ 用于极轻强度 |
| ④ SVG filter（`feTurbulence`） | 效果最像，但运行时开销大 | ❌ 不用 |

**无论选哪种，都必须满足**：四层拆解（见 3.2）、总不透明度 ≤ 8%、无缝平铺、不覆盖文字与卡片内部、不触发滚动重绘、空闲 CPU 增量为 0、分辨率无关（高 DPI 下不模糊不失真）。

**性能约束**

| 约束 | 要求 |
|------|------|
| 纹理尺寸 | 程序化生成：启动时一次性生成；位图备选：≤ 256×256，可平铺，单张 ≤ 32 KB |
| 生成本身开销 | 启动时一次性生成，≤ 30 ms |
| 渲染开销 | 相比纯色背景，帧率下降 ≤ 3% |
| 内存 | ≤ 4 MB |
| 关闭纹理后 | 帧率与纯色背景一致 |
| 合成方式 | `background-image` + `background-repeat`，或独立叠层 + `mix-blend-mode: multiply`（低透明度） |
| 是否触发重绘 | **不触发**。纹理层不随滚动重绘（使用独立合成层或固定附着） |
| 空闲 CPU 增量 | **0** |
| 滚动帧率影响 | ≤ 1 FPS |

**反模式（禁止）**

- ❌ 用 `feTurbulence` 做实时噪声
- ❌ 每次渲染重新生成纹理
- ❌ 用大量 DOM 元素堆叠纹理
- ❌ 纹理层参与布局（必须是纯视觉叠层）

### 3.2 宣纸质感的四层拆解

宣纸观感来自四层叠加（见下表）。**总不透明度不超过 8%**，超过会干扰文字。

| 层 | 内容 | 实现 | 不透明度 |
|----|------|------|---------|
| L1 基色 | 纸的本色 | 纯色填充 | 100% |
| L2 纤维 | 极细的横向纤维，噪点 + 方向模糊 | 噪点 + 方向模糊 | 2%–3% |
| L3 帘纹 | 抄纸竹帘留下的等距浅纹，间距 3–6px | 细密条纹 | 1%–2% |
| L4 晕染 | 局部极淡深浅变化，模拟吸墨，大尺度低频噪声 | 大尺度低频噪声 | 2%–4% |

要求：

- 纹理层 `pointer-events: none`，不拦截点击；
- 必须无缝平铺；
- 分辨率无关：高 DPI 下不模糊、不失真。

### 3.3 质感强度分级

| 档位 | 不透明度 | 说明 | 适用 |
|------|:-------:|------|------|
| 关 | 0 | 纯色底 | 低配设备、无障碍主题、电池模式 |
| 轻 | 0.025 | **默认**。几乎察觉不到，但拿掉后会感觉"少了点东西" | 默认 |
| 标准 | 0.045 | 能看出纸感，不影响阅读 | 大屏、校对场景 |
| 明显 | 0.075 | 明确的纸质感 | 演示、截图 |

**自动降级规则**（按优先级）：

1. 系统「减少动效」或「提高对比度」开启 → 质感降到「关」
2. 无障碍主题 → 质感固定为「关」
3. 使用电池 → 降到「轻」或「关」
4. 设备性能评分低 → 降到「轻」
5. 帧率检测低于 50 FPS 持续 3 秒 → 临时降到「轻」，并提示用户

### 3.4 边界与毛边

细节决定质感，但都不能抢内容：

| 细节 | 做法 |
|------|------|
| 卡片边缘 | 不用纯硬边框，用 1px 极淡描边 + 极轻内阴影模拟纸的厚度 |
| 分隔线 | 不是实线，是 1px、透明度 12%–18% 的线 |
| 滚动条 | 圆角细条，颜色取辅助墨色透明度 40%，悬停加深 |
| 选中背景 | 用强调色浅底（浅靛青），不用系统蓝 |
| 焦点环 | 2px，外扩 2px，键盘操作时可见、鼠标操作时不显示 |

## 四、色彩系统

### 4.1 Token 分层

```
基础色板（palette）  →  语义 token  →  组件 token
   原始色值              用途命名        具体实现
```

**只允许组件使用语义 token 或组件 token，禁止直接引用基础色板色值。**

| 类别 | 语义 token 示例 |
|------|----------------|
| 表面 | `surface` `surface-raised` `surface-sunken` `surface-overlay` |
| 文字 | `text-primary` `text-secondary` `text-tertiary` `text-disabled` `text-inverse` |
| 边框 | `border-subtle` `border-default` `border-strong` `border-focus` |
| 交互 | `interactive-default` `interactive-hover` `interactive-active` `interactive-selected` |
| 状态 | `status-success` `status-warning` `status-danger` `status-info` |
| 数据 | `data-1` … `data-8`（图表配色） |

### 4.2 对比度要求

| 场景 | 最低对比度 |
|------|:---------:|
| 正文文字 | 4.5:1 |
| 大号文字（≥ 18px 或 ≥ 14px 粗体） | 3:1 |
| 图标（承载信息） | 3:1 |
| 焦点轮廓 | 3:1 |
| 边框（承载信息，如表单边界） | 3:1 |
| 高对比主题下所有上述项 | **7:1** |

**验证方式**：内置对比度检查脚本，对全部主题 × 全部 token 组合跑一遍，CI 中断言通过。

### 4.3 数据可视化配色

数据图表遵循中文用户习惯：

| 语义 | 颜色 | 说明 |
|------|------|------|
| **上涨 / 正向** | **红系** | 遵循中国市场惯例（红涨绿跌） |
| **下跌 / 负向** | **绿系** | 同上 |
| 中性 | 灰蓝系 | — |

**各主题的数据系列色**（8 色，需在相应底色上通过对比度校验）：

| 主题 | data-1 … data-8（示意方向） |
|------|---------------------------|
| 宣纸（亮） | 靛青、朱砂、竹绿、赭黄、紫檀、青灰、绛紫、苍青 |
| 夜墨（暗） | 上述色在深底上的提亮版本 |

**要求**

- 图表配色不依赖红绿单一区分（色盲友好）：除颜色外必须有形状、线型或标签区分
- 提供「色盲友好配色」开关（在「外观 → 辅助功能」中）

## 五、字体系统

### 5.1 字体槽位

界面使用**三个独立字体槽位**，可分别配置：

| 槽位 | 用途 | 默认（宣纸主题） |
|------|------|----------------|
| **标题字** | 页面标题、模块名、弹窗标题、大号数字 | 宋体系（衬线） |
| **正文字** | 正文、列表、表单、按钮 | 黑体系（无衬线），可读性优先 |
| **代码字** | 代码块、SQL 编辑器、字段名、等宽数据 | 等宽体系 |

### 5.2 默认字体栈

**标题字（宋体系）**

```
"Noto Serif CJK SC", "Source Han Serif SC", "Songti SC", "STSong",
"SimSun", "Georgia", serif
```

**正文字（黑体系）**

```
"PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei",
"Noto Sans CJK SC", "Source Han Sans SC", "Hiragino Sans GB", sans-serif
```

**代码字（等宽）**

```
"JetBrains Mono", "Cascadia Mono", "SF Mono", "Menlo",
"Consolas", "Liberation Mono", monospace
```

**原则**

| 原则 | 说明 |
|------|------|
| **不内嵌字库** | 中文完整字库动辄 10–20 MB，直接违反体积目标。一律使用系统字体栈 |
| 逐项回退 | 栈内逐个尝试，最后必须回退到一个确定可用的通用族 |
| 跨平台可用 | 三平台的默认栈都必须在纯净系统上可用 |
| 宣纸主题不强制宋体正文 | 宋体在 Windows 小字号下发虚，正文仍用黑体；想用宋体正文可切「宋体正文」预设 |

### 5.3 内置字体预设

| 预设 ID | 名称 | 标题 | 正文 | 代码 |
|---------|------|------|------|------|
| `default` | 默认 | 宋体系 | 黑体系 | 等宽体系 |
| `all-sans` | 全黑体 | 黑体系 | 黑体系 | 等宽体系 |
| `all-serif` | 全宋体 | 宋体系 | 宋体系 | 等宽体系 |
| `all-mono` | 全等宽 | 等宽体系 | 等宽体系 | 等宽体系 |
| `large-print` | 大字版 | 宋体系 | 黑体系 | 等宽体系（字号 ×1.25） |

预设只改槽位指向与尺度，不改变用户导入的字体文件。

### 5.4 自定义字体导入

**支持格式**

| 格式 | 支持 | 说明 |
|------|:----:|------|
| `.ttf` | ✅ | TrueType |
| `.otf` | ✅ | OpenType |
| `.woff2` | ✅ | 体积最小，优先推荐 |
| `.woff` | ✅ | 兼容 |
| `.ttc` / `.otc` | ⚠️ | 字体集合，需用户选择其中一个字重 |
| `.eot` | ❌ | 已过时 |
| `.fon` / `.fnt` | ❌ | 位图字体，不支持 |

**导入流程**

```
选择文件 → 校验 → 读取元信息 → 预览 → 指定槽位 → 授权确认 → 完成
```

| 步骤 | 要求 |
|------|------|
| 校验 | 检查文件头魔数；解析失败则明确报错（"文件已损坏或不是字体文件"） |
| 大小上限 | 单文件 ≤ 30 MB（可配）；超过则拒绝并说明 |
| 元信息 | 读取字体名、字重、字符集覆盖情况（是否含中文字形） |
| **中文字形检测** | 若不包含中文字形，明确警告"该字体不含中文字形，中文会回退到系统字体" |
| 预览 | 用一段包含中文、英文、数字、标点的样文实时预览 |
| 槽位 | 可指定为标题/正文/代码/多处 |
| **授权确认** | 必须勾选"我确认拥有该字体的使用授权"。我们不代管字体授权，但必须提示 |
| 存储 | 复制到数据目录 `fonts/`，记录到元数据 |
| 文件名冲突 | 用内容哈希区分，不覆盖 |

**字体管理**

| 能力 | 说明 |
|------|------|
| 列表 | 显示已导入字体、占用的磁盘空间、被哪些预设引用 |
| 重命名 | 可改显示名（不改文件） |
| 删除 | 若被当前方案引用，提示并降级到默认字体 |
| 导出 | 可导出字体方案（指向关系，不含字体文件本身） |
| 清除全部 | 一键移除全部导入字体 |

**字体方案导出格式（示意）**

```json
{
  "name": "我的方案",
  "slots": {
    "heading": { "source": "system", "stack": ["Noto Serif CJK SC", "serif"] },
    "body":    { "source": "imported", "fontId": "a1b2c3", "fallback": ["PingFang SC", "sans-serif"] },
    "code":    { "source": "system", "stack": ["JetBrains Mono", "monospace"] }
  },
  "scale": 1.0
}
```

> **注意**：导出不含字体文件本体（体积与授权问题）。导入方若没有对应字体，明确提示"此字体未安装，已回退"。

### 5.5 字体加载与性能

| 要求 | 规格 |
|------|------|
| 加载策略 | 懒加载。导入字体在首次使用时加载，不阻塞启动 |
| 冷启动影响 | **0**（未使用的字体不加载） |
| 加载失败 | 静默回退到 fallback 栈，并在设置中标记该字体"加载失败" |
| 子集化 | 若支持，对导入字体做子集化以减小内存（可配置，默认关闭） |
| 内存占用 | 单个导入字体 ≤ 40 MB 内存；超过则提示用户改用较小的字体 |
| 首字延迟 | 字体切换后首屏渲染不得出现无文字状态（先渲染 fallback，再替换） |
| 三平台一致 | 同一字体文件在三平台渲染结果可能存在细微差异，属正常 |

### 6.1 尺度系统

| 用途 | 字号 | 行高 | 字重 |
|------|:----:|:----:|:----:|
| 页面大标题 | 24px | 1.4 | 600 |
| 页面标题 | 20px | 1.45 | 600 |
| 分组标题 | 16px | 1.5 | 600 |
| 正文 | 14px | 1.7 | 400 |
| 次要正文 | 13px | 1.65 | 400 |
| 辅助文字 | 12px | 1.6 | 400 |
| 表格单元格 | 13px | 1.5 | 400 |
| 代码 | 13px | 1.6 | 400 |
| 大号数字（仪表盘） | 28px | 1.2 | 600 |

**界面密度预设**

| 密度 | 行高缩放 | 内边距缩放 | 适用 |
|------|:-------:|:---------:|------|
| 紧凑 | 0.9 | 0.75 | 数据密集场景、小屏 |

### 6.2 中文排版细节

| 项 | 处理 |
|----|------|
| **行高** | 中文正文 ≥ 1.7（中文方块字需要更大行距才透气），比英文排版标准高 |
| **字距** | 正文 0；标题可 `-0.01em`；不使用 `letter-spacing` 拉开中文 |
| **避头尾** | `line-break: strict`；禁止标点出现在行首 |
| **标点** | 使用全角中文标点（，。？！：；""''），不用半角 <br>**代码与路径中保留半角** |
| **中西文混排** | 中英文之间不强制加空格（保持原文）；但界面文案撰写时**主动加空格**（如「打开 CSV 文件」） |
| **数字** | 表格与数据列使用 `font-variant-numeric: tabular-nums`（等宽数字），避免列错位 |
| **省略** | 长文本单行溢出用 `…`（U+2026），不用三个点 |
| **换行** | 允许在连字符、斜杠后换行；路径优先在 `/` 后换行 |
| **缩进** | 段落不首行缩进（现代界面惯例）；如需缩进提供开关 |
| **引号** | 中文内容用「」与""；代码与标识符用 `"` `'` |

### 6.3 文案风格（与视觉同等重要）

> 直接表达，不用暗示。不说半句话让人猜，不玩隐喻，不把话说成一团雾。

| 要求 | ✅ 正确 | ❌ 错误 |
|------|--------|--------|
| 直说 | 「备份失败，目标磁盘不可写。请换个位置或检查权限。」 | 「备份遇到了一些小问题」 |
| 给动作 | 「点击『重新备份』再试一次。」 | 「请稍后重试」 |
| 说清后果 | 「删除后无法恢复。」 | 「你确定吗？」 |
| 不用隐喻 | 「网络访问已关闭」 | 「大门已上锁」 |
| 不用营销词 | 「本地存储」 | 「极致安全的本地存储」 |
| 不用被动含糊 | 「程序删除了 3 个文件」 | 「文件已被处理」 |
| 承认做不到 | 「无法防御键盘记录器。」 | 「全面保护你的安全」 |

**禁用词表**：极致、颠覆、赋能、生态闭环、敬请期待、小问题、稍等片刻、似乎、可能大概、据说。

## 七、动效系统

### 7.1 设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **有信息价值** | 每个动效都要回答"什么东西变了、从哪来、到哪去" |
| 2 | **只动合成属性** | 只使用 `transform` 与 `opacity`；**禁止**动 `width`/`height`/`top`/`left`/`margin` |
| 3 | **时长有上限** | 单次动效 ≤ 480ms（进度类除外） |
| 4 | **可关闭** | 提供四档强度：关 / 精简 / 标准 / 丰富；任一档都必须可用 |
| 5 | **尊重系统** | 系统「减少动效」开启时，自动降到「精简」 |
| 6 | **不阻塞操作** | 动效期间界面必须可交互（除确需防重复提交的场景） |
| 7 | **无循环** | 不存在持续播放的装饰性动画 |
| 8 | **可中断** | 用户新操作到来时，上一个动效立即平滑收尾，不排队 |

### 7.2 时长 Token

| Token | 值 | 用途 |
|-------|:--:|------|
| `--dur-instant` | 80 ms | 按压反馈、开关切换 |
| `--dur-fast` | 140 ms | 悬浮、焦点、图标变化、颜色过渡 |
| `--dur-normal` | 200 ms | 面板展开、弹出层、主题切换 |
| `--dur-slow` | 320 ms | 页面切换、抽屉、大块内容位移 |
| `--dur-deliberate` | 480 ms | 极少使用：初次进入的空态、完成长截图 |

### 7.3 缓动 Token

| Token | 曲线 | 用途 |
|-------|------|------|
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 通用（默认） |
| `--ease-enter` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | 元素进入（减速） |
| `--ease-exit` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | 元素退出（加速） |
| `--ease-emphasized` | `cubic-bezier(0.2, 0, 0, 1)` + 位移 | 强调位移动 |
| `--ease-spring` | `cubic-bezier(0.34, 1.15, 0.64, 1)` | 落位回弹，**仅在拖拽落位与卡片弹出使用** |
| `--ease-linear` | `linear` | 仅用于进度条（真实进度）与骨架屏微光 |

> **弹性曲线的使用配额**：全应用同时存在的 spring 动效不超过 2 处。滥用即廉价。

### 7.4 动效强度分级

| 档位 | 行为 |
|------|------|
| **关** | 全部动效时长归零（只保留状态变化，无过渡）。进度反馈保留 |
| **精简** | 只保留：按压反馈、焦点、必需要的位置变化；去除位移类进出场、回弹、骨架微光 |
| **标准**（默认） | 全部常规动效 |
| **丰富** | 在标准基础上增加：列表项渐进错峰入场、更明显的落位回弹、空态舒展 |

### 7.6 微交互细节清单

这些是「愉悦感」的真正来源，每一条都要实现到位：

| # | 细节 | 要求 |
|---|------|------|
| 1 | 拖拽零延迟 | 拖拽时元素紧跟指针，误差 ≤ 1 帧 |
| 2 | 视觉水位 | 悬浮、按下、选中三态必须有可分辨但不突兀的差异 |
| 3 | 焦点环 | 键盘操作的焦点环必须清晰且不影响布局（用 `outline` 而非 `border`） |
| 4 | 滚动惯性 | 滚动带有轻微惯性，松手后平滑减速（使用平台原生行为，不自行实现） |
| 5 | 边缘阴影 | 可滚动区域在滚动时顶部/底部出现渐隐遮罩（0 → 100% 透明），提示还有内容 |
| 6 | 数字等宽 | 所有会变化的数字（尺寸、进度、计时）用等宽数字，避免宽度跳动 |
| 7 | 文本选区 | 选区颜色随主题（宣纸用浅靛青底），不用浏览器默认蓝 |
| 8 | 光标形状 | 可拖拽处用抓取光标；可点击用指针；不可用用禁用光标 |
| 9 | 复制反馈 | 任何"复制"动作必须有 480ms 内的视觉确认 |
| 10 | 快捷键提示 | 鼠标悬浮在带快捷键的按钮上时，提示气泡里显示快捷键 |
| 11 | 空输入保护 | 输入框为空时提交按钮呈禁用态但**不消失**（位置稳定） |
| 12 | 长按 | 需要长按的操作给出环形进度反馈 |
| 13 | 窗口缩放 | 拖拽窗口边缘时内容自适应，不出现滚动条闪烁 |
| 14 | 手风琴展开 | 展开时使用实际内容高度，不做固定高度 |
| 15 | 错误定位 | 表单校验失败时，视口平滑滚动到第一个错误字段并聚焦 |
| 16 | 撤销提示 | 破坏性操作后显示可撤销提示（若支持撤销），停留 5 秒后自动消失 |
| 17 | 标签弹出 | 打标签时标签块从输入框位置弹出，带极轻弹性 |
| 18 | 搜索高亮 | 搜索结果关键词高亮淡入（不闪） |
| 19 | 进度真实性 | 进度条必须反映真实进度；不确定进度时用不确定态（不做假进度） |
| 20 | 静默失败禁止 | 任何失败都必须有可见反馈 —— 这是最重要的一条 |

### 7.7 禁止的动效

| ❌ 禁止 | 原因 |
|--------|------|
| 页面切换时整页翻页/3D 翻转 | 慢、晕、廉价 |
| 元素从屏幕外飞入 | 位移过大，注意力被抢 |
| 循环播放的装饰动画 | 违反「安静」原则 |
| 骨架屏与内容同时存在（不消失） | 视觉混乱 |
| 鼠标跟随光晕/拖尾 | 无信息价值，消耗 GPU |
| 按钮点击时的水波纹（除非是触屏场景） | 桌面场景不需要 |
| 完成操作后的全屏庆祝 | 打断节奏 |
| 自动播放的引导动画（用户没点就动） | 抢注意力 |
| 长于 480ms 的常规动效 | 感觉慢 |
| 用动效掩盖加载（把等待包装成"精彩过程"） | 欺骗用户 |

---

## 八、降级与无障碍

### 8.1 无障碍要求

| 项 | 要求 |
|----|------|
| 系统「减少动效」 | 自动切到「精简」，并保留进度反馈 |
| 系统「提高对比度」 | 切到高对比主题，质感关闭 |
| 屏幕阅读器 | 动效状态变化通过语义属性播报；避免因动效导致焦点丢失 |
| 色盲 | 提供色盲友好配色；图表不依赖单一颜色区分 |
| 键盘可达 | 全部交互可键盘完成；焦点顺序符合视觉顺序 |
| 缩放 | 100%–300% 下布局不破、文字不截断 |
| 对比度 | 全部主题通过 4.5:1（正文）/ 3:1（大字号与图形）；高对比主题 7:1 |

### 8.2 性能降级

| 触发条件 | 降级动作 |
|----------|---------|
| 使用电池 | 质感 → 轻/关；动效 → 精简；关闭非必要阴影 |
| 帧率 < 50 FPS 持续 3 秒 | 动效 → 精简；质感 → 轻；记录到性能日志 |
| 内存压力高 | 关闭骨架屏微光；减少合成层 |
| 低端设备（自动检测） | 默认使用「精简」动效 + 「轻」质感 |
| 远程桌面/虚拟机 | 检测到软件渲染时，动效 → 关，质感 → 关 |

> **降级必须是自动的、可感知的、可撤销的**。降级后在设置中显示"因设备性能，动效已调整为精简"，用户可手动改回。

## 九、性能红线

| 指标 | 要求 |
|------|------|
| 动效期间帧率 | ≥ 55 FPS（万行表格滚动场景 ≥ 55 FPS） |
| 主题切换耗时 | ≤ 200 ms，无白屏闪烁 |
| 纸纹层空闲 CPU 增量 | **0** |
| 纸纹层滚动帧率影响 | ≤ 1 FPS |
| 纸纹 GPU 内存 | ≤ 4 MB |
| 字体加载对冷启动影响 | **0 ms**（懒加载） |
| 字体文件内存占用 | ≤ 40 MB / 字体 |
| 单次动效时长 | ≤ 480 ms（进度类除外） |
| 动效触发的布局重排 | **0 次**（只动 transform/opacity） |
| 长时间运行唯一动画数 | 空闲时 **0**（不允许循环动画常驻） |

**门禁**：性能回归超过 10% 阻止合并（与 `docs/14` 一致）。视觉资源新增导致包体积增长 > 2% 需说明理由。

## 十一、实现顺序

视觉系统必须在第一批业务组件之前落地，顺序如下：

```
① token 层  →  ② 组件（先用 token）  →  ③ 宣纸主题打磨
→  ④ 高对比主题（验证 token 完整性）  →  ⑤ 暗色主题
→  ⑥ 纹理层
```

理由：

- **token 必须先于组件**：组件一旦写死颜色，改主题就要逐个改组件，是最常见返工来源；
- **第二个主题要早做**：用一个风格差异大的主题（如高对比）交叉验证，才能确认 token 抽象真的中立，避免把宣纸的特有属性硬编码进组件；
- **纹理放最后**：纹理最容易影响性能，放到最后打磨，避免早期就被性能问题拖住。
