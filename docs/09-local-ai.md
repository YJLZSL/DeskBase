# 09 · 本地 AI 架构与隐私保护策略

> AI 是助手，不是数据泄露通道。**默认本地运行不是限制，是设计。**

---

## 一、立场与边界

### 1.1 三条铁律

| 铁律 | 含义 |
|------|------|
| **默认本地** | 全部 AI 能力默认由本机模型完成，断网可用 |
| **数据不出境** | 模型、向量索引、对话记录、临时数据全部本地存储；S2/S3 数据永不外发 |
| **外发需逐次授权** | 若用户主动启用外部服务，每次调用需确认，并提供脱敏预览 |

### 1.2 AI 的定位

| 是 | 不是 |
|----|------|
| 帮你把乱的内容整理成结构 | 替你决定数据怎么改 |
| 帮你查你想查的东西（自然语言 → SQL） | 自动执行生成的 SQL |
| 帮你读懂一堆文字 | 把你的文字传到别人服务器去读 |
| 在你明确指定的范围内工作 | 悄悄扫描整个数据目录 |

### 1.3 明确的能力边界

| 不做 | 原因 |
|------|------|
| 默认调用云端 AI API | 隐私承诺 |
| 用户数据的云端向量化 | 隐私承诺 |
| 基于用户数据的模型训练（上传） | 隐私承诺 |
| AI 自动执行写操作 | 安全风险不可接受 |
| AI 自主访问未授权数据 | 权限边界 |
| 隐藏的 AI 功能（用户不知情时运行） | 透明性要求 |

## 二、整体架构

```
┌────────────────────────────────────────────────────────────┐
│                      应用层（AI 功能入口）                   │
│  自然语言查询 · 摘要 · 分类 · 翻译 · OCR增强 · 转写 · 语义搜索 │
└────────────────────────────────────────────────────────────┘
                            ↓
┌────────────────────────────────────────────────────────────┐
│                   AI 编排层（Orchestrator）                  │
│  · 提示词模板管理    · 上下文组装（受权限约束）               │
│  · 数据分类过滤（S2/S3 拦截）                                │
│  · 结果后处理        · 隐私闸门（是否允许外发）               │
└────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────┬─────────────────────────────────────┐
│   本地推理后端        │      外部服务适配器（默认禁用）        │
│   （默认路径）        │      · 仅用户显式配置后启用            │
│                      │      · 逐次确认 + 脱敏预览            │
│  · 可插拔后端         │      · 全量审计                       │
│  · 模型管理与校验      │                                       │
└──────────────────────┴─────────────────────────────────────┘
                            ↓
┌────────────────────────────────────────────────────────────┐
│                        数据层                                │
│  模型文件 · 向量索引 · 对话记录 · 临时推理数据（全部本地）      │
└────────────────────────────────────────────────────────────┘
```

### 2.1 隐私闸门（Privacy Gate）

**所有** AI 请求都必须经过隐私闸门。它是一个强制中间层，不可绕过。

```
请求 →
  ① 数据分类检查：请求中是否含 S2 / S3 数据？
       ├─ 含 → 若是本地推理：放行
       │      若是外部服务：拒绝，并告知用户原因
       └─ 不含 → 继续
  ② 后端检查：当前后端是本地还是外部？
       ├─ 本地 → 直接放行
       └─ 外部 → 检查用户是否已开启外部服务
                  ├─ 未开启 → 拒绝
                  └─ 已开启 → 进入 ③
  ③ 脱敏处理：按用户配置的规则脱敏
  ④ 授权检查：本次调用是否已获授权？
       ├─ 未授权 → 弹出脱敏预览，等待用户确认
       └─ 已授权（用户选择了"本次会话内允许"） → 放行
  ⑤ 发出请求 → 记录审计日志
```

### 2.2 架构原则

| 原则 | 说明 |
|------|------|
| **可插拔推理后端** | 抽象出统一接口，允许替换不同的本地推理引擎 |
| **后端可完全移除** | 不装本地模型时，AI 功能整体不可用但不影响其他功能 |
| **不可绕过闸门** | 隐私检查在架构上强制，不依赖调用方自觉 |
| **失败安全** | 闸门异常时默认拒绝，不默认放行 |
| **可审计** | 每次 AI 调用（本地与外部）都记录 |

## 三、本地推理

### 3.1 本地模型管理

| 能力 | 说明 |
|------|------|
| 模型来源 | 官方校验的模型清单；支持从本地文件导入自定义模型 |
| 下载 | 需用户显式确认；显示来源、体积、哈希值；下载后校验哈希 |
| 校验 | SHA-256 校验，不匹配则拒绝加载 |
| 切换 | 可按任务类型配置不同模型（如摘要用小模型、复杂推理用大模型） |
| 卸载 | 一键删除模型文件 |
| 存储 | 模型文件存于用户指定目录（默认数据目录外的独立位置，便于单独管理） |
| 占用提示 | 显示每个模型的磁盘占用、内存/显存需求、推理速度 |

### 3.2 推理后端候选（不绑定）

| 后端类型 | 特点 | 适用 |
|---------|------|------|
| 轻量 CPU 推理引擎 | 无需 GPU，体积小，速度中等 | 大多数用户 |
| GPU 加速推理引擎 | 快，但需 GPU 与较大的运行时 | 有独显的用户 |
| 系统内置推理框架 | 利用 OS 提供的 AI 能力 | 平台支持时 |
| 外部本地服务（如用户自建的 Ollama / LM Studio） | 用户已有环境时复用 | 高级用户 |

> **不绑定具体引擎**：AI 编排层通过统一接口调用，具体后端可在 ADR 中另行决策。

### 3.3 任务与模型匹配

| 任务 | 建议模型规模 | 说明 |
|------|-------------|------|
| 摘要 / 分类 / 翻译 | 小（1–3B 参数） | 快，CPU 也能跑 |
| 对话 / 报表解读 | 中（7–8B） | 平衡质量与速度 |
| NL2SQL / 复杂推理 | 中到大（7–14B） | 需要更强的结构化输出能力 |
| OCR / 转写 | 专用模型 | 非通用 LLM |

**降级策略**：若目标模型未安装，自动降级到已安装的最小可用模型，并提示用户。

### 3.4 资源控制

| 控制项 | 默认 | 说明 |
|-------|------|------|
| 是否使用 GPU | 可用则用 | 用户可关闭 |
| 内存上限 | 系统内存的 25% | 超出则拒绝推理并提示 |
| 显存上限 | 自动检测 | |
| 并发推理数 | 1 | 避免资源争抢 |
| 推理超时 | 120 秒 | 可配 |
| 空闲卸载 | 5 分钟无使用则释放模型内存 | 释放后下次使用需重新加载 |
| 电池模式 | 使用电池时降级到小模型或不使用 GPU | 省电 |

> **与「安静」原则的一致性**：AI 模型**只在被调用时加载**，空闲时完全释放。不能出现"AI 服务常驻后台吃内存"的情况。

## 四、AI 能力设计

### 4.1 自然语言查询（NL2SQL）

| 环节 | 设计 |
|------|------|
| 输入 | 中文自然语言问题 |
| 上下文 | 当前库的**表名、字段名、字段注释、类型**（不含数据内容） |
| 生成 | 本地模型生成 SQL |
| **展示** | **必须完整显示生成的 SQL**，并给出简短解释（"我理解你想查…"） |
| 确认 | 用户点「执行」才运行；可先「仅预览前 20 行」 |
| 写操作 | 若生成的是写操作（INSERT/UPDATE/DELETE/DDL），显示影响估计并要求输入确认词 |
| 修正 | 用户可手动编辑 SQL 后再执行 |
| 失败 | 生成不了就明确说"我没理解你的问题"，**绝不允许**输出看似合理但错误的 SQL 后静默执行 |
| 学习 | 可选：记录用户修正（默认关闭，且仅本地） |

**示例交互**

```
┌─────────────────────────────────────────────────────────┐
│ 问：上个月哪些客户没付尾款                                │
├─────────────────────────────────────────────────────────┤
│ 我理解你想查：上个月有订单但收款状态不是"已结清"的客户      │
│                                                         │
│ 生成的 SQL：                                             │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ SELECT DISTINCT c.name, o.amount, o.order_date      │ │
│ │ FROM 客户 c                                          │ │
│ │   JOIN 订单 o ON o.customer_id = c.id                │ │
│ │   LEFT JOIN 收款 p ON p.order_id = o.id              │ │
│ │ WHERE o.order_date >= '2026-08-01'                   │ │
│ │   AND o.order_date <  '2026-09-01'                   │ │
│ │   AND (p.status IS NULL OR p.status <> '已结清')      │ │
│ │ ORDER BY o.order_date DESC;                          │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ 这是只读查询，不会修改数据。                              │
│                                                         │
│ [ 执行 ]  [ 仅预览 20 行 ]  [ 编辑 SQL ]  [ 取消 ]        │
└─────────────────────────────────────────────────────────┘
```

### 4.2 数据摘要

| 能力 | 说明 |
|------|------|
| 对象 | 笔记、文档、选区、查询结果、整张表 |
| 参数 | 长度（一句话 / 短 / 中 / 长）、风格（客观 / 通俗 / 要点） |
| 输出 | 摘要文本，可插入或另存 |
| 长文本处理 | 分段摘要再汇总（Map-Reduce 式），全部本地完成 |
| 不修改原文 | 摘要只作为新内容呈现，不覆盖原数据 |

### 4.3 智能分类与打标签

| 能力 | 说明 |
|------|------|
| 场景 | 大量笔记/记录自动归类 |
| 方式 | 用户给定候选标签集，模型为每条内容选择 |
| 呈现 | 显示建议，**用户确认后**才应用；可批量接受 |
| 可撤销 | 分类操作产生一条可整体撤销的记录 |
| 学习 | 用户的修正可用于本地提示优化（可选，默认关） |

### 4.4 翻译

| 能力 | 说明 |
|------|------|
| 范围 | 选中文本、整篇笔记、OCR 结果、表格字段 |
| 语言 | 中英日韩等（取决于本地模型能力） |
| 术语表 | 用户可维护术语对照表，翻译时自动应用 |
| 模式 | 替换原文 / 并列显示 / 新建译文笔记（**默认并列显示**，不破坏原文） |

### 4.5 OCR（AI 增强）

| 能力 | 说明 |
|------|------|
| 与基础 OCR 的分工 | 基础 OCR（办公工具模块）处理常规印刷体；AI 增强处理手写、复杂版式、表格结构 |
| 表格还原 | 识别表格结构，输出为可写入表格模块的二维数据 |
| 版面分析 | 识别标题、段落、列表、图片位置 |
| 完全本地 | 识别模型本地运行，图片不出网 |

### 4.6 语音转写

| 能力 | 说明 |
|------|------|
| 输入 | 麦克风录音 / 音频文件 |
| 输出 | 文本 + 时间轴（可选说话人分离） |
| 本地 | 转写模型本地运行；音频文件不出网 |
| 权限 | 麦克风权限**仅在用户点击录音时申请**，不后台监听 |
| 存储 | 音频与转写结果存在本地；可单独清除 |

### 4.7 语义搜索

| 能力 | 说明 |
|------|------|
| 原理 | 本地嵌入模型生成向量，本地向量索引检索 |
| 增强 | 与关键词搜索混合（混合检索），提升召回 |
| 范围 | 用户显式选择的库/笔记范围；**不默认全库扫描** |
| 索引 | 后台增量构建，可暂停、可重建、可清除 |
| 资源 | 索引构建限速，不影响前台操作 |
| 引用 | 搜索结果显示明确的来源，便于核实 |

### 4.8 报表解读

| 能力 | 说明 |
|------|------|
| 输入 | 查询结果或表格数据（结构化） |
| 输出 | 通俗语言描述趋势、异常、极值 |
| 呈现 | 与数据同屏显示，可折叠 |
| 免责 | 明确标注"由本地模型生成，仅供参考" |

## 五、数据存储与生命周期

| 数据 | 位置 | 加密 | 生命周期 |
|------|------|------|---------|
| 模型文件 | 用户指定目录 | 否（公开模型） | 用户手动删除 |
| 向量索引 | 数据目录 `vectors/` | 跟随全局 | 可重建，可清除 |
| 对话记录 | 数据目录 `ai/conversations/` | 跟随全局 | 默认保留 90 天，可清空 |
| 提示词模板 | 数据目录 `ai/prompts/` | 否 | 随程序更新 |
| 临时推理数据 | 内存 + 临时目录 | 跟随全局 | 推理结束即清除 |
| 推理日志 | 数据目录 `logs/ai/` | 跟随全局 | 默认仅记录元数据（耗时、模型、是否外发），**不记录内容** |
| 用户修正记录 | 数据目录 `ai/feedback/` | 跟随全局 | 默认关闭，开启后保留 30 天 |

### 5.1 一键清除

`设置 → AI → 清除 AI 数据` 提供：

| 选项 | 清除内容 |
|------|---------|
| 清除对话记录 | 全部对话历史 |
| 清除向量索引 | 索引数据（下次使用时重建） |
| 清除修正记录 | 用户反馈数据 |
| 清除全部 AI 数据 | 以上全部（不含模型文件） |
| 删除模型文件 | 一并删除已下载的模型 |

**以上操作均二次确认。**

## 六、外部 AI 服务的接入（默认完全禁用）

### 6.1 启用流程

```
用户进入 设置 → AI → 外部 AI 服务
        ↓
阅读说明（明确告知：数据将离开本机）
        ↓
勾选：「我理解启用后，我选择发送的内容将离开本机」  ← 必须手动勾选
        ↓
填写服务地址、认证方式（凭证存入系统密钥链）
        ↓
配置脱敏规则
        ↓
选择允许发送的数据分类（默认仅 S0；S1 需单独授权；S2/S3 永不）
        ↓
测试连接（发送一条不含任何用户数据的探测请求）
        ↓
启用
```

### 6.2 逐次确认

**默认首次调用必须确认，且提供"本次会话内允许"与"仅此一次"选项。**

```
┌─────────────────────────────────────────────────────────────┐
│  ⚠ 即将把内容发送到外部服务                                   │
├─────────────────────────────────────────────────────────────┤
│  目标：https://ai.example.com/v1/chat                        │
│  用途：摘要生成                                              │
│  数据分类：S1（个人内容）                                     │
│                                                             │
│  实际将发送的内容（已按你的规则脱敏）：                        │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 请总结以下内容：                                        │ │
│  │ 客户 [姓名已隐藏] 于 [电话已隐藏] 签约，金额 8,000 元…  │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
│  ☐ 本次会话内不再询问                                        │
│                                                             │
│  [ 发送 ]   [ 取消 ]   [ 编辑脱敏规则 ]                       │
└─────────────────────────────────────────────────────────────┘
```

### 6.3 脱敏规则

| 类型 | 默认规则 | 可自定义 |
|------|---------|---------|
| 手机号 | 替换为 `[电话已隐藏]` | ✅ |
| 身份证号 | 替换为 `[证件号已隐藏]` | ✅ |
| 银行卡号 | 替换为 `[卡号已隐藏]` | ✅ |
| 邮箱 | 替换为 `[邮箱已隐藏]` | ✅ |
| 姓名（中文） | **默认不脱敏**（会严重损害可用性） | 用户可开启 |
| 自定义正则 | 无 | 用户可添加 |
| 自定义词表 | 无 | 用户可添加 |

> 姓名默认不脱敏是一个刻意的取舍：全面脱敏会让 AI 输出完全不可用。我们选择**如实展示将要发送的内容**，让用户自己决定，而不是给用户虚假的安全感。

### 6.4 外发审计

| 记录项 | 内容 |
|-------|------|
| 时间 | 精确到秒 |
| 目标 | 服务地址 |
| 用途 | 哪个功能发起 |
| 数据分类 | S0 / S1 |
| 内容大小 | 字符数 |
| 是否脱敏 | 是 / 否 |
| 用户授权方式 | 逐次确认 / 会话内允许 |
| 结果 | 成功 / 失败 |

**不记录内容本身**（否则审计日志自己就成了泄露源）。

## 七、AI 隐私面板

在 AI 模块内提供一个常驻可访问的透明度面板：

```
AI 隐私面板
─────────────────────────────────────────────────────────────
运行模式：● 本地运算（默认）    ○ 允许外部服务

本地模型
  · 当前模型          qwen2.5-3b-instruct（本地）
  · 模型来源          官方校验清单
  · 磁盘占用          1.8 GB
  · 状态              已加载（空闲 5 分钟后自动释放）

数据流向
  · 你的数据是否离开本机  否
  · 本机推理次数（今日）  42 次
  · 外部调用次数（今日）  0 次

存储
  · 对话记录          18 条，1.2 MB    [ 查看 ] [ 清空 ]
  · 向量索引          34 MB            [ 重建 ] [ 清除 ]
  · 临时数据          推理结束即清除

─────────────────────────────────────────────────────────────
[ 一键完全关闭 AI ]        [ 查看 AI 调用审计日志 ]
─────────────────────────────────────────────────────────────
```

**「一键完全关闭 AI」是最显眼的开关**，点击后：所有 AI 入口从界面隐藏、模型不加载、向量索引不构建、不产生任何 AI 相关网络请求。

## 八、AI 三级设置汇总

| 分组 | 设置项 | 默认值 |
|------|-------|-------|
| **总开关** | 启用 AI 功能 | 开启（首次使用时询问） |
| | 一键完全关闭 | — |
| **本地模型** | 默认模型 | 摘要/分类用小模型 |
| | NL2SQL 模型 | 中等模型 |
| | 模型存储目录 | 独立目录 |
| | 使用 GPU | 可用则用 |
| | 内存上限 | 系统内存的 25% |
| | 空闲释放时间 | 5 分钟 |
| | 电池模式降级 | 开启 |
| **外部服务** | 启用外部 AI 服务 | **关闭** |
| | 服务地址 | 空 |
| | 认证方式 | 空（凭证存系统密钥链） |
| | 每次调用需确认 | **开启** |
| | 允许发送的数据分类 | 仅 S0 |
| | 脱敏规则 | 手机号/证件/卡号/邮箱 |
| | 调用审计日志 | **开启** |
| **存储与隐私** | 保留对话记录 | 90 天 |
| | 记录用户修正 | **关闭** |
| | 记录推理内容日志 | **关闭**（仅记元数据） |
| | 向量索引自动构建 | 开启（限速） |
| **能力开关** | 自然语言查询 | 开启 |
| | 摘要 / 分类 / 翻译 | 开启 |
| | 语义搜索 | 开启 |
| | 语音转写 | 开启（麦克风按需授权） |
| | OCR 增强 | 开启 |
| **显示** | 显示「由 AI 生成」标注 | **开启（不可关）** |
| | 显示生成耗时 | 开启 |

## 九、AI 输出安全

| 风险 | 对策 |
|------|------|
| AI 生成的 SQL 危险 | 必须人工确认；写操作显示影响估计；绝不允许自动执行 |
| AI 生成内容含幻觉 | 明确标注"由 AI 生成，请核对"；涉及数据的结论需可追溯到源数据 |
| AI 生成的代码被自动执行 | **不允许**。任何 AI 生成的可执行内容都必须人工确认 |
| AI 建议的批量操作 | 显示影响范围，需确认，且可撤销 |
| 提示词注入（内容中含恶意指令） | 用户数据作为**数据**传入，不作为指令；敏感操作仍走人工确认 |
| AI 输出中的链接 | 不自动打开；点击前显示完整 URL |
| AI 输出中的 Markdown 渲染 | 走同一套白名单净化 |

## 十、性能与资源目标

| 指标 | 目标 |
|------|------|
| 小模型加载（首次） | ≤ 3 秒 |
| 摘要生成（500 字输入，小模型，CPU） | ≤ 5 秒 |
| NL2SQL 生成（中等模型，CPU） | ≤ 15 秒 |
| NL2SQL 生成（中等模型，GPU） | ≤ 3 秒 |
| 语义搜索返回（10 万条记录索引） | ≤ 500 ms |
| 向量索引构建（10 万条） | ≤ 30 分钟（限速、可暂停，不影响前台） |
| 空闲 AI 内存占用 | **0**（模型释放后完全退出） |
| AI 相关后台进程（未使用时） | **0** |

> 最后两条是「安静」原则在 AI 上的体现：**不用 AI 时，它不该占任何资源。**

## 十一、AI 红线清单

| # | 红线 |
|---|------|
| 1 | 不默认调用任何外部 AI API |
| 2 | 不把 S2 / S3 数据发送到本机之外 |
| 3 | 不自动执行 AI 生成的 SQL 或任何可执行内容 |
| 4 | 不在用户不知情时运行 AI |
| 5 | 不把用户数据用于任何形式的模型训练或上传 |
| 6 | 不在对话记录或日志中记录 S2 / S3 数据 |
| 7 | 不在未展示"将发送内容"的情况下外发数据 |
| 8 | 不让 AI 越权访问用户未指定的数据范围 |
| 9 | 不隐藏 AI 的网络行为（全部记入审计日志） |
| 10 | 不使用需要上传数据的"增强"功能作为默认选项 |
