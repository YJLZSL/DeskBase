# 10 · 原生桌面端与手机远程端

> 桌面端是**数据主端**，手机端是**安全遥控器**。
> 这个分工不能颠倒——颠倒就意味着数据要么上云，要么在手机上又存一份。

---

## 一、总体架构

```
┌────────────────────────────────────────────────────────────────┐
│                  桌面端（数据主端 · Data Owner）                 │
│                                                                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐  │
│  │  本地存储     │  │  本地引擎     │  │  远程服务（可选）      │  │
│  │  主数据库     │  │  办公/数据库  │  │  · 默认关闭           │  │
│  │  附件/索引    │  │  备份/AI      │  │  · 局域网直连         │  │
│  │  密钥        │  │              │  │  · 自托管中继         │  │
│  └──────────────┘  └──────────────┘  └──────────────────────┘  │
└────────────────────────────────────────────────────────────────┘
                              ▲
                              │ 端到端加密通道
                              │ （配对后协商密钥，中继不可读）
                              ▼
┌────────────────────────────────────────────────────────────────┐
│                   手机端（安全远程端 · Thin Client）             │
│                                                                │
│  · 不存储主数据（仅本地缓存最小必要数据，可一键清除）              │
│  · 持有设备私钥，用于通道认证                                    │
│  · 权限受桌面端授权约束                                         │
│  · 按需连接，不后台常驻                                         │
└────────────────────────────────────────────────────────────────┘
```

### 1.1 核心分工

| 维度 | 桌面端 | 手机端 |
|------|-------|-------|
| 数据所有权 | **唯一主副本** | 无主副本（仅临时缓存） |
| 数据变更 | 全部可变更 | 只有被授权的操作 |
| 备份 | 由桌面端负责 | 不参与 |
| AI 推理 | 桌面端执行 | 只发请求（走加密通道） |
| 生命周期 | 常开或按需启动 | 打开即用，用完即走 |
| 系统集成 | 文件系统、剪贴板、截图、通知 | 通知、相机（可选）、扫码 |

### 1.2 为什么不是"两边都有数据 + 云端同步"

因为那会：
- 引入云端服务（违反本地优先）
- 引入冲突合并复杂度
- 引入"哪个是最新版"的困惑
- 引入数据在手机丢失后被读取的风险

**选择单主端 + 远程访问**，代价是手机离线时不可用，收益是数据只有一个真相来源。

## 二、桌面端设计

### 2.1 原生体验要求

| 要求 | 具体标准 |
|------|---------|
| 冷启动 | ≤ 1.2 秒到可交互 |
| 热启动 | ≤ 400 ms |
| 窗口响应 | 拖拽、缩放、最大化无卡顿（稳定 60 FPS） |
| 系统集成 | 原生菜单栏/托盘、系统通知、系统剪贴板、文件关联（可选）、拖放文件 |
| 高 DPI | 完美支持 100%–300% 缩放，无模糊、无错位 |
| 多显示器 | 窗口可跨屏、截图支持全屏或指定屏、贴图支持跨屏 |
| 深色模式 | 跟随系统，切换即时生效 |
| 无障碍 | 屏幕阅读器、纯键盘操作、焦点可见、对比度达标 |
| 输入法 | 中文输入法下无候选框错位、无重复输入 |
| 平台惯用法 | 各平台的快捷键、菜单结构、窗口行为符合本地习惯 |

### 2.2 进程结构

```
主进程（最小权限，无 UI）
  · 数据访问仲裁
  · 文件系统操作
  · 密钥管理
  · 进程生命周期管理
      │
      ├── UI 进程（渲染界面，无文件系统直访权限）
      ├── 数据库进程（可选，独立运行查询，崩溃不影响 UI）
      ├── 备份进程（执行备份时启动，完成后退出）
      ├── AI 推理进程（按需启动，空闲释放）
      ├── 远程服务进程（仅开启远程访问时启动）
      └── 插件进程（每个插件独立进程，按权限沙箱）
```

**原则**：**不需要的进程不启动；用完即退出。**

### 2.3 托盘行为

| 行为 | 设计 |
|------|------|
| 默认是否有托盘图标 | 有（窗口关闭时可选择隐藏到托盘或退出） |
| 关闭窗口的行为 | 首次询问"最小化到托盘 / 退出程序"，可记住选择 |
| 托盘菜单 | 打开主窗口、快速笔记、快速待办、截图、剪贴板历史、备份状态、退出 |
| 托盘图标提示 | 显示备份状态（正常/失败）、远程连接数（有连接时） |
| 退出时 | 强制 checkpoint、关闭连接、清理临时文件、**不留后台进程** |

> **注意**：「最小化到托盘」是一种资源常驻。因此首次必须询问，且用户选择后可在设置中更改。如果用户选择"退出"，则托盘图标也一并消失，不留后台。

## 三、远程访问通道设计

### 3.1 三种连接模式

| 模式 | 说明 | 默认 | 适用 |
|------|------|------|------|
| **局域网直连** | 设备与桌面端在同一局域网，直接建立加密连接 | 可选（需用户开启） | 家庭、办公室 |
| **自托管中继** | 用户自己部署的中继服务器转发加密流量 | 可选（需配置） | 跨网络、无公网 IP |
| **完全关闭** | 不建立任何监听、不做任何发现 | **默认** | 大多数用户 |

**明确不支持**：官方托管的公共中继服务。这会让"数据不经过我们"的承诺失效。

### 3.2 局域网发现与直连

| 环节 | 设计 |
|------|------|
| 发现 | mDNS / 局域网广播（仅在用户开启远程访问时启用） |
| 连接 | 直接 TCP/TLS 连接到桌面端监听端口 |
| 端口 | 默认随机高位端口（避免冲突与扫描）；可在设置中固定 |
| 绑定地址 | 默认仅绑定局域网接口，不绑定公网接口 |
| 认证 | 配对时生成设备密钥对；连接时双向认证 |
| 加密 | TLS 1.3 + 应用层端到端加密（双层） |

### 3.3 自托管中继

| 环节 | 设计 |
|------|------|
| 中继职责 | **只转发加密数据包，不知道内容** |
| 部署 | 提供自托管中继的部署说明与容器镜像（在文档中提供，非本仓库强制） |
| 加密 | 端到端加密在桌面端与手机端之间协商；中继仅有密文 |
| 可验证性 | 提供"中继不可读"的说明与验证方法（如：中继日志中不含明文、密钥不在中继侧） |
| 配置 | 用户填写中继地址；提供连接测试；显示是否连通、延迟多少 |

### 3.4 端到端加密

```
配对阶段（一次性，需用户在场）：
  1. 桌面端显示二维码（含：桌面端公钥指纹 + 配对码 + 局域网地址）
  2. 手机端扫码，得到桌面端公钥
  3. 手机端生成自己的密钥对，把公钥指纹回传（或由用户在桌面端确认指纹）
  4. 双方在通道内完成密钥协商（如 ECDH），得到会话密钥
  5. 用户需在桌面端确认设备指纹（防中间人）
  6. 生成长期设备标识，写入双方设备列表

通信阶段：
  使用协商出的会话密钥加密全部应用层数据
  · 密钥轮换：每 N 次请求或每 N 分钟轮换
  · 前向保密：使用临时密钥（如 X25519 ECDHE）
  · 完整性：AEAD 保证数据完整性与认证
```

| 设计点 | 要求 |
|-------|------|
| 身份验证 | **必须由用户确认设备指纹**（不能只有扫码，扫码可被中间人替换） |
| 前向保密 | 每次会话使用临时密钥 |
| 重放保护 | 请求带单调递增序号 + 时间戳 |
| 密钥存储 | 手机端私钥存于系统安全存储（Keychain / Keystore） |
| 吊销 | 桌面端可随时吊销某设备；吊销后其密钥失效 |

### 3.5 配对流程（用户体验）

```
桌面端                     手机端
────────────────────────────────────────────
设置 → 远程访问
  [ 开启远程访问 ]
  ↓
选择模式：● 仅局域网  ○ 局域网+自托管中继
  ↓
[ 添加设备 ]
  ↓
显示二维码
（含配对码 + 指纹）
        ────────── 扫码 ──────────→  打开 DeskBase App
                                      点击「连接桌面端」
                                         ↓
                                      扫描二维码
                                         ↓
                                    显示桌面端指纹：
                                    A1:B2:C3:D4:...
                                         ↓
                                    「请确认这是你电脑上
                                      显示的指纹」
                                         ↓
  ←───── 显示待确认设备 ────────
  「手机 名称: 小林的 iPad
    指纹: F5:E6:D7:C8:...
    [ 确认配对 ]  [ 拒绝 ]」
         ↓
    用户点确认
         ↓
  ←───── 建立加密通道 ─────→  配对成功
         ↓
  配置该设备权限              进入主界面
  （默认只读）
```

### 3.6 连接生命周期

| 阶段 | 行为 |
|------|------|
| 手机端打开 | 检查已配对设备，尝试连接最近使用的桌面端 |
| 连接建立 | 认证 → 协商密钥 → 拉取权限清单 → 进入可用界面 |
| 空闲 | 默认 5 分钟无操作自动断开（省电） |
| 断开 | 清除内存中的会话密钥与临时数据 |
| 重连 | 用户操作时自动重连，显示连接状态 |
| 桌面端不可达 | 明确提示原因（未开启远程 / 不在同一网络 / 已吊销） |

## 四、权限模型

详见 [08 · 隐私、安全、加密、权限与审计](08-privacy-security.md#52-远程权限多设备)。此处补充**交互**设计。

### 4.1 权限的五维结构

```
数据库 → 表 → 字段 → 操作 → 时段
```

### 4.2 权限编辑器（桌面端）

| 要求 | 说明 |
|------|------|
| 可视化 | 树形结构，逐级勾选 |
| 预设 | 提供「只读浏览」「数据录入」「完全管理」三个预设，可在此基础上微调 |
| 冲突提示 | 若授予"改"但未授予"读"，提示逻辑矛盾并建议修正 |
| 字段隐藏 | 可对某设备隐藏特定字段（如身份证号） |
| 预览 | 提供「以该设备视角预览」，让用户看到手机上实际能看到什么 |
| 批量 | 可为多台设备批量设置权限 |

### 4.3 权限生效方式

| 要求 | 说明 |
|------|------|
| **服务端强制** | 权限检查在桌面端执行，**不依赖手机端自觉** |
| 逐次校验 | 每个请求都校验权限，不信任会话内的缓存授权 |
| 越权拒绝 | 越权请求被拒绝并记入审计日志，且通知桌面端用户（可选） |
| 权限变更即时生效 | 修改权限后，现有连接立即受新权限约束 |

## 五、手机端设计

### 5.1 定位

| 是 | 不是 |
|----|------|
| 桌面端的安全遥控器 | 独立的数据应用 |
| 查看、录入、审批、查询 | 完整的数据管理 |
| 按需连接的工具 | 常驻后台的服务 |
| 只持有最小必要缓存 | 持有完整数据副本 |

### 5.2 功能范围

| 功能 | 说明 | 优先级 |
|------|------|-------|
| 查看数据 | 浏览授权的表/笔记，支持筛选排序 | 进阶 |
| 录入数据 | 表单录入，离线时暂存本地队列（重连后提交） | 进阶 |
| 审批 | 对待办/申请的通过/驳回 | 进阶 |
| 查询 | 简单条件查询（复杂查询在桌面端做） | 进阶 |
| 接收通知 | 备份完成/失败、任务完成、权限变更 | 进阶 |
| 快速记录 | 拍照/录音/文字快速记录，同步到桌面端 | 进阶 |
| 扫码连接 | 配对时扫码 | 进阶 |
| 设置 | 查看连接状态、清除本地缓存、断开连接 | 进阶 |

### 5.3 省电与省流量

| 策略 | 设计 |
|------|------|
| 按需连接 | 打开 App 才连接，切到后台 N 分钟后断开 |
| 无后台常驻 | **不注册后台服务、不做后台轮询** |
| 通知机制 | 不使用实时长连接；需要通知时由桌面端在用户下次连接时同步（或使用系统推送需用户显式开启，并说明代价） |
| 数据压缩 | 传输使用压缩；图片按需请求缩略图，点击才取原图 |
| 缓存策略 | 只缓存用户看过的内容；有容量上限；可一键清除 |
| 增量拉取 | 只拉取变更部分，不全量刷新 |
| 前台限制 | 前台时也限制并发请求数 |

> **关于推送通知的诚实说明**：真正的实时推送需要常驻连接或第三方推送服务（会引入数据外发）。因此默认使用"下次连接时同步"，若用户需要实时通知，需显式开启并接受"通知需经过推送服务（仅传最小通知标识，不含内容）"。

### 5.4 离线行为

| 场景 | 行为 |
|------|------|
| 无网络/不可达 | 显示"未连接"，可浏览本地缓存（若有），不可修改 |
| 录入时断线 | 内容暂存本地队列，明确提示"将在连接后提交" |
| 重连后 | 自动提交队列，显示提交结果（成功/冲突/失败） |
| 冲突 | 若记录已被桌面端修改，提示用户选择保留哪个版本 |

### 5.5 本地存储（手机端）

| 数据 | 存储 | 加密 | 清除 |
|------|------|------|------|
| 设备私钥 | 系统安全存储 | 系统级 | 解绑时删除 |
| 会话密钥 | 内存 | — | 断开即清除 |
| 页面缓存 | 应用私有目录 | 跟随系统加密 | 可一键清除 |
| 待提交队列 | 应用私有目录 | 加密 | 提交成功后删除 |
| 桌面端地址与指纹 | 应用私有目录 | 否 | 解绑时删除 |

**手机端绝不存储**：完整数据库、附件原文件、密钥材料（除自身设备私钥）。

## 六、同步语义（在远程访问框架下）

由于采用"单主端"架构，严格意义上不存在"双向同步"，而是**远程读写**：

| 操作 | 语义 |
|------|------|
| 手机读 | 实时从桌面端读取（不读缓存副本用于写决策） |
| 手机写 | 提交到桌面端，由桌面端的事务保证一致性 |
| 离线写 | 暂存队列，重连后提交；提交时校验数据版本，冲突则提示 |
| 冲突解决 | **不自动合并**。提示用户选择，避免静默覆盖 |

### 6.1 冲突检测

| 机制 | 说明 |
|------|------|
| 版本号 | 每条记录带版本号；提交时带期望版本 |
| 乐观锁 | 版本不匹配则拒绝提交，返回当前版本 |
| 用户决策 | 显示"你改的"与"桌面端现在的"对比，让用户选择 |
| 不静默覆盖 | **任何情况下都不静默覆盖用户数据** |

## 七、用户可选项（可选的同步能力）

若未来提供**多桌面设备同步**（如公司与家里两台电脑），必须遵循：

| 要求 | 说明 |
|------|------|
| 可选 | 默认关闭 |
| 自托管 | 支持用户自己的服务器；也可用局域网直连 |
| 端到端加密 | 强制；服务端不可读 |
| 零知识设计 | 服务端不持有明文密钥 |
| 冲突处理 | 明确的冲突提示，不静默覆盖 |
| 可退出 | 随时关闭同步，关闭后本地数据完整保留 |
| 不依赖 | 关闭同步后全部功能正常 |

**明确不提供**：官方的、托管的、默认开启的云同步。理由见 [01 · 愿景、边界与核心原则](01-vision-boundary-principles.md)。

## 八、安全审计

| 记录项 | 内容 |
|-------|------|
| 配对事件 | 时间、设备名、指纹、结果 |
| 连接事件 | 时间、设备、来源地址、持续时间 |
| 权限变更 | 时间、设备、变更内容 |
| 数据访问 | 时间、设备、访问了哪个库/表、操作类型、影响行数 |
| 越权尝试 | 时间、设备、请求内容、被拒绝原因 |
| 吊销事件 | 时间、设备、原因 |
| 异常 | 认证失败次数超限、异常来源地址 |

**通知策略**：新设备配对成功、越权尝试、权限变更 → 桌面端显著通知（可配置）。

## 九、风险与取舍

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 用户忘记关闭远程访问 | 数据暴露面扩大 | 开启后托盘图标显示状态；提供"自动关闭"选项（如 24 小时后自动关闭） |
| 配对被中间人劫持 | 数据被窃听 | 强制用户确认设备指纹；不提供"跳过确认"选项 |
| 手机丢失 | 设备私钥泄露 | 桌面端可远程吊销；权限有效期限制；建议用户开启手机锁屏 |
| 自托管中继被攻破 | 若实现有误可能泄露 | 端到端加密使中继仅有密文；提供安全配置指引 |
| 局域网内被扫描 | 暴露服务存在 | 不强依赖端口隐藏；依靠加密与认证；提供"仅直连指定设备"模式 |
| 用户权限配置过宽 | 数据被过度访问 | 提供"以该设备视角预览"；默认只读；提供预设 |
| 移动端缓存泄露 | 缓存内容被读取 | 缓存加密、容量上限、一键清除、退出时清除选项 |
| 断网频繁导致体验差 | 用户放弃使用远程功能 | 明确的状态提示、离线队列、重连自动提交 |

## 十、性能与资源目标

| 指标 | 目标 |
|------|------|
| 配对完成（扫码到可用） | ≤ 20 秒 |
| 局域网连接建立 | ≤ 1 秒 |
| 列表首屏加载（100 条） | ≤ 800 ms |
| 同网段操作延迟 | ≤ 800 ms |
| 自托管中继延迟 | ≤ 2 秒（取决于中继质量） |
| 手机端空闲耗电 | 后台无耗电（不常驻） |
| 手机端前台内存 | ≤ 150 MB |
| 桌面端远程服务进程内存（无连接时） | ≤ 20 MB |
| 桌面端远程服务进程内存（3 个连接） | ≤ 60 MB |
| 未开启远程时 | **远程服务完全不启动** |

## 十一、红线清单

| # | 红线 |
|---|------|
| 1 | 远程访问默认**关闭** |
| 2 | 不提供官方托管的公共中继 |
| 3 | 端到端加密不可关闭 |
| 4 | 设备指纹必须由用户确认，不提供"跳过" |
| 5 | 权限校验必须在桌面端（服务端）执行 |
| 6 | 不静默覆盖用户数据；冲突必须提示 |
| 7 | 手机端不存储完整数据副本 |
| 8 | 手机端不注册后台常驻服务 |
| 9 | 未开启远程功能时，不监听任何端口、不做任何局域网发现 |
| 10 | 权限默认最小（只读 + 用户显式选择的范围） |
| 11 | 全部远程操作记入审计日志 |
| 12 | 一侧吊销设备后，其密钥立即失效，不需要对方配合 |
