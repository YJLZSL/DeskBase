# 06 · SQL 数据库能力设计

> 目标是造一个**新手不会怕、老手不会嫌**的数据库。这需要同一份模型、两条路径。

---

## 一、设计立场

| 立场 | 具体含义 |
|------|---------|
| **单文件优先** | 默认一个库 = 一个文件，便于携带、备份、迁移 |
| **嵌入式** | 不要求用户安装数据库服务、不开端口、不配置连接串 |
| **能力不阉割** | 高级用户必须能拿到完整的 SQL、视图、触发器、索引、执行计划 |
| **双路径** | 同一张表，新手用图形界面/向导，老手用 SQL 编辑器 |
| **可解释** | 向导生成的每一步都能看到等价的 SQL；AI 生成的 SQL 必须展示供确认 |
| **可撤销** | 破坏性操作（删表、改结构、批量更新）必须有确认、有预览、有回退 |
| **安全默认** | 不记录 SQL 日志（隐私）、不自动联网、API 默认仅本机 |

---

## 二、数据模型与库管理

### 2.1 库（Database）

| 能力 | 说明 |
|------|------|
| 新建 | 选择位置、命名、是否加密、初始字符集/排序规则（进阶可改） |
| 打开 | 最近库列表、从文件打开、拖入文件打开 |
| 属性 | 大小、表数、记录总数、创建时间、最后修改、加密状态 |
| 操作 | 重命名、移动、复制、压缩（VACUUM 类操作）、完整性检查、导出 |
| 多库 | 支持同时打开多个库，标签页切换 |
| 只读打开 | 以只读模式打开（防止误改，适合查看别人给的文件） |
| 库级加密 | 首启询问；开启后每次打开需口令或系统密钥链解锁 |

### 2.2 表（Table）

| 能力 | 说明 |
|------|------|
| 建表向导 | 表名 → 逐列定义 → 主键 → 索引 → 预览 DDL → 创建 |
| 可视化编辑 | 加列、删列、改名、改类型、改约束、调顺序 |
| 安全改结构 | 改结构前自动创建快照；高风险改动显示影响评估；提供一键回退 |
| 表注释 | 表级与字段级注释，老手写给自己，新手看得懂 |
| 操作 | 重命名、复制结构（含/不含数据）、清空（需输入确认）、删除（需输入表名确认） |
| 数据校验 | 建列时可选：非空、唯一、范围、正则、枚举、外键 |

**建表向导示意**

```
第 1 步 · 表名
   [ 客户                  ]   ⓘ 只能用字母、数字、下划线

第 2 步 · 字段
   ┌────────────┬──────────┬──────┬────────┬──────┐
   │ 字段名      │ 类型      │ 主键  │ 必填    │ 说明  │
   ├────────────┼──────────┼──────┼────────┼──────┤
   │ id         │ 自动编号  │  ✔   │   ✔    │      │
   │ 姓名        │ 文本      │      │   ✔    │      │
   │ 电话        │ 文本      │      │        │ 11位 │
   │ 类型        │ 单选项    │      │   ✔    │      │
   │ 加入日期    │ 日期      │      │        │      │
   └────────────┴──────────┴──────┴────────┴──────┘
   [+ 添加字段]      [从模板开始]      [导入 CSV 自动生成字段]

第 3 步 · 索引
   建议：为「电话」建唯一索引（常用于查询，且应唯一）
   [√] 创建      [ ] 暂不创建

第 4 步 · 预览
   CREATE TABLE 客户 (
     id        INTEGER PRIMARY KEY AUTOINCREMENT,
     name      TEXT NOT NULL,
     phone     TEXT UNIQUE,
     category  TEXT NOT NULL,
     joined_at DATE
   );
   CREATE UNIQUE INDEX idx_customer_phone ON 客户(phone);

   [ 返回修改 ]                    [ 创建 ]
```

### 2.3 字段类型

**新手看到的「类型」（中文语义）**

| 界面名称 | 底层类型 | 说明 |
|---------|---------|------|
| 文本 | TEXT | 任意文字 |
| 长文本 | TEXT | 备注、描述 |
| 数字（整数） | INTEGER | 计数、编号 |
| 数字（小数） | REAL / NUMERIC | 金额、比例 |
| 日期 | DATE | 只有日期 |
| 日期时间 | DATETIME | 日期 + 时间 |
| 是/否 | BOOLEAN | 复选框 |
| 单选项 | TEXT + 约束 | 固定候选中选一个 |
| 多选项 | TEXT / 关系表 | 多选 |
| 关联 | 外键 | 指向另一张表 |
| 附件 | 路径引用 | 指向附件存储 |
| 自动编号 | 自增主键 | |
| JSON | TEXT / JSON | 结构化数据（进阶） |
| 二进制 | BLOB | 图片、文件（进阶） |

**高级模式**额外暴露：`VARCHAR(n)`、`CHAR(n)`、`DECIMAL(p,s)`、`BIGINT`、`SMALLINT`、`TINYINT`、`TIMESTAMP WITH TIME ZONE`、`UUID`、枚举底层表达等。

> 原则：**新手看到意图，老手看到类型**。切换模式时映射关系不变，不会因为切换而改变数据。

## 三、查询能力

### 3.1 三条查询路径

```
                    同一张表 / 同一份数据
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
  ① 查询向导           ② SQL 编辑器        ③ 自然语言查询
  （勾选 + 下拉）      （完整 SQL）        （中文提问 → SQL）
        │                   │                   │
        └───────────────────┴───────────────────┘
                            │
                     都能「查看等价 SQL」
```

### 3.2 查询向导（新手默认入口）

**交互流程**

```
第 1 步 · 我要找什么
   ○ 某张表的记录      ● 需要组合多张表的数据

第 2 步 · 选数据源
   [客户]  [订单]  [收款]     ← 自动检测关联关系并连线提示

第 3 步 · 要哪些字段（勾选）
   ☑ 客户.姓名   ☑ 订单.金额   ☑ 收款.状态   ☐ 订单.备注

第 4 步 · 加条件（可多条，AND / OR 可切换）
   ┌──────────┬────────┬──────────┬──────┐
   │ 收款.状态 │  等于  │  未结清   │  ✕  │
   │ 订单.日期 │ 在年内 │  2026     │  ✕  │
   └──────────┴────────┴──────────┴──────┘
   [+ 添加条件]        [切换为 或 ]

第 5 步 · 排序与限制
   排序：订单.日期 ↓      最多返回：100 行

第 6 步 · 预览 SQL 与结果
   [ 查看 SQL ]  [ 执行 ]  [ 保存为视图 ]  [ 保存为收藏 ]
```

**关键设计**

- 选表后自动识别外键关系，用连线展示，用户不用理解 JOIN 概念。
- 条件用自然语言表达（"在年内"、"包含"、"大于等于"），底层翻译为 SQL。
- **每一步都能展开查看等价的 SQL**，让用户在不知不觉中学会 SQL。
- 生成的查询可一键「保存为视图」或「保存为收藏查询」。

### 3.3 SQL 编辑器（高级入口）

| 能力 | 说明 |
|------|------|
| 语法高亮 | 关键字、字符串、数字、注释、函数分别着色 |
| 自动补全 | 表名、字段名、函数、关键字；带类型提示 |
| 智能提示 | 输入 `SELECT * FROM ` 后列出表；输入 `t.` 后列出 `t` 的字段 |
| 括号匹配 | 自动配对与高亮 |
| 格式化 | 一键美化（可配风格：紧凑/标准/展开） |
| 多光标 | 支持（进阶） |
| 执行 | `Ctrl+Enter` 执行选中或全部；`Ctrl+Shift+Enter` 只执行光标所在语句 |
| 多语句 | 支持一次多条，逐条执行并分别显示结果 |
| 结果 | 表格视图 + 文本视图（原始输出）切换 |
| 导出结果 | 直接导出查询结果（不落表） |
| 查询历史 | 自动记录，可搜索、可收藏、可重跑 |
| 收藏查询 | 命名保存，可参数化 |
| 参数化查询 | 用 `:参数名` 占位，执行时弹窗填值 |
| 错误提示 | 指出出错位置与行号，给出通俗解释与修复建议 |
| 危险操作拦截 | `DROP` / `DELETE` 无 `WHERE` / `UPDATE` 无 `WHERE` 执行前二次确认 |
| 事务控制 | 手动 `BEGIN` / `COMMIT` / `ROLLBACK`，界面上显示当前事务状态 |
| 执行计划 | `EXPLAIN` 可视化：扫描方式、命中索引、预估行数、耗时热点（进阶） |
| 慢查询标记 | 超过阈值（默认 1 秒）的查询在历史中标记（进阶） |
| 只读模式 | 可切到只读，防止误改生产数据 |

### 3.4 自然语言查询（进阶，属 AI 阶段）

| 环节 | 设计 |
|------|------|
| 输入 | 中文提问，如「上个月哪些客户没付尾款」 |
| 上下文 | 自动带入当前库的表结构与字段注释（**仅本地**） |
| 生成 | 由本地模型生成 SQL |
| **展示** | **必须完整展示生成的 SQL**，并提供「为什么这样写」的简要解释 |
| 确认 | 用户必须点「执行」才运行；可先「仅预览」看结果前 20 行 |
| 修正 | 用户可手动改 SQL 再执行；修正结果可用于本地提示优化（可选，默认关闭） |
| 失败处理 | 生成不了就说"我没理解"，不允许生成看似合理但错误的 SQL 后静默执行 |
| 隐私 | 表结构与字段名属 S1 数据，**默认不发送到任何外部服务** |

> **红线**：AI 生成的 SQL **绝不允许自动执行**。任何写操作（INSERT/UPDATE/DELETE/DDL）由 AI 生成的，必须显示影响估计（将影响 N 行）并要求显式确认。

## 四、关系、视图、索引、触发器

### 4.1 关系（Relations）

| 能力 | 说明 |
|------|------|
| 外键定义 | 图形界面选择目标表与字段 |
| 关系类型 | 一对一、一对多、多对多（多对多自动建中间表） |
| ER 图 | 可视化全部表与关系，可拖拽布局、缩放、导出为图片 |
| 级联规则 | `CASCADE` / `SET NULL` / `RESTRICT` / `NO ACTION`，界面上用中文解释每种含义 |
| 引用完整性检查 | 建立关系前扫描现有数据是否存在孤儿记录，报告冲突 |
| 关系浏览 | 在记录详情中直接跳转到关联记录 |

**级联规则的中文解释（界面必须展示）**

| 选项 | 界面文字 |
|------|---------|
| RESTRICT | 如果还有关联记录，就不允许删除（最安全，默认） |
| CASCADE | 删除主记录时，关联记录一并删除（⚠ 有数据丢失风险） |
| SET NULL | 删除主记录时，关联记录的相关字段置空 |
| NO ACTION | 交给数据库默认行为处理 |

### 4.2 视图（Views）

| 能力 | 说明 |
|------|------|
| 创建 | 从查询向导或 SQL 编辑器一键「保存为视图」；也可用视图设计器 |
| 双模式 | 可视化设计器 / DDL 编辑器，可随时切换 |
| 物化视图 | 支持缓存结果，可设置刷新策略（手动/定时）（进阶） |
| 使用 | 视图在表列表中单独分组，查询视图与查询表体验一致 |
| 依赖分析 | 显示视图依赖哪些表；删表时提示会被影响的视图 |
| 编辑 | 修改视图定义，含影响提示 |

### 4.3 索引（Indexes）

| 能力 | 说明 |
|------|------|
| 创建 | 选字段、选顺序、唯一/普通、复合索引、表达式索引（进阶） |
| 管理 | 查看现有索引、大小、命中次数 |
| 统计 | 每个索引被使用多少次；长期未使用的索引提示可删除（进阶） |
| 建议 | 根据慢查询历史与查询模式，建议创建哪些索引（进阶） |
| 重建与优化 | 一键重建/分析，显示优化前后对比 |
| 命名规范 | 默认 `idx_表名_字段名`，可改 |
| 影响提示 | 创建索引时提示：会加快查询，但会增大文件体积并略微降低写入速度 |

### 4.4 触发器（Triggers）

| 能力 | 说明 |
|------|------|
| 事件 | `BEFORE` / `AFTER` + `INSERT` / `UPDATE` / `DELETE` |
| 作用范围 | 行级 / 语句级 |
| 条件 | 可加 `WHEN` 条件（图形化或 SQL） |
| 动作 | 执行 SQL / 更新其他表 / 校验并抛错 / 记录审计 |
| 可视化设计器 | 事件 → 条件 → 动作三步表单；同时显示等价 DDL |
| 调试 | 提供「试运行」：在事务中模拟一次触发，显示影响后回滚 |
| 启用/禁用 | 可临时禁用而不删除 |
| 风险提示 | 明确提示：触发器会产生"看不见的写入"，可能影响性能与调试难度 |

## 五、数据编辑与校验

### 5.1 数据网格

| 能力 | 说明 |
|------|------|
| 直接编辑 | 双击进入编辑，提交即写入（事务保护） |
| 批量编辑 | 选中多行修改同一字段 |
| 新增行 | 底部空白行直接输入 |
| 删除行 | 可多选删除，删除前显示影响行数 |
| 复制/粘贴 | 支持从 Excel 粘贴多行多列，自动匹配列 |
| 撤销 | 编辑操作可撤销（会话内） |
| 筛选排序 | 表头点击排序，工具栏筛选 |
| 行详情 | 侧滑面板展示全字段（含长文本、JSON、附件） |
| 关联跳转 | 外键字段可点击跳转 |
| 只读保护 | 查询结果集默认只读，需点「启用编辑」 |
| 提交模式 | 立即提交 / 手动提交（显示待提交变更数） |

### 5.2 数据校验

| 校验类型 | 说明 |
|---------|------|
| 非空 | 字段不允许为空 |
| 唯一 | 值不可重复 |
| 范围 | 数值/日期区间 |
| 正则 | 自定义模式（如手机号） |
| 枚举 | 限定在候选集合内 |
| 外键 | 必须存在于关联表 |
| 自定义表达式 | 字段间约束（如 `结束日期 >= 开始日期`） |

**校验失败的呈现**

- 单元格红色边框 + 悬浮说明
- 底部汇总提示：「3 个字段存在校验问题」，可点击逐条定位
- 导入时校验失败不中断，生成错误报告

## 六、导入导出

### 6.1 导入

| 格式 | 要点 |
|------|------|
| CSV / TSV | 编码探测（UTF-8 / GBK / UTF-16）、分隔符自动识别、引号规则、表头识别 |
| JSON | 数组 / 嵌套对象；嵌套可展平为多列或保留为 JSON 列 |
| Excel | 多 Sheet 选择、合并单元格处理、公式取当前值、日期类型识别 |
| SQL | 解析 DDL + DML（进阶） |
| 剪贴板 | 直接粘贴制表符分隔的表格数据 |

**导入性能目标**

| 数据量 | 目标耗时 |
|-------|---------|
| 1 万行 | ≤ 2 秒 |
| 10 万行 | ≤ 15 秒 |
| 100 万行 | ≤ 3 分钟（分批提交，进度可中断） |

导入期间显示真实进度（已处理行数 / 总行数），可取消，取消后保留已导入部分并明确告知。

### 6.2 导出

见 [05 · 办公工具箱](05-office-toolbox.md#十三导入导出)，数据库模块提供额外的：

| 能力 | 说明 |
|------|------|
| 结构导出 | 只导出建表语句（DDL），用于迁移结构 |
| 结构与数据 | DDL + INSERT |
| 查询结果导出 | 导出任意查询的结果集 |
| 分文件导出 | 按字段值拆分多个文件（如按年份拆） |
| 脱敏导出 | 指定字段替换为脱敏值（进阶） |

## 七、性能设计

### 7.1 目标

| 场景 | 目标 |
|------|------|
| 打开库（10 万行，50 MB） | ≤ 800 ms |
| 表数据首屏加载（任意行数） | ≤ 300 ms（只加载可见行） |
| 索引命中查询（万行表） | ≤ 50 ms |
| 无索引全表扫描（10 万行） | ≤ 800 ms，并提示建议加索引 |
| 插入 1 万行（批量） | ≤ 3 秒 |
| 表结构变更（加列，100 万行） | ≤ 5 秒 |
| 滚动浏览 100 万行表 | ≥ 50 FPS |

### 7.2 优化手段

| 手段 | 说明 |
|------|------|
| 虚拟滚动 | 只渲染可见行 |
| 分页 / 游标 | 大结果集分批取，不用一次性载入 |
| 预编译语句 | 参数化查询复用执行计划 |
| 事务批量提交 | 批量导入每 N 行提交一次，平衡速度与内存 |
| 索引 | 自动建议 + 一键创建 |
| 连接复用 | 单进程内复用数据库连接 |
| 结果集上限 | 默认 10 000 行，超出提示"继续加载更多" |
| 查询超时 | 默认 30 秒，超时可中断 |
| 后台执行 | 长查询移到后台线程，界面不冻结 |
| 文件压缩 | 定期 `VACUUM` 类操作，可手动触发也可是自动（默认关闭，手动） |
| 惰性加载 | 表结构、索引信息按需读取 |
| 缓存 | 元数据缓存、查询计划缓存，有上限 |

### 7.3 大表与弱机策略

| 情形 | 策略 |
|------|------|
| 表 > 100 万行 | 提示用户，默认只加载前 N 行，提供显式"加载全部" |
| 内存不足 | 自动降低批大小，提示用户 |
| 硬盘空间不足 | 写入前预检，不足时拒绝并说明需要多少空间 |
| 库文件在慢速介质（U 盘/网络盘） | 提示性能影响，建议复制到本地 |

## 八、版本历史与时间点恢复（数据库侧）

| 能力 | 说明 |
|------|------|
| 库级历史 | 每次结构变更产生一个"结构版本"，可查看变更内容与回滚 |
| 记录级历史 | 可选开启：记录每次数据变更的前后值（会增加存储） |

| 时间点恢复 | 选择时间点 → 预览该时刻的数据 → 恢复到新库或覆盖 |
| 结构变更预览 | 改结构前显示迁移计划、预计耗时、风险评估 |

## 九、权限与审计

### 9.1 本地权限

单机场景下权限需求有限，但需覆盖：

| 能力 | 说明 |
|------|------|
| 库级口令 | 开启加密后，打开库需口令 |
| 只读模式 | 以只读方式打开（适合查看敏感库） |
| 敏感表保护 | 指定表需再次输入口令才能查看（进阶） |
| 导出限制 | 可为指定库/表设置"禁止导出"标志（防止误操作或约束他人使用） |

### 9.2 远程权限（启用远程访问时）

见 [10 · 桌面端与手机远程端](10-desktop-mobile-remote.md#四权限模型)。

权限粒度：**数据库 → 表 → 字段 → 操作 → 时段**。

### 9.3 审计日志

| 记录项 | 内容 |
|-------|------|
| 结构变更 | 谁、何时、把什么改成了什么 |
| 数据变更 | 表、行数、时间（默认不记录具体值，避免日志成为泄露源） |
| 查询 | 可选记录（**默认关闭**，隐私考虑） |
| 导出 | 谁导出了什么、导到哪里、多大 |
| 远程连接 | 设备、时间、IP（局域网）、操作摘要 |
| 加密操作 | 加解密、口令修改、密钥轮换 |

**审计日志本身的管理**：本地存储、可搜索、可导出、可清空（清空前二次确认）、有容量上限、自动轮转。

## 十一、安全红线（数据库相关）

| 红线 | 要求 |
|------|------|
| **参数化查询** | 所有由界面或 AI 生成的查询必须参数化，禁止字符串拼接用户输入 |
| **AI 不自动执行** | AI 生成的任何 SQL 都必须展示并等待人工确认 |
| **破坏性操作确认** | `DROP` / `TRUNCATE` / 无 `WHERE` 的 `UPDATE`/`DELETE` 必须二次确认，并要求输入对象名 |
| **改结构先快照** | 任何结构变更前自动创建快照，失败可回退 |
| **API 默认仅本机** | 生成的 HTTP 接口默认只绑定 `127.0.0.1`，对外暴露需显式开启并提示风险 |
| **查询日志默认关闭** | 记录执行的 SQL 可能泄露业务信息，默认不记录 |
| **导出留痕** | 导出操作记入审计日志 |
| **不自动上传** | 数据库文件、查询结果、表结构默认不发送到任何外部服务 |
