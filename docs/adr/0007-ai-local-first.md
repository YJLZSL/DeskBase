# ADR-0007: AI 默认本地推理，外部服务逐次授权

- **状态**：已接受
- **日期**：2026-09-17
- **决策者**：核心维护者
- **相关**：[09 · 本地 AI 架构](../09-local-ai.md)、[ADR-0005](0005-network-closed-by-default.md)

---

## 背景

产品需要 AI 能力（自然语言查询、摘要、分类、翻译、OCR、转写、语义搜索）。

业界主流做法是调用云端大模型 API：质量高、无需显卡、无需下载模型、按量付费。但云端 API 意味着：

- 用户数据要发送到第三方服务器
- 我们无法控制对方的日志、保留、二次使用策略
- 需要 API 密钥管理
- 需要持续的服务可用性与成本承诺

本项目宣称"AI 不能成为数据泄露通道"。要在提供 AI 能力的同时兑现这个承诺，必须在架构层面做出选择。

---

## 决策

**AI 默认由本机模型推理；外部 AI 服务默认完全禁用，启用后仍需逐次授权与脱敏预览。**

具体要求：

1. 全部 AI 能力默认由**本地模型**完成，完全断网可用。
2. 模型、向量索引、对话记录、临时推理数据**全部本地存储**。
3. **禁止**默认调用任何云端 AI API。
4. 若用户主动配置外部服务：
   - 必须显式阅读说明并手动勾选同意
   - **每次调用**默认需确认（可设为会话内允许）
   - 发送前必须展示**实际将发送的脱敏后内容**
   - 全部调用记入审计日志
   - 可随时完全关闭
5. **S2 / S3 级数据永不外发**，无论用户如何配置（隐私闸门强制拦截）。
6. AI 生成的 SQL 与任何可执行内容**绝不自动执行**，必须人工确认。
7. 提供「AI 隐私面板」，展示运行模式、数据流向、调用次数、存储占用。
8. 提供「一键完全关闭 AI」，关闭后界面不再出现 AI 入口、不加载模型、不构建索引。
9. 不使用 AI 时，**AI 相关后台进程数 = 0，内存占用回到基线**。

---

## 备选方案

### 方案 A：默认云端 API
- 优点：质量最好；无需下载模型；无需显卡；开发最快
- 缺点：用户数据必须外发；需要密钥与费用；需要网络；无法离线；无法证明"数据不外传"
- **为什么不选**：与本产品的第一原则（本地优先）和第七条承诺（AI 不出网）直接冲突。

### 方案 B：默认云端 + 本地小模型兜底
- 优点：质量与离线兼顾
- 缺点：默认仍是外发；用户难以判断当前用的是哪个；"兜底"会变成"默认"
- **为什么不选**：默认外发就是默认外发，不该用"兜底"来稀释。

### 方案 C：仅本地，完全不允许外部服务
- 优点：最纯粹的隐私承诺
- 缺点：用户如果有自己的企业大模型或愿意用外部服务，我们无法支持；某些任务本地模型能力不足（如复杂推理）
- **为什么不选（改为"默认禁用 + 可选启用"）**：完全禁止会把有正当需求的用户推开。我们选择：**默认安全 + 用户知情选择**。

### 方案 D：本地优先 + 外部服务逐次授权（采纳）
- 优点：默认安全；保留灵活性；用户可验证；与隐私承诺一致
- 缺点：本地模型质量可能不足；模型下载有门槛；外部服务流程较繁琐（但这是刻意的摩擦）
- **为什么选它**：安全默认 + 知情选择是唯一在隐私与能力之间取得正确平衡的方式。摩擦点放在"外发"这一步，是合理的。

## 后果

### 正面
- 断网可用，在无网络或受限网络环境下 AI 功能不缩水
- 用户可以自己验证"AI 没有联网"（拔网线测试 + 审计日志）
- 无 API 密钥管理、无服务成本、无第三方依赖
- 尊重了有外部 AI 需求的高级用户
- 隐私承诺成为真实的差异化，而非口号

### 负面
- **本地模型质量可能不如云端大模型**
  - 缓解：按任务选模型；NL2SQL 提供"展示 + 人工修正"闭环，不承诺一次正确
- **模型下载门槛**（体积 1–8 GB）
  - 缓解：小模型优先；按需下载；显式说明体积与来源
- **需要的磁盘与内存空间更大**
  - 缓解：空闲释放；内存上限；按任务选模型；不下载模型时 AI 功能优雅禁用
- **外部服务的确认流程繁琐**
  - 缓解：提供"本次会话内允许"选项，这是刻意的摩擦，但给了用户选择权

### 中性
- AI 功能与"网络默认关闭"策略的耦合需要在架构上明确（隐私闸门为强制中间层）
- 需要额外的隐私闸门与审计实现

---

## 验证方式

| # | 验证项 | 判据 |
|---|-------|------|
| 1 | 断网可用 | 完全断网时全部 AI 功能可用 |
| 2 | 本地推理零网络 | 本地推理期间网络 IO = 0 |
| 3 | S2/S3 拦截 | 构造含 S2 数据的请求，外发路径必须被拦截 |
| 4 | 逐次确认 | 外部服务调用必须弹出含"实际发送内容"的确认框 |
| 5 | 不自动执行 | AI 生成的 SQL 必须展示并等待确认，验证无自动执行路径 |
| 6 | 资源释放 | AI 空闲 5 分钟后内存回到基线；AI 后台进程数 = 0 |
| 7 | 一键关闭 | 关闭后 AI 入口全部隐藏，无模型加载、无网络请求 |
| 8 | 审计完整 | 每次 AI 调用（本地与外部）均有记录 |
