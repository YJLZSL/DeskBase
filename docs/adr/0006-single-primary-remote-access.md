# ADR-0006: 采用单主端 + 远程访问，不做双向同步

- **状态**：已接受
- **日期**：2026-09-17
- **决策者**：核心维护者
- **相关**：[10 · 桌面端与手机远程端](../10-desktop-mobile-remote.md)、[ADR-0001](0001-local-first-architecture.md)

---

## 背景

用户会想在手机上看电脑里的数据。业界主流做法是"双向同步 + 云端中转"：每台设备都持有数据副本，通过云端服务保持一致。

这种架构需要解决：冲突合并（CRDT / OT）、时钟与顺序、离线队列、版本向量、部分同步、设备配对与撤销、云端存储与加密。同时它意味着：

- 需要账号与云端服务
- 手机上存有完整数据副本（丢失即泄露）
- "哪个是最新版"成为用户的持续困惑
- 加密方案复杂（云端需要能处理密文或持有密钥）

---

## 决策

**采用单主端 + 远程访问架构：桌面端持有唯一主数据副本，手机端是安全远程端，不持有完整数据副本，不做双向同步。**

具体要求：

1. 桌面端是**数据主端**，是唯一的数据真相来源。
2. 手机端是**远程客户端**，通过端到端加密通道访问桌面端的数据。
3. 手机端仅持有最小必要的临时缓存，可一键清除。
4. 写操作由手机端提交到桌面端，由桌面端的事务保证一致性。
5. 冲突处理：不自动合并。版本不匹配时提示用户选择。
6. 不提供官方的、托管的、默认开启的云同步。
7. 未来若提供多桌面设备同步，必须是可选的、自托管的、端到端加密的，且冲突需提示而非静默覆盖。

---

## 备选方案

### 方案 A：全量双向同步 + 官方云
- 优点：多端体验最顺滑；离线可用性最好
- 缺点：需要云端与账号；需要冲突合并算法（复杂度极高）；手机持有完整副本（泄露风险）；违反本地优先承诺
- **为什么不选**：与 ADR-0001 根本冲突，且工程复杂度会吞掉整个团队。

### 方案 B：全量双向同步 + 自托管服务
- 优点：不依赖官方云；多端体验较好
- 缺点：仍需冲突合并算法；仍需手机持有完整副本；自托管门槛高；与"打开即用"冲突
- **为什么不选**：省去了云端，但保留了最贵的那部分（冲突合并与多副本一致性）。收益不成比例。

### 方案 C：文件级同步（用户把数据目录放在自己的同步盘）
- 优点：实现成本极低，几乎不需要新代码
- 缺点：多设备同时写会导致文件损坏；同步盘会做冲突重命名（产生 `xxx (冲突副本).db`）；无法给出有意义的冲突提示
- **为什么不选（但保留作为用户自助方案）**：对单设备 + 备份场景可行，但多设备并发写会造成数据损坏。我们可以在文档中说明风险，但不把它作为官方方案宣传。

### 方案 D：单主端 + 远程访问（采纳）
- 优点：无云端依赖；无冲突合并；数据只有一个真相来源；手机不持有完整副本；与本地优先承诺一致
- 缺点：手机离线时不可用；桌面端必须开机且可连接；跨网络需自托管中继
- **为什么选它**：用"手机离线不可用"这一个明确的取舍，换掉了整个冲突合并与云端托管的复杂度。对一个本地优先产品，这是正确的交换。

---

## 后果

### 正面
- 不需要实现冲突合并算法，工程复杂度大幅降低
- 手机不持有完整数据副本，设备丢失风险显著降低
- 无云端服务，无账号体系，隐私承诺保持完整
- 数据一致性由桌面端的事务层保证，逻辑清晰
- 权限模型简单（服务端强制校验）

### 负面
- **手机离线不可用**（只能查看已缓存的少量内容）
  - 缓解：提供离线录入队列，重连后提交；明确提示"未连接"状态
- **桌面端必须可达**（开机 + 网络可达）
  - 缓解：局域网直连门槛低；自托管中继解决跨网络
- **实时通知困难**
  - 缓解：默认"下次连接时同步"；若用户需要实时通知，需显式开启推送（并说明推送服务只传最小标识）
- 用户可能不理解"为什么手机上看不到全部数据"
  - 缓解：界面明确说明"数据在电脑上，手机是遥控器"

### 中性
- 产品定位进一步明确：手机端是辅助工具，不是主战场
- 移动端可以做得非常轻（只做查看/录入/审批），开发成本可控

---

## 验证方式

| # | 验证项 | 判据 |
|---|-------|------|
| 1 | 手机不持有完整副本 | 检查手机端存储：无完整数据库、无附件原文件 |
| 2 | 冲突不静默覆盖 | 模拟并发修改，必须提示用户选择 |
| 3 | 端到端加密 | 抓包无法读出明文；中继侧日志无明文 |
| 4 | 权限服务端强制 | 篡改客户端请求越权操作，被桌面端拒绝并记入审计 |
| 5 | 无云端依赖 | 无外网环境（仅局域网）下远程访问可用 |
| 6 | 离线行为明确 | 桌面端不可达时，手机端显示明确状态，不静默失败 |
| 7 | 一键吊销 | 桌面端吊销设备后，该设备立即失效，不需对方配合 |
