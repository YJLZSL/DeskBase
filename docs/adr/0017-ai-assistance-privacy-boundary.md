# ADR-0017: AI 协助的隐私边界（要 AI 帮忙，但数据一个字节都不出去）

- **状态**：提议（2026-09-18 起草，**待发起人确认**）
  · **2026-09-19 定位**：本 ADR 是 [ADR-0019](0019-network-boundary-clarification.md) 里 **R1（数据红线）**的
  AI 侧实现。那句"网络默认关闭"当初要防的就是这件事 —— 所以本 ADR 的每一条都**不可让步**，
  而更新检查之类的功能不归本 ADR 管（它们不接触用户数据）。
- **日期**：2026-09-18

## 背景

发起人要求："能要 AI 协助，AI 协助的同时又能保证数据不外传上传。"

这两句必须**同时**成立，否则宁可不做：对一个"数据不出本机"的产品来说，
AI 功能是最容易把整份承诺一次性赔掉的地方 —— 用户一条"帮我看看这张表为什么对不上账"，
如果连同行数据一起发去云端，前面所有隐私设计都白做了。

ADR-0007 已经定了"AI 默认本地推理、外部服务逐次授权"。本 ADR 补的是**具体到按钮和字段的边界**。

---

## 决策

### 1. 默认本地，默认不联网

- AI 能力**默认关闭**；开启后默认走**本机推理**（模型可插拔，程序不自带，需用户自己下载，每次下载需确认）。
- 本机没有可用模型时，AI 功能**直接不可用**，并说明"需要下载模型（或开启外部服务）"。
  **不许静默降级到云端** —— 用户以为在本地跑，实际数据出去了，这是最坏的一种欺骗。

### 2. 外部 AI 服务：默认关闭 + 逐次授权 + 数据最小化

| 规则 | 具体要求 |
|------|---------|
| 开关 | 网络总开关（ADR-0005）之下的独立开关，默认关闭。关闭时网络 IO 必须为 0 |
| 授权 | **每一次调用**都要单独确认，不做"一次授权永久有效" |
| 展示 | 确认框必须显示**将要发送的内容**（脱敏后的原文），不是"是否允许发送数据"这种空话 |
| 最小化 | 默认只发**结构信息**（表名、字段名、类型、报错文本），**不发数据行** |
| 发数据 | 若某功能确实需要发行数据，**单独一个勾选项，默认不勾**，且提示"这会把你选中的行发给外部服务" |
| 审计 | 每次调用（成功 / 被拒绝）都记本地审计日志，可查看可导出 |
| 清除 | 对话记录本地存储，一键清除 |

### 3. AI 给的东西不许自动执行

- 生成的 **SQL 必须原样展示**并让用户确认后才执行（与 ADR-0007 一致：AI 生成的 SQL 不自动执行）。
  危险语句照走 ADR-0016 / 现有闸门，不因为"是 AI 写的"就放行。
- 建议的建表结构、字段类型同样要用户确认后落库。
- AI 不能替用户做删除、覆盖、导出这类不可逆动作，**一次都不能**。

### 4. 先做最有用的三件，别一上来就做大而全

| 能力 | 说明 |
|------|------|
| 自然语言 → SQL | 展示生成的 SQL，用户确认才执行。对"不会写 SQL 的人"吸引力最大 |
| 建表建议 | 描述"我要记客户和回款"，给出表名与字段建议（含类型），用户可改 |
| 报错解释 | 把 SQLite 的英文报错翻成"哪里错了、怎么改"，**只发报错文本，不发数据** |

### 5. 界面必须有 AI 隐私面板

常驻显示：当前用的是本地模型还是外部服务（或关闭）、数据流向、本次会话有没有发出过内容、一键清除。
**没有这个面板就不许上线 AI 功能。**

### 6. 没做到之前，界面不出现 AI 入口

在 ADR 批准且本地/外部链路都就位之前，界面上**不放**"AI 助手"按钮。
放一个点了没反应的按钮，比不放更伤信任。

## 备选方案

### 方案 A：接主流云 API，快速好用（否决）

体验最好、成本最低，但直接违反"默认数据不出本机"。
即便做成"用户可选择"，默认路径一旦是云端，绝大多数用户会一路点同意 —— 那承诺就只剩宣传语。

### 方案 B：只做本地，永不联网（部分采纳）

最安全，但本机没模型时功能完全不可用，对"想让 AI 帮忙"的诉求等于没做。
**采纳其精神**：默认本地、默认不发数据；把"可选外部"作为用户显式打开的例外。

### 方案 C：把数据脱敏后再发（不采纳为默认）

脱敏很难做对（姓名、金额、地址、甚至"某客户欠款 12 万"这种组合都是敏感信息），
且用户无法验证脱敏效果。**不把它当默认**，只作为外部调用时的可选降险手段。
