# ADR-0009: 采用简洁 / 高级双界面模式

- **状态**：已接受
- **日期**：2026-09-17
- **决策者**：核心维护者
- **相关**：[03 · 信息架构](../03-information-architecture.md)、[01 · 愿景、边界与核心原则](../01-vision-boundary-principles.md)

---

## 背景

产品要同时服务两类差异极大的用户：

- **普通办公用户**（约 65%）：会用 Word / Excel，不懂 SQL，不知道"主键"是什么。看到一堆不认识的按钮就会关掉软件。
- **专业用户**（约 10%）：要完整 SQL、索引、触发器、执行计划、API。

同时满足两者的常见做法有三种：做成两个产品、只做简单版、只做专业版。三者都不理想。

而且还有一个隐含约束：**切换模式不能导致数据不一致或功能断层**。用户在新手模式下建的数据，在高级模式下必须完整可见可编辑；反之亦然。

---

## 决策

**采用简洁模式（默认）/ 高级模式双界面模式，基于同一份数据模型，模式只改变界面呈现，不改变数据能力。**

具体要求：

1. **简洁模式**（默认）：一级模块可见 5 个（工作台 / 办公工具 / 数据库 / 备份与恢复 / 设置）；二级功能只显示核心 4–5 个；数据库默认入口是**查询向导**而非 SQL 编辑器。
2. **高级模式**：全部 10 个一级模块可见；暴露索引、触发器、视图、ER 图、执行计划等；数据库默认入口可配置为 SQL 编辑器。
3. **切换方式**：设置 → 外观 → 界面模式；首次使用时询问。
4. **切换不改变数据**：两种模式操作同一份数据模型，字段类型有稳定的双向映射。
5. **不允许功能断层**：任何在简洁模式下建立的实体，都必须能在高级模式中被完整表达与编辑。
6. **局部展开**：任何功能页可单独「展开更多」，此操作不改变全局模式。
7. **折叠标注**：折叠的高级内容旁标注「可能影响稳定性或隐私」。
8. **简洁模式不阉割数据**：只是隐藏了控件，数据能力（字段类型、关系、约束）在底层完整保留。

---

## 备选方案

### 方案 A：单一界面，全部功能可见
- 优点：实现最简单；没有"两个模式"的维护成本
- 缺点：直接吓退核心用户（65% 的普通用户）
- **为什么不选**：核心用户是产品存活的基础，不能牺牲他们。

### 方案 B：单一界面，只做简单功能
- 优点：体验统一；实现简单
- 缺点：专业用户流失；产品上限被锁死；无法与"内置 SQL 数据库能力"的定位匹配
- **为什么不选**：放弃了产品的差异化能力。

### 方案 C：两个独立产品（DeskBase Lite / DeskBase Pro）
- 优点：各自体验纯粹
- 缺点：维护两套代码；数据互通复杂；用户升级时需要迁移；定位分散
- **为什么不选**：对本项目规模来说成本过高，且会造成用户困惑。

### 方案 D：简洁 / 高级双模式（采纳）
- 优点：同一份数据、同一套代码；两类用户都得到合适界面；升级路径平滑
- 缺点：需要维护两套界面配置；需严格控制"高级功能在新手模式下的隐藏方式"；测试矩阵翻倍
- **为什么选它**：唯一能在不分裂产品的前提下服务两类用户的方式。

### 方案 E：动态渐进（根据使用行为自动展开功能）
- 优点：无需用户选择
- 缺点：不可预测（用户不知道界面为什么变了）；可能"猜错"（用户其实需要高级功能但被隐藏）；实现复杂
- **为什么不选**：把控制权交给猜测。用户应该能明确地选择，而不是被算法安排。

## 后果

### 正面
- 普通用户首次打开看到的是能懂的界面
- 专业用户可一键获得完整能力
- 数据模型统一，不存在"迁移到高级版"的问题
- 产品定位同时覆盖"人人可用"与"专业可用"

### 负面
- **实现与测试成本增加**：每个功能都要考虑两种模式的呈现，测试矩阵翻倍
  - 缓解：以"控件可见性配置"的方式实现，而不是写两套界面；自动化测试覆盖两种模式的关键路径
- **可能出现"断层"缺陷**（某功能在一种模式下无法完成）
  - 缓解：把"模式切换不丢能力"作为发布门禁项；增加专门的模式切换回归测试
- **用户可能不知道高级模式的存在**
  - 缓解：首次使用引导中提及；在需要高级功能的场景（如"要建索引吗？"）给出提示与直达入口

### 中性
- 需要定义清晰的"字段类型双向映射表"
- 需要定义"哪些控件属于高级"的清单并保持稳定

---

## 验证方式

| # | 验证项 | 判据 |
|---|-------|------|
| 1 | 首次使用体验 | 5 名普通用户测试，≥ 4 人在 10 分钟内完成三个核心动作 |
| 2 | 模式切换无断层 | 在简洁模式建立含关系与约束的表，切到高级模式后可完整查看与编辑；反向亦然 |
| 3 | 数据不变 | 切换模式前后，数据库文件哈希不变（除界面偏好外的数据不变） |
| 4 | 高级可达 | 从简洁模式 3 次点击内可到达任一高级功能 |
| 5 | 折叠标注 | 全部折叠的高级内容均有影响提示 |
| 6 | 专业用户满意 | 3 名有 SQL 经验的用户测试，认为"该有的都有" |
| 7 | 回归测试 | CI 中覆盖两种模式的关键路径 |
