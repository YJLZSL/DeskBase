# ADR-0023 · 产品定位转向「Office 三件套的扩展与升级」

- 状态：已接受
- 日期：2026-09-22
- 取代：ADR-0020 中「表格优先形态」的定位部分（形态保留，定位被本 ADR 接管）

---

## 1. 背景

v0.4.0 把 SQL 整个去掉了（ADR-0021），关系能力改由共通字段 / 同步规则 /
命名视图承载（ADR-0022）。这带来一个必须回答的问题：**DeskBase 现在是什么？**

原来的定位是「本地优先、隐私优先的办公工具箱 + 给非程序员用的轻量 SQL 数据库」——
一个双头定位。去掉 SQL 之后，后半句不成立了，而前半句（办公工具箱）反而
因为少了数据库的包袱变得更纯粹。

同时，发起人明确了想要的方向：**Office 三件套的扩展与升级，加上各种有益于
办公的功能**。这不是放弃已有的能力，而是给它们一个更准确的名字和更清楚的顺序。

## 2. 决策

**DeskBase 定位为：Office 三件套的扩展与升级 + 办公实用功能集。**

三条边界（决定了什么做、什么不做）：

1. **不替代 Office，补它不做与做不好的那部分。**
   Office 是通用巨物，做的是"什么都能做一点"。DeskBase 做的是它嫌小不做、
   做了又很别扭的那块：长截图、批量格式转换、把一张台账从 Excel 里搬出来
   自己管、本机跑的 AI 协助。**能共存，不抢位。**

2. **三件套方向各自有落点，但不追求全功能。**
   - 文档：轻量写作与整理（笔记已在，往文档方向长）
   - 表格：**已具备**（建表 / 关联 / 协同更新 / 导入导出 Excel）—— 这是目前最厚的一块
   - 演示：后期，先把前两件做扎实

3. **底座不变：本地优先、隐私优先、单文件、零遥测。**
   这是相对 Office（云端账号、遥测、订阅）最硬的差异，也是三条底线（不丢数据 /
   不泄露 / 不污染）的由来。**任何新功能都不能破这三条。**

## 3. 理由

- **去掉 SQL 之后，"数据库"不再是卖点**。继续挂这个名字，界面上已经没有
  对应的东西（没有查询输入框），用户会困惑。表格能力反而因为没了 SQL 而更纯粹：
  用户要的是"一张能查、能备份、能带走的台账"，不是"一个数据库"。
- **发起人的真实需求是办公**，不是数据库。从第一天起项目就有截图、格式转换、
  笔记这些办公向功能，它们一直处在"工具箱"的模糊定位里。这次是把模糊变清楚。
- **差异化的位置不在"功能更多"，而在"更轻、更私密、更可控"**。
  跟 Office 比功能数量必输；比"一个 exe、数据在自己手里、不联网"则能赢。

## 4. 被否决的方案

| 方案 | 为什么不 |
|------|---------|
| 继续叫「轻量数据库」 | 界面上已无对应物（无查询入口），名字与实物脱节，用户会困惑 |
| **完全替代 Office** | 不现实也不必要。文档 / 表格 / 演示每一项都是十年工程，且用户已有 Office 与既有习惯 |
| 只做工具箱，不碰三件套方向 | 工具箱是"杂"，没有主线，功能会一直发散、排不出优先级 |
| 先做完演示再回头 | 表格这块已经能用且有实测（10 万行导入、崩溃恢复 16/16），应该先把它做透 |

## 5. 影响

- **文档全线重排**：`README.md`、`docs/03` 信息架构、`docs/05` 办公工具箱、
  `ROADMAP.md` 按新定位重写。
- **教程重写**：`app/ui/help.js` 的内容从「数据库使用教程」改为面向
  「办公三件套扩展」的入门引导（本 ADR 的直接产物之一）。
- **界面信息架构**：一级模块按「文档 / 表格 / 演示 / 工具 / 设置」组织；
  现有四个视图（工作台 / 笔记 / 数据库 / 设置）按此逐步对齐。
- **v0.5.0 起按新顺序推进**，见 `ROADMAP.md`。
