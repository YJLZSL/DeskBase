# ADR-0001: 采用本地优先（Local-First）架构

- **状态**：已接受
- **日期**：2026-09-17
- **决策者**：核心维护者
- **相关**：[01 · 愿景、边界与核心原则](../01-vision-boundary-principles.md)、[08 · 隐私、安全、加密、权限与审计](../08-privacy-security.md)

---

## 背景

DeskBase 要做一个办公数据工具。同类产品的主流做法是"云端账号 + 云端存储 + 多端同步"：用户注册账号，数据存在服务商服务器，通过账号在不同设备间同步。

我们必须在架构层面决定数据放在哪里，因为这会决定：

- 用户是否需要账号
- 断网时能否使用
- 我们是否需要运营服务器
- 数据泄露的责任边界
- 商业模式的可能性

---

## 决策

**DeskBase 采用本地优先架构：数据的主副本永远存在用户设备上，网络是例外状态而非默认状态。**

具体要求：

1. 首启不要求登录、不要求联网、不要求激活。
2. 全部核心功能（笔记、表格、数据库、截图、备份、本地 AI）在完全断网下可用。
3. 程序启动时不建立任何外部连接。
4. 数据目录与程序目录可分离，整个数据目录可整体搬移。
5. 联网功能（更新检查、模型下载、远程访问、同步、外部 AI）全部默认关闭且可单独开关。
6. 数据可整体导出为开放格式，用户不需要本软件也能读取自己的数据。

---

## 备选方案

### 方案 A：云端优先（SaaS）
- 优点：多端同步开箱即用；易于做协作；可持续订阅收入；服务器端可做复杂计算
- 缺点：需要账号体系；断网不可用；需要持续运营服务器成本；数据泄露风险集中在服务商；隐私承诺难以证明
- **为什么不选**：与产品定位（隐私优先）根本冲突。隐私承诺一旦建立在"请相信我们"，就无法被用户验证。而且需要长期运营成本，对一个开源项目是不现实的负担。

### 方案 B：本地存储 + 官方云同步
- 优点：兼顾本地与多端；用户门槛低
- 缺点：仍需账号；仍需服务器；"数据是否上传"取决于同步开关，用户难以确认真实行为；引入冲突合并复杂度
- **为什么不选**：折中方案看起来温和，但它保留了账号与服务器，等于保留了全部隐私风险，只是多了一层"你也可以关掉"的安慰。真正的问题（数据必须经过我们）没有解决。

### 方案 C：本地优先 + 可选自托管同步
- 优点：本地为主；需要多端时用户可自建；无官方服务器
- 缺点：跨设备体验不如 SaaS 顺滑；自托管有门槛
- **为什么选它**：这是唯一能在满足隐私承诺的同时提供多端能力的路径。门槛由"远程访问 + 自托管中继"来降低：家庭局域网场景几乎零门槛，跨网络场景才需要自托管。

---

## 后果

### 正面

- **隐私承诺可验证**：程序内可查看审计日志与"我本机存了什么"；用户可抓包验证。
- **无服务器运营成本**：项目不需要长期资金维持基础设施，可持续性大幅提升。
- **断网可用**：目标用户（诊所、车间、个体户）的网络环境往往不稳定。
- **数据归属清晰**：数据在用户设备上，泄露责任边界明确。
- **可迁移**：整目录复制即迁移，不需要导出导入流程。
- **信任壁垒**：在"万物上云"的环境里，本地优先本身就是差异化。

### 负面

- **多设备体验不如云产品顺滑**：需要配对与连接，不能做到"打开就同步"。
- **用户需要自己管备份**：虽然我们默认开启自动备份，但备份介质由用户选择，安全性依赖用户的介质管理。
- **无法利用云端算力**：复杂 AI 任务只能本地跑，或由用户显式授权外发。
- **没有账号体系，无法做用户运营**：我们不知道用户是谁，也无法推送消息。
- **商业变现路径受限**：不能靠订阅、不能靠广告、不能靠数据变现。

### 中性

- 目标用户群重新定义：愿意为隐私付出少量不便的用户，而不是追求极致便利的用户。
- 需要额外投入"可验证性"的工程量（审计日志、网络自证视图），这些在云产品里根本不需要做。

---

## 验证方式

| # | 验证项 | 判据 |
|---|-------|------|
| 1 | 完全断网可用性 | 拔网线后可完成完整工作流（建库→导入→查询→截图→备份→恢复） |
| 2 | 启动无网络连接 | 抓包 + 系统网络计数器：启动后 5 分钟内连接数 = 0 |
| 3 | 网络功能关闭时网络 IO = 0 | 系统计数器 + 抓包双验证 |
| 4 | 无账号可用 | 全新安装后不使用任何账号完成全部 MVP 功能 |
| 5 | 可迁移性 | 仅用第三方工具可完整读出全部数据 |
| 6 | 迁移零依赖 | 换机全程不联网、不登录、不经过第三方服务器 |
