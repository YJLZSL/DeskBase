# ADR-0020: 表格优先的界面形态与 AI 表格（取代 ADR-0009 的界面结论）

- **状态**：已接受（2026-09-20，发起人决定）
- **取代**：[ADR-0009 简洁 / 高级双界面模式](0009-dual-ui-mode.md) 的界面结论
- **遵循**：[ADR-0017 AI 协助的隐私边界](0017-ai-assistance-privacy-boundary.md)（本 ADR 不修订它，只引用）
- **不变**：[ADR-0003 单文件 SQLite 存储](0003-storage-sqlite.md) —— 存储层保留，只是不再露面
- **相关**：[ADR-0005 网络默认关闭](0005-network-closed-by-default.md)、[ADR-0007 AI 默认本地推理](0007-ai-local-first.md)

## 背景

发起人 2026-09-20 的决定：**"删掉数据库功能，变成更方便的 Excel 表格、AI 表格"**。

已交付的 v0.3.0-beta.x 里，"数据库"对非程序员是一道门槛：建表要先选字段类型
（文本 / 金额 / 日期 / 是-否 / 整数 / 小数 / 二进制 / JSON / 日期时间）、要理解主键、
还要面对 SQL 编辑器与执行计划这些概念。调研里最硬的一条结论（"非程序员可用性是生死线"）
指向同一个方向：**用户要的是一张能直接开始记东西的表，不是一套数据库管理系统**。

本 ADR 记录这次形态转向的决定、边界与代价。

## 决策

### 1. 界面形态：表格优先（Excel 式）

- **打开即表格**：进入模块就是一张可编辑的表，直接敲字、加列、改列名、拖列宽。
- **字段类型不再出现在界面上**：类型由系统按内容自动推断并内部维护；
  用户看不到也不选择 `INTEGER` / `MONEY` / `DATE` 这些词。
- **主键 / 索引 / 视图 / 执行计划不出现在产品里**（保留在存储层的实现细节中）。
- **术语改写**：库表 → **表格**；字段 → **列**；建表向导 → **新建表格**。
  全产品文案、教程与文档（含 `docs/`）按这条改。

### 2. SQL 与"数据库"概念从产品移除

- 撤下 SQL 编辑器页签与"查询向导"入口；不再有"执行 SQL"这类入口。
- **存储层不动**：仍是单文件 SQLite（ADR-0003 不变），WAL + `synchronous=FULL`、
  事务、元数据表全部保留。
- **因此已交付的能力全部继续有效**：Excel / CSV 导入、崩溃恢复、备份、
  数据自动升级、工作区持久化 —— 而且**用户数据无需任何迁移**（数据模型未变）。
- **可逆点**：将来若需要，可以加一个"高级"入口把 SQL 放回来，而不必动存储。
  本轮**不**提供该入口（发起人明确要求移除）。

### 3. AI 表格：走 ADR-0017 的"外部服务"路径

发起人选择：**接远程模型，逐次授权**。落实为 ADR-0017 已定义的规则，逐条对齐：

| ADR-0017 的要求 | 本 ADR 的落地 |
|---|---|
| AI 能力默认关闭，且是网络总开关之下的**独立开关** | 设置页新增 AI 开关，**默认关闭**；关闭时网络 IO 必须为 0 |
| **不许静默降级** | 本轮**不做本地推理**。因此开启 AI 时**必须显式选择"使用云端服务"**，并写清"你的数据会发往该服务商" —— 不许出现"以为在本地、其实发出去了" |
| 外部服务**默认只发结构** | 默认只发送列名与类型，不发送数据行 |
| 要发数据行必须**逐次显式授权 + 展示将发送的内容** | 每次调用前弹确认：**哪个服务商、哪些列、多少行、样例前 N 行**；用户确认后才发 |
| 全部调用**记审计**（含被拒） | 每次调用与每次拒绝都写入数据目录的审计日志（时间 / 服务商 / 列名 / 行数；**不含数据本体**） |
| 数据最小化 | 只发当前操作涉及的那一列（或选中的区域），不发整表 |

**首个能力**：「**整理这一列**」—— 用户用一句自然语言描述要做的事
（"把手机号统一成 11 位数字"、"从地址里抠出省份"、"把日期补成 YYYY-MM-DD"），
AI 返回逐行的处理结果，**先预览、后应用**（应用为新的列，原列不动）。

### 4. 版本与进度

- 本决策**并入 v0.3.0**（尚未发正式版，重定义其范围）。
- 原 v0.4.0 的"AI 协助"主题并入本 ADR；原 v0.4.0 的"业务表"主题顺延。
- v0.3.0 原剩余四项的处置：**简洁模式取消**（表格形态本身就是简洁的）；
  **教程扩写改为"表格用法"教程**；**崩溃一致性 100 次保留**（底线不因形态变化而放松）；
  **安装版保留**（仍受本机 `reg.exe` 限制）。

## 后果

**收益**
- 门槛显著降低：不需要理解类型 / 主键 / SQL 就能开始记东西。
- 已交付的数据能力（导入 / 崩溃恢复 / 备份 / 事务）**全部保留**，且无需迁移。
- Excel 用户的心智模型可以直接迁移过来（"就是一张表"）。

**代价与风险**
- **SQL 能力对高级用户消失**（已留可逆点：将来可加"高级"入口，不动存储）。
- **引入数据外发面**：由 ADR-0017 的三道闸（默认关闭 / 逐次授权 / 审计 + 数据最小化）控制；
  但"用户点了确认"之后数据确实离开本机 —— 这一点必须在界面上说清，不能含糊。
- 类型不露面意味着**推断错误时用户无从纠正** —— 对策：推断只在导入与新建时发生，
  且提供"这一列看起来是日期，按日期处理 / 按文本处理"的轻量纠正面板（不暴露类型名）。
- 全产品文案与教程要跟着改（含 `docs/`），否则会出现"文档说数据库、界面说表格"的分裂。
