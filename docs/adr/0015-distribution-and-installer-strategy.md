# ADR-0015: 分发形态与安装器方案

- **状态**：提议
- **日期**：2026-09-17
- **决策者**：待定（依赖 ADR-0010 桌面外壳选型，L3 决策）

## 背景

DeskBase 是本地优先、隐私优先的办公工具箱 + 内置轻量 SQL 数据库，Apache-2.0 开源，处于 M0 阶段。

项目发起人在 2026-09-17 明确变更需求：**v0.1.0 必须同时提供便携版与 Windows 安装版（exe）**。此前「安装版推迟到 v0.4.0」的计划作废。

已确定的约束（来自既有 ADR 与文档）：

- ADR-0008：便携版优先、安装版用户级安装（`HKCU`、不需管理员、不写 `HKLM`、生成 `install-manifest.json`）。
- docs/12：安装向导需 13 步、完全自绘品牌界面（亮/暗主题、高 DPI、屏幕阅读器、中英文）；卸载界面同为自绘品牌界面；支持静默安装（且不偷偷开启默认关闭的选项）；卸载双模式 + 残留检查报告。
- docs/11：仅写最小注册表（约 12 值，仅用于卸载）；卸载后残留必须为 0。
- docs/14：Windows 安装包 ≤ 80 MB，便携版解压后 ≤ 220 MB。
- ADR-0010（**现已接受**）：桌面外壳在「系统 WebView / 自带运行时 / 原生 UI」三选一，安装器方案依赖此选型。
  → 该选型已定：**Rust + 系统 WebView2，Windows 优先**。本 ADR 依赖的前提已满足，
  下面的方案分析按此结论读。

工具链现状（**决策当时**的实测，2026-09-17）：Node.js ✅、Python ❌；
Rust / NSIS / Inno / WiX / Windows SDK 均 ❌ 未装。任何方案需说明额外工具链成本。

> ⚠️ 上面这一行说的是**决策当时**的环境，不是现在。Rust 与 MSVC 工具链
> 现在都已就位（项目本身就在 MSVC 下构建），下面各方案的工具链成本
> 需要按当前情况重新核对。

## 决策

**v0.1.0 分发形态：便携版（zip/自解压）+ Windows 安装版（exe）并行提供。安装版采用「自建安装器」——用与桌面外壳同一技术栈编写的轻量设置程序，以唯一满足 docs/12 的完全自绘品牌界面、主题、高 DPI、屏幕阅读器与同品牌卸载界面要求。NSIS / Inno Setup 作为「先快速出包」的备选路径，但需明确接受 UI 降级（做不到自绘/无障碍标准）。**

具体约定：

1. **便携版**：解压即用，零注册表写入，纯 zip 或自解压 exe 交付（形态待 Q7 决策）。
2. **安装版（主推·自建安装器）**：
   - 复用选中桌面外壳技术栈（WebView2 引导 / Electron 复用 / 原生框架），UI 与 docs/12 完全一致。
   - 默认安装到 `%LocalAppData%\Programs\DeskBase`，数据目录默认 `%UserProfile%\DeskBaseData`。
   - 仅写 `HKCU\Software\DeskBase`（约 12 值，仅卸载用）+ 系统要求 Uninstall 键，不写 `HKLM`，不需管理员。
   - 安装时生成 `install-manifest.json`，卸载据此精确清理。
   - 静默安装与交互安装走同一份代码路径，从机制上保证「静默不偷偷开启默认关闭选项」。
   - 自带品牌卸载器，支持保留数据 / 导出后卸载 / 彻底清除三模式 + 残留检查报告。
3. **备选（加速交付）**：v0.1.0 若外壳选型未定或时间紧，可先用 NSIS/Inno 产出标准向导安装包占位（UI 降级），后续替换为自绘安装器。
4. **不采用 MSIX / WiX-MSIX** 作为 v0.1.0 主方案：MSIX 安装 UI 不可定制（系统 App Installer），直接违反 docs/12 硬要求；仅在未来作为可选企业/商店渠道评估（待 Q6）。

本 ADR 状态为「提议」：因 ADR-0010 外壳选型未定，安装器具体技术路线仍需 PoC 确认，故暂不作为「已接受」。

## 备选方案

### 方案 A：NSIS
- 优点：开源、极成熟、跨平台编译（makensis）、体积小、HKCU/静默/manifest 全可控、本机可装
- 缺点：**UI 为经典 Win32 外观，做不到 docs/12 的自绘主题/高 DPI/屏幕阅读器/卸载品牌界面**
- 为什么不选（作主方案）：违反「完全自绘现代界面」硬要求。仅作备选（接受 UI 降级）。

### 方案 B：Inno Setup
- 优点：免费、成熟、Pascal 脚本多页向导、暗色支持、HKCU/静默可控
- 缺点：同 NSIS 的 UI 天花板；非 OSS；编译主要限 Windows，CI 跨平台需 Wine（未实测）
- 为什么不选（作主方案）：同 A，UI 受限。仅作备选。

### 方案 C：WiX Toolset（MSI）
- 优点：开源、企业友好、MSI 事务/回滚成熟
- 缺点：UI 极简、每用户 MSI 行为坑多、体积一般偏大、自绘 13 步向导近乎等于自建
- 为什么不选：UI 与需求背离，且比 NSIS 不省事。

### 方案 D：MSIX / App Installer
- 优点：微软主推、卸载天然干净（容器移除）
- 缺点：**安装 UI 永远不可定制**（系统接管）；需签名/信任；虚拟注册表语义与「只写 HKCU 最小项」诉求不完全一致；残留检查报告 UI 无法自绘
- 为什么不选：直接违反 docs/12 的 UI 硬要求。仅未来作企业/商店可选渠道评估。

### 方案 E：自解压 exe（iexpress / 7z SFX）
- 优点：零工具链（iexpress 内置于 Windows）、适合便携版
- 缺点：纯解压，不写注册表、不建快捷方式、无向导、无 manifest
- 为什么不选（作安装版）：无法承载安装版需求；**仅适合便携版**。

### 方案 F：框架自带打包器（electron-builder / tauri bundler）
- 优点：降低标准安装包接入成本
- 缺点：底层仍是 NSIS/WiX，UI 限制同 A/C，不解决自绘
- 为什么不选（作主方案）：解决「产出格式」不解决「界面自绘」。可作自建安装器外的补充。

### 方案 G：自建安装器（采纳·主推）
- 优点：唯一完整满足 docs/12 全部硬要求（自绘+主题+高 DPI+屏幕阅读器+卸载同界面）；静默与交互同源；manifest 天然精确；用户级 HKCU 完全可控；不引入额外打包工具链
- 缺点：需自建文件复制/原子重命名/失败回滚/权限占用检测/卸载自删除等逻辑，开发成本高于现成框架；依赖外壳选型（ADR-0010）
- 为什么选：唯一同时满足「零污染」「最小权限」「自绘现代界面」「卸载同品牌」的方案。

## 后果

### 正面
- 安装与卸载界面 100% 符合 docs/12 的视觉与无障碍标准，第一次见面即建立品牌信任。
- 静默与交互同源，从机制杜绝「静默偷偷开选项」，满足企业审计要求。
- `install-manifest.json` 精确清理，卸载残留可验证为 0。
- 用户级 HKCU 安装，无需管理员，UAC 弹窗消失。
- 对三种外壳（系统 WebView / 自带运行时 / 原生 UI）均适用，方案不绑定单一技术。

### 负面
- 需自行实现安装/卸载核心逻辑（复制、回滚、注册表、快捷方式、自删除），开发与测试成本高于 NSIS 脚本。
- 依赖 ADR-0010 外壳选型；外壳未定前，安装器具体技术路线悬而未决。
- 若外壳选「自带运行时（Electron 类）」且未与应用共用运行时，安装包体积可能突破 ≤80 MB 预算（待 Q3 决策）。
- 安装逻辑 bug 直接冲击「零残留」承诺，需配套自动化残留检测（docs/14 §14）。

### 中性
- 便携版与安装版需分别维护交付物（zip + exe），但逻辑可共享。
- 代码签名（Authenticode）建议延后但路径明确（购买证书 + `signtool`，私钥离线）。

## 验证方式

| # | 验证项 | 判据 |
|---|-------|------|
| 1 | 完全自绘界面 | 安装/卸载界面为自绘品牌界面，非系统默认框；亮/暗主题实时切换生效 |
| 2 | 无障碍 | 纯键盘可走完 13 步安装与卸载全流程；屏幕阅读器可读出全部控件名称与状态变化；100%–300% 缩放无错位 |
| 3 | 用户级安装 | 标准用户账户下无需管理员完成安装；`HKLM` 下无本项目相关项 |
| 4 | 最小注册表 | `HKCU\Software\DeskBase` 下值 ≤ 15 个，全部仅用于卸载 |
| 5 | 静默不越权 | 静默安装后，交互默认关闭的选项仍为关闭；审计日志与交互一致 |
| 6 | manifest 完整 | `install-manifest.json` 覆盖全部创建项（注册表/快捷方式/关联/自启/防火墙）|
| 7 | 卸载零残留 | 干净虚拟机：安装→使用→彻底清除卸载→文件+注册表残留 = 0；残留检查报告逐项通过 |
| 8 | 体积预算 | Windows 安装包 ≤ 80 MB；便携版解压后 ≤ 220 MB（docs/14 §12）|
| 9 | 离线安装 | 断网环境下可完成安装与卸载，无网络请求 |
| 10 | 三外壳可行 | 在 ADR-0010 选定外壳后，自建安装器可产出对应平台的安装/卸载程序 |
