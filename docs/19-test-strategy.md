# 19 · 测试策略：冒烟、压力、破坏性测试与缺陷排查

> 数据丢失和隐私泄露这两件事，**只能靠测试来防**。写完代码自我感觉良好，不算数。
>
> 本文定义 DeskBase 的测试分层、冒烟门禁、压力测试场景、破坏性测试方法，以及缺陷排查与分级的规范。

---

## 一、测试立场

### 1.1 三条原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **测试是承诺的证据** | 「不丢数据」「不泄露」「不污染」这三条承诺，每一条都必须有对应的测试来证明 |
| 2 | **先写能失败的测试** | 修 bug 先写复现用例；做崩溃恢复先写强杀脚本。测试先红后绿 |
| 3 | **没有测试的功能等于没做** | 不接受的交付方式是「我手动试过了，没问题」 |

### 1.2 测试不能只靠人工

| 必须自动化 | 可以人工 |
|-----------|---------|
| 单元 / 集成 / 端到端 / 冒烟 | 可用性测试（真实用户） |
| 性能基准 / 崩溃恢复 / 卸载残留 | 视觉审美判断 |
| 依赖漏洞 / 许可证 / 体积 | 长截图在特定真实应用上的表现 |
| 压力 / 长稳 / 破坏性注入 | 无障碍的实际使用感受 |

**自动化接入 CI 作为门禁；不可自动化的在发布前人工执行并记录。**

---

## 二、测试分层

```
第 8 层  真实用户验收        5 名新用户，可用性判断              发布前
第 7 层  破坏性 / 故障注入    强杀、断电、损坏、权限拒绝          发布前 + 每周
第 6 层  压力 / 长稳          大数据、并发、72 小时、资源极限      发布前 + 每周
第 5 层  端到端              完整用户闭环                      每次 PR
第 4 层  冒烟                15 分钟核心路径                    每次构建
第 3 层  集成                模块间协作、数据库、 IPC            每次 PR
第 2 层  单元                函数与组件                        每次提交
第 1 层  静态分析            lint / typecheck / SAST / SCA     每次提交
```

**越靠下的层越频繁，越靠上的层越昂贵。**

## 三、冒烟测试（Smoke Test）

### 3.1 定义与目标

冒烟测试是**最小可信度检查**：证明这个构建「没有坏到不能用」。

| 项 | 要求 |
|----|------|
| 触发时机 | 每次构建产物生成后 |
| 时长上限 | **≤ 15 分钟** |
| 覆盖范围 | 覆盖每个一级模块的**一条主路径**，不测边界与异常 |
| 判定 | 任一项失败 → **构建作废**，不进入后续测试 |
| 执行者 | CI 自动执行；本条失败不消耗人工排查时间 |

> 冒烟测试的作用是**快速止损**：不要在坏掉的构建上跑 40 分钟的压力测试。

### 3.2 冒烟用例集（v0.1.0）

按顺序执行，前一项失败则中止后续（因为后续依赖它）。

| # | 用例 | 通过判据 |
|:--:|------|---------|
| S01 | 冷启动 | 窗口可交互 ≤ 1.2 s（中配） |
| S02 | 生成示例数据 | 无报错，示例库/笔记可打开 |
| S03 | 新建笔记并自动保存 | 输入后 2 秒内落盘；重启后内容仍在 |
| S04 | 新建表格并输入 3 行 | 数据正确；排序生效；保存成功 |
| S05 | 待办：新建 → 勾选完成 | 状态正确；聚合视图反映变化 |
| S06 | 日历：新建事件 | 与待办联动正确 |
| S07 | 看板：拖动卡片跨列 | 拖拽跟手；落位正确；与表格数据一致 |
| S08 | 区域截图 + 标注 + 保存 | ≤ 400 ms 进入选区；标注生效；进入历史 |
| S09 | 滚动长截图（固定测试页） | 拼接完整，无缺失、无重复 |
| S10 | 图片 OCR | 1080p 图 ≤ 1.5 s，文字正确 |
| S11 | 剪贴板：复制 → 唤起历史 → 粘贴 | 历史含该条；粘贴内容正确 |
| S12 | 标签：打标签 → 按标签筛选 | 能筛出目标项 |
| S13 | 全局搜索找到 S03 的笔记 | 命中且可跳转 |
| S14 | 建表 → 导入 100 行 CSV | 导入成功，行数正确 |
| S15 | 查询向导完成一次查询 | 返回结果正确，可查看等价 SQL |
| S16 | 手动备份 + 健康检查 | 备份生成；健康检查全部通过 |
| S17 | **强杀进程 → 重启** | **恢复向导自动出现**；数据完整；完整性检查通过 |
| S18 | 一键全量导出 | 目录生成，含 README.txt 与校验和 |
| S19 | 退出程序 | 无残留进程、无残留句柄 |
| S20 | 网络断言 | 网络功能关闭时，本次冒烟全程网络 IO = 0 |

### 3.3 断网冒烟

在 S01–S19 之外，另跑一轮**断网冒烟**：

```
物理断网（或防火墙全禁）→ 执行 S01–S19（跳过涉及网络的步骤）
判据：全部通过，且界面上不出现任何网络相关报错
```

### 3.4 冒烟门禁规则

| 规则 | 说明 |
|------|------|
| 冒烟不通过 → 不构建发布包 | 不要浪费构建与签名资源 |
| 冒烟不通过 → 不跑压力测试 | 浪费时间 |
| 冒烟连续 3 次同一用例失败 | 升级为 P0 缺陷，停止该分支的合并 |
| 冒烟用例不允许被跳过 | 除了明确标记为「环境不适用」（如无 GPU 时的 GPU 测试） |
| 冒烟用例数量克制 | **不允许无限增长**。新加用例必须替换掉价值最低的旧用例，总数控制在 25 条以内 |

## 四、压力测试（Stress Test）

### 4.1 目标

找出**在正常使用中不会出现、但一定会出现**的问题：内存泄漏、性能衰减、资源耗尽、状态错乱。

### 4.2 数据量压力

标准数据集见 [14 · 性能优化与量化指标](14-performance-budget.md#12-测试数据规模标准集)。

| 场景 | 操作 | 判据 |
|------|------|------|
| 十万行表 | 打开、滚动、排序、筛选、编辑 | 滚动 ≥ 50 FPS；首屏 ≤ 300 ms；内存增量 ≤ 300 MB |
| 百万行表 | 打开、滚动、索引查询 | 滚动 ≥ 50 FPS；索引查询 ≤ 200 ms |
| 千万行表 | 打开、索引查询 | 打开 ≤ 5 s；索引查询 ≤ 500 ms；有明确的行数提示 |
| 五千篇笔记 | 列表滚动、全文搜索 | 搜索首屏 ≤ 300 ms；列表 ≥ 55 FPS |
| 一万张截图 | 历史浏览、滚动、OCR 文本搜索 | 滚动 ≥ 55 FPS；搜索 ≤ 600 ms |
| 十万个文件 | 索引、搜索、批量操作 | 搜索 ≤ 400 ms；批量操作有进度且可取消 |
| 单个大附件（2 GB） | 导入、预览、删除 | 不 OOM；有进度；删除后空间释放 |
| 超长文本（单条 100 MB） | 写入、打开、搜索 | 不崩溃；有明确提示；搜索可用 |

### 4.3 并发压力

| 场景 | 判据 |
|------|------|
| 10 个查询并行执行 | 全部正确返回；界面不冻结；无死锁 |
| 导入 10 万行的同时执行查询 | 查询阻塞但最终正确；不出现脏读 |
| 备份进行中继续编辑 | 编辑正常；备份内容一致（不含编辑中的未提交数据或含一致性快照） |
| 两个窗口（同一进程）编辑同一条记录 | 版本冲突被检测；提示用户；不静默覆盖 |
| 定时任务到期同时用户正在操作 | 任务延后或降速，不抢资源 |
| 剪贴板高频写入（每秒 10 次 × 1000 次） | 历史正确；无重复项；不卡顿 |

### 4.4 长时间运行（长稳）

| 场景 | 时长 | 判据 |
|------|:----:|------|
| 空闲挂机 | 8 小时 | 内存增长 ≤ **10 MB**；CPU 平均 ≤ 0.3% 且**无周期性尖峰** |
| 空闲挂机 | 72 小时 | 内存增长 ≤ 30 MB；无句柄泄漏；无文件句柄增长 |
| 持续编辑 | 4 小时 | 内存稳定；无卡顿累积；撤销栈不无限增长 |
| 持续滚动 | 1 小时 | 帧率不衰减（前后 10 分钟对比差异 ≤ 5%） |
| 反复打开/关闭库 | 100 次 | 内存增长 ≤ 20 MB；无残留线程 |
| 反复切换模块 | 500 次 | 内存增长 ≤ 20 MB |
| 连续截图 | 200 次 | 内存增长 ≤ 50 MB；历史正确 |
| 连续查询 | 1 000 次 | 内存增长 ≤ 30 MB |

> **判据红线**：任何**线性上升且不收敛**的内存曲线，无论幅度多小，一律视为 P0 缺陷。

### 4.5 资源极限

| 场景 | 模拟方式 | 判据 |
|------|---------|------|
| 内存不足 | 限制进程内存到 2 GB | 优雅降级或明确报错，不崩溃、不损坏数据 |
| 内存极低 | 限制到 512 MB | 拒绝重操作并说明原因；已完成的数据不丢 |
| 磁盘写满 | 数据盘填满后继续写入 | 写入前预检；明确提示需要多少空间；**已提交数据不损坏** |
| 磁盘剩余极少 | 剩余 100 MB | 拒绝备份/导入并说明；不影响正常编辑小数据 |
| 句柄耗尽 | 打开大量文件 | 不崩溃；释放后可恢复 |
| CPU 满载 | 后台跑满 CPU | 前台仍可操作；后台任务自动降速 |
| 只读介质 | 数据目录设为只读 | 明确提示；不产生半写入文件 |

### 4.6 环境异常

| 场景 | 操作 | 判据 |
|------|------|------|
| 睡眠唤醒 | 睡眠/唤醒 100 次 | 唤醒后连接与文件句柄有效；任务延后而非补跑 |
| 休眠 | 休眠/恢复 20 次 | 数据完整；无重复恢复向导 |
| 系统时间跳变 | 向前跳 1 年、向后跳 1 年 | 时间戳不乱序；排序仍正确；不产生未来时间记录 |
| 时区切换 | 切换到跨日时区 | 日历事件时间正确（保留原始时区） |
| 夏令时边界 | 在 DST 切换时刻创建事件 | 不产生重复或丢失事件 |
| U 盘热拔 | 数据目录在 U 盘，使用中拔出 | 明确报错；不崩溃；重新插入后可继续 |
| 网络切换 | 局域网 → 蜂窝 → 断网（远程功能开启时） | 连接状态正确反映；不静默失败 |
| 弱网 | 限速 50 KB/s + 丢包 20% | 远程操作超时并有明确提示；不无限重试 |
| 系统休眠中任务到期 | 任务在休眠期间到期 | 唤醒后**延后执行**，不集中补跑 |

### 4.7 交互压力

| 场景 | 判据 |
|------|------|
| 快速连点同一按钮 50 次 | 不重复提交；不产生 50 条记录；有幂等保护 |
| 狂按快捷键 | 不卡死；不产生异常状态；不重复打开窗口 |
| 疯狂滚轮（万行表） | 不崩溃；帧率可短暂下降但能恢复 |
| 连续拖拽 100 次 | 不丢事件；最终状态正确 |
| 输入法快速切换 + 连续输入 | 不重复字符；不丢字符 |
| 窗口快速缩放 | 布局不破；不出现滚动条闪烁 |
| 两个实例同时启动（便携版） | 明确提示"已在运行"或正确共享，**不允许两个实例同时写同一份数据** |

### 4.8 输入压力（脏数据）

必须准备一套"脏数据"语料，覆盖以下输入，逐一通过导入/编辑/搜索/导出全流程：

| 类型 | 示例 |
|------|------|
| 超长文本 | 单字段 1 MB、100 MB |
| 超长文件名 | 255 字符、含中文与 emoji |
| 特殊字符 | `\0`（空字节）、控制字符、RTL 文本（阿拉伯语）、组合 emoji |
| 生僻字 | CJK 扩展 B/C/D 区字符、异体字 |
| 注入串 | `' OR 1=1 --`、`<script>alert(1)</script>`、`../../etc/passwd`、`$(rm -rf /)` |
| 格式异常 | CSV 引号不闭合、JSON 语法错误、Excel 合并单元格、多表头、混合类型列 |
| 编码混用 | UTF-8 / GBK / UTF-16 混在同一批文件 |
| 空值 | 全空行、全空列、NULL 与空字符串混用 |
| Unicode 边界 | U+FFFF、代理对、零宽字符 |
| 数字边界 | 极大整数、极小负数、NaN、Infinity、科学计数法 |

**判据**：不崩溃、不损坏数据、不执行注入内容、给出明确错误或正确处理。

## 五、破坏性测试（故障注入）

> 这一类测试专门验证「出事的时候会不会坏」，是「不丢数据」承诺的核心证据。

### 5.1 写入中断

| # | 场景 | 方法 | 判据 |
|:--:|------|------|------|
| F01 | **写入中强杀进程** | 随机延迟 1–5 s 后 `SIGKILL`，**重复 100 次** | 每次重启后完整性检查通过；最多丢失最后一个未提交事务 |
| F02 | 断电模拟 | 虚拟机强制关机，重复 50 次 | 同 F01 |
| F03 | 事务中途中断 | 在事务提交的中间阶段强杀 | 该事务要么全有要么全无 |
| F04 | checkpoint 期间强杀 | 在 checkpoint 进行中强杀 | 重启后恢复正确 |
| F05 | 备份过程中强杀 | 备份进行中强杀 | 无半成品备份被标记为"可用" |

### 5.2 数据损坏

| # | 场景 | 方法 | 判据 |
|:--:|------|------|------|
| F06 | 主库文件被截断 | 手动截断数据库文件的尾部 | 明确报错并引导恢复；不静默使用损坏数据 |
| F07 | 主库文件字节翻转 | 随机翻转 1 个字节 | 完整性检查发现；从备份恢复可用 |
| F08 | WAL 文件损坏 | 篡改 WAL | 恢复到一致状态或明确失败；不产生错乱数据 |
| F09 | 备份包内文件损坏 | 损坏备份中一个文件 | **健康检查必须发现**；阻止恢复该备份 |
| F10 | 配置文件损坏 | 写入非法 JSON | 程序可启动；回退到默认配置；提示用户 |
| F11 | 附件文件丢失 | 删除 attachments 下一个文件 | 引用处显示"文件缺失"；不崩溃 |
| F12 | 元数据与 schema 不一致 | 手动改真实表结构绕过服务层 | 检测到不一致并提示修复，不静默出错 |

### 5.3 权限与资源拒绝

| # | 场景 | 方法 | 判据 |
|:--:|------|------|------|
| F13 | 数据目录无写权限 | 设为只读 | 明确提示；不产生半写入文件；不崩溃 |
| F14 | 备份目标不可写 | 目标盘只读 | 备份失败并显著告警；不影响主数据 |
| F15 | 备份目标不可达 | 拔掉 NAS / 断开网络盘 | 失败并告警；下次可重试 |
| F16 | 临时目录不可写 | 设为只读 | 明确报错；核心功能仍可用（或说明哪些不可用） |
| F17 | 密钥文件被删除（加密开启后） | 删除密钥材料 | 明确提示解锁不可用；**不损坏数据** |
| F18 | 磁盘空间在写入中途耗尽 | 写入大文件时填满磁盘 | 事务回滚；数据一致；明确提示 |
| F19 | 插件进程 OOM | 让插件吃满内存 | 插件被终止；主程序提示"插件 X 已停止"；数据无损 |
| F20 | 子进程崩溃 | 强杀数据库/AI/远程子进程 | 主程序察觉并恢复或重启该进程；不整程序崩溃 |

### 5.4 破坏性测试的执行节奏

| 时机 | 范围 |
|------|------|
| 每次 PR（若改动涉及存储/恢复/权限） | F01（缩减为 20 次）+ F06 + F13 |
| 每周 | F01–F20 全量 |
| 发布前 | F01–F20 全量 + 人工复核全部失败记录 |
| 每次改动崩溃恢复逻辑后 | F01（完整 100 次）+ F02 + F03 + F04 |

## 六、缺陷排查规范

### 6.1 排查五步法

```
① 复现
   把问题变成一条可重复执行的步骤。复现不了就不是缺陷，是现象。
   记录：精确步骤、环境、数据规模、发生频率

② 最小化
   删掉一切不影响复现的操作与数据。
   目标：把"导入 10 万行后点排序会崩"缩到"空表插入 1 行后点排序会崩"

③ 定位
   二分法：在代码路径中间打点，判断问题在前半段还是后半段
   提交二分：git bisect 找出引入问题的那个提交
   数据二分：把数据集砍一半再试

④ 定性
   判断属于哪一类（见 6.3），这决定了修复方式与回归测试怎么写

⑤ 验证
   写一个复现用例（先红）→ 修复 → 用例转绿
   → 跑该模块全部回归 → 跑崩溃恢复（若涉及数据）
```

### 6.2 现场保留要求

发现严重缺陷时**先保留现场再动手修**：

| 要保留的 | 说明 |
|---------|------|
| 日志 | 运行日志 + 错误日志 + 审计日志 |
| 数据库文件 | 出问题的那一刻的完整数据目录副本 |
| 崩溃转储 | 若有 |
| 环境信息 | 版本、提交哈希、系统版本、硬件配置 |
| 精确步骤 | 能一次复现的步骤序列 |
| 时间点 | 问题发生的准确时间（便于查日志） |

> **不要**在保留现场之前重装、清缓存、重启机器。

### 6.3 常见缺陷类型与排查路径

| 类型 | 典型表现 | 优先排查方向 |
|------|---------|------------|
| **数据丢失/损坏** | 数据不见了、内容变了 | 事务边界、fsync 是否被省、原子写入、WAL 与主库的一致性 |
| **崩溃** | 进程退出、白屏 | 空引用、越界、未捕获异常、递归过深、第三方库 |
| **内存泄漏** | 内存持续增长 | 事件监听未解绑、定时器未清除、缓存无上限、大对象被闭包持有 |
| **性能衰减** | 越用越慢 | 无上限的集合、重复计算、索引失效、渲染节点累积 |
| **并发错乱** | 偶发的错误状态 | 共享状态无锁、异步竞态、事务隔离级别不足 |
| **权限越界** | 不该能访问的能访问 | 服务端校验缺失、客户端信任、路径未规范化 |
| **隐私泄露** | 意外的网络请求或明文落盘 | 依赖自带上报、日志记录敏感数据、缓存未清理 |
| **状态不一致** | 界面与数据不符 | 单一数据源被绕过、缓存未失效、乐观更新未回滚 |
| **界面错乱** | 布局破、错位 | 缩放、长文本、空数据、极端窗口尺寸未测 |

### 6.4 排查反模式

| ❌ 不要 | 原因 |
|--------|------|
| 靠加 try/catch 把异常吞掉 | 问题被隐藏，下次以更严重的形式出现 |
| 靠加延时/sleep 绕过竞态 | 竞态没解决，只是更难复现 |
| 靠重试掩盖失败 | 失败原因未解决，可能造成重复写入 |
| 改测试让它通过 | 测试是判据，不是障碍 |
| 只改症状不改根因 | 同一个根因会在别处再冒出来 |
| 在没有复现用例的情况下改代码 | 无法证明修好了，也无法防回归 |
| 直接把用户的数据库发到群里排查 | 隐私泄露。必须脱敏或使用自造数据 |

## 七、缺陷分级与处理时限

| 级别 | 判定标准 | 处理时限 | 能否发布 |
|:----:|---------|---------|---------|
| **P0 致命** | 数据丢失或损坏；隐私泄露；无法启动；崩溃后不可恢复；权限绕过；加密被绕过 | **24 小时内**响应并给方案 | **绝对不能** |
| **P1 严重** | 核心功能不可用；性能严重不达标；卸载残留；内存泄漏（线性增长） | 3 个工作日内 | 不能 |
| **P2 一般** | 非核心功能异常；有 workaround 的问题；体验明显受损 | 下个次版本 | 可以（需记录） |
| **P3 轻微** | 文案、对齐、罕见的边界情况 | 排期处理 | 可以 |

### 7.1 P0 缺陷的强制动作

| # | 动作 |
|---|------|
| 1 | 立即停止发布流程 |
| 2 | 保留现场并按 6.2 记录 |
| 3 | 评估影响范围（多少用户、多少数据受影响） |
| 4 | 写复现用例 |
| 5 | 修复 + 转绿 |
| 6 | 跑完整 F01–F20 破坏性测试 |
| 7 | 若已发布，评估是否需要发布紧急补丁与用户告知 |
| 8 | 写复盘记录（根因、为什么没被测试发现、如何补测试） |

### 7.2 复盘要求

任何 P0、P1 缺陷修复后必须回答：

| 问题 | 目的 |
|------|------|
| 根因是什么？ | 避免只修症状 |
| 为什么现有测试没发现？ | 找出测试盲区 |
| 补了哪个测试？ | 防止回归 |
| 同类问题还有哪些地方可能出现？ | 举一反三 |
| 流程上有什么可以改的？ | 防止同类问题再次进入代码 |

### 8.1 回归范围

| 改动类型 | 必跑回归 |

### 8.2 回归清单维护

- 回归清单每季度复核一次，删除不再适用的用例（功能已下线）。
- 回归清单条目上限：**300 条**。超出时合并或删除价值最低的。

- 破坏性测试必须脚本化（强杀循环、损坏注入都不能靠手点）。

## 十、测试反模式

| ❌ 反模式 | 为什么不行 |
|----------|-----------|
| 只有 happy path 测试 | 真实使用中出问题的一定是异常路径 |
| 测试依赖执行顺序 | 单独跑就失败，CI 上串行跑却通过 —— 会掩盖问题 |
| 测试依赖网络 | 不稳定，且违反离线承诺 |
| 用 `sleep` 等待异步 | 不稳定；应该用条件等待 |
| 只测 UI 不测数据层 | 数据损坏不会在界面上立刻暴露 |
| 性能测试只跑一次 | 单次结果无意义，必须有多次与中位数 |
| 压力测试在开发机上跑 | 结果不可比，且会干扰开发 |
| 冒烟用例无限膨胀 | 15 分钟变成 1 小时，就没人跑了 |
| 「我本地试过了」当作验收 | 无法复现、无法防回归 |
| 把用户的真实数据用于测试 | 隐私问题。必须用自造数据或严格脱敏 |

## 十一、门禁汇总

| 门禁 | 触发 | 不通过后果 |
|------|------|-----------|
| 静态分析 | 每次提交 | 阻止合并 |
| 单元 / 集成 | 每次 PR | 阻止合并 |
| 端到端 | 每次 PR | 阻止合并 |
| 性能回归 | 每次 PR（相关模块） | 阻止合并 |
| **冒烟** | **每次构建** | **构建作废** |
| 压力（抽样） | 每周 | 记录并排期修复 |
| 压力（全量）+ 破坏性 | 发布前 | **阻止发布** |
| 长稳 72 小时 | 每个次版本发布前 | 阻止发布 |
| 卸载残留 = 0 | 发布前 | 阻止发布 |
| 真实用户验收 | 每个里程碑 | 阻止进入下一阶段 |
